## I. Приложение: перенос сервера на новое железо (инструкция-шпаргалка)

База живёт в Docker-volume `postgres\\\\\\\_prod` и дампах — контейнер «без памяти», данные на диске.

**Сценарий А — старый диск живой (без дампов):**

* \[ ] `docker compose down` → `tar czf pgdata.tgz -C /var/lib/docker/volumes deploy\\\\\\\_postgres\\\\\\\_prod`
* \[ ] Новый сервер: Ubuntu+Docker → `docker load -i fitintel-prod\\\\\\\_\\\\\\\*.tar.gz` → `.env` (ТЕ ЖЕ секреты) → `up -d db` → `down`
* \[ ] Распаковать volume → `up -d` → проверить `/health` и число клиентов
* \[ ] Лицензия: machine-id новый → активировать новый ключ (бесплатно по заявке)

**Сценарий Б — диск умер (только бэкапы):**

* \[ ] Новый сервер: Docker → образ → `.env` → `up -d db`
* \[ ] `gunzip -c backups/fitintel\\\\\\\_\\\\\\\*.sql.gz | docker exec -i deploy-db-1 psql -U fitnexus\\\\\\\_user -d fitnexus\\\\\\\_ai`
* \[ ] `up -d` → сверка счётчиков таблиц → лицензия новым ключом
* Потери = данные после последнего дампа (поэтому E3/E4 — ежедневно и на второй носитель).

**Не пострадает при переносе:** desktop-клиенты (настройки на ПК), `client\\\\\\\_settings.json`, `connections.json` — только поменять адрес сервера при смене IP.
