## I. Приложение: перенос сервера на новое железо (инструкция-шпаргалка)

База живёт в Docker-volume `postgres_prod` и дампах — контейнер «без памяти», данные на диске.

**Сценарий А — старый диск живой (без дампов):**
- [ ] `docker compose down` → `tar czf pgdata.tgz -C /var/lib/docker/volumes deploy_postgres_prod`
- [ ] Новый сервер: Ubuntu+Docker → `docker load -i fitintel-prod_*.tar.gz` → `.env` (ТЕ ЖЕ секреты) → `up -d db` → `down`
- [ ] Распаковать volume → `up -d` → проверить `/health` и число клиентов
- [ ] Лицензия: machine-id новый → активировать новый ключ (бесплатно по заявке)

**Сценарий Б — диск умер (только бэкапы):**
- [ ] Новый сервер: Docker → образ → `.env` → `up -d db`
- [ ] `gunzip -c backups/fitintel_*.sql.gz | docker exec -i deploy-db-1 psql -U fitnexus_user -d fitnexus_ai`
- [ ] `up -d` → сверка счётчиков таблиц → лицензия новым ключом
- Потери = данные после последнего дампа (поэтому E3/E4 — ежедневно и на второй носитель).

**Не пострадает при переносе:** desktop-клиенты (настройки на ПК), `client_settings.json`, `connections.json` — только поменять адрес сервера при смене IP.
