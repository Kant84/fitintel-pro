# FitIntel Pro — MAX-бот и Магазин: документация (Волна 5)

Дата: 2026-10-09. Покрывает: бот MAX, регистрацию клиентов, магазин (серверный склад и киоск-эмуляцию),
пополнение баланса онлайн, параметры клуба. Всё проверено по коду текущего релиза.

---

## 1. Архитектура бота MAX

| Компонент | Файл | Назначение |
|---|---|---|
| Команды, webhook, привязка, QR | `app/api/v1/max_bot.py` | `/max-bot/webhook`, `/max-bot/link`, `/max-bot/settings`, команды `/qr /balance /visits /abonement /bonuses`, cron-эндпоинты |
| Сценарии (меню, диалоги) | `app/services/bot_scenarios.py` | регистрация, главное меню 1–8, запись, дети, «Мои записи», покупка товара с баланса, пополнение баланса |
| FSM-хранилище | таблица `max_bot_fsm` (создаётся автоматически) | состояние диалога по `max_user_id` |
| Привязка MAX ↔ клиент | таблица `max_bot_bindings` (создаётся автоматически) | `max_user_id` → `client_id` (hex) |
| Настройки бота | таблица `max_bot_settings` (строка id=1) | `bot_token`, `webhook_secret` |
| Лог команд | таблица `max_bot_log` | аудит обращений |
| Мессенджер (рассылки, журнал) | `app/api/v1/messenger.py` | очередь `messenger_notifications`, привязки legacy `messenger_bindings` |

Порядок обработки сообщения: webhook → секрет (если задан) → `bot_scenarios.handle()` (меню/сценарии)
→ если сценарий не обработал — команды из `max_bot.py`. Ответ возвращается в теле webhook **и**
дублируется прямой отправкой в MAX (если задан токен).

## 2. Где вписывать токен бота (три способа, приоритет сверху вниз)

1. **Таблица БД `max_bot_settings`** (рекомендуется, хранится в PostgreSQL клуба):
   ```bash
   curl -X POST http://192.168.101.182/api/v1/max-bot/settings \
        -H "Content-Type: application/json" \
        -H "Authorization: Bearer <JWT суперадмина>" \
        -d '{"bot_token": "ТОКЕН_ИЗ_КАБИНЕТА_MAX"}'
   ```
2. **Переменная окружения на сервере** `deploy/.env`:
   ```
   MAX_BOT_TOKEN=ТОКЕН_ИЗ_КАБИНЕТА_MAX
   ```
   (используется, если в таблице токен пуст; после правки .env — пересборка контейнера)
3. В кабинете MAX токен выдаётся при создании бота; он же вписывается в настройки webhook-приёмника,
   если MAX требует авторизацию входящих (опционально).

**Webhook-секрет** (необязательно): `POST /max-bot/settings {"webhook_secret": "..."}`.
Если задан — заголовок `x-max-bot-secret` каждого webhook-запроса сверяется с ним; если НЕ задан —
webhook принимает все запросы (удобно для тестов).

### 2.1 Регистрация бота в MAX (кабинет разработчика)
1. Создать бота (только верифицированные организации-юрлица РФ).
2. Получить токен.
3. Указать **публичный HTTPS-адрес webhook**: `https://<домен-клуба>/api/v1/max-bot/webhook`.
   ВНИМАНИЕ: MAX не принимает webhook на «голый» IP локалки — нужен домен с TLS
   (если домена нет: любой туннель/TLS-прокси для теста).
4. Вписать токен на сервер (п.2).

### 2.2 Вход клиента в бота
- Ссылка/deep-link: `https://max.ru/<имя_бота>?start=reception` (параметр — источник:
  `reception`, `poster`, `card` — пишется в `clients.source`; `club:<код>` — привязка клуба).
- QR для печати в клубе: сгенерировать любым генератором QR из этой ссылки.

## 3. Регистрация клиента в боте (автоматическая)

Новый пользователь → `/start` → бот запускает мастер:
1. ФИО одной строкой;
2. Телефон (+7…);
3. Email (опционально, «-»);
4. Дата рождения ДД.ММ.ГГГГ (проверка `CHILD_MAX_AGE` для детей — взрослую карточку просит создать на ресепшене).

Результат: создан `Client` + автоматическая привязка `max_bot_bindings`. Дальше — главное меню.

**Ручная привязка** (если клиент писал боту до внедрения): `POST /api/v1/max-bot/link`
`{"client_id": "<uuid>", "max_user_id": 123456789}` (или вкладка «MAX сообщения» → «Привязки»).

**Дети:** меню «7» → «добавить ребёнка» (ФИО + дата рождения) → карточка `client_category=CHILD`,
`parent_id` = родитель. Бронь ребёнка = основание для входа родителя (политика входа).

## 4. Главное меню бота (тексты редактируются: «Настройки» → «Параметры клуба» → «Лейблы бота», ключи `TXT.*`)

| № | Пункт | Что делает |
|---|---|---|
| 1 | Магазин | 1. Занятия и услуги (запись) · 2. Товары (оплата с баланса — только серверный склад) |
| 2 | Расписание занятий | список активных услуг → запись (дата по `schedule.days` → слот с лимитом мест) |
| 3 | Личный тренер | свободные персональные слоты |
| 4 | Мои записи | активные брони + «подтвердить N» / «отменить N» (окно `CANCEL_WINDOW_HOURS`) |
| 5 | QR на вход | одноразовый QR, TTL `QR_TTL_MINUTES`, пауза обновления `QR_REFRESH_COOLDOWN_SECONDS`. QR выдаётся при наличии основания: активный абонемент ИЛИ оплаченная бронь в окне входа (`ENTRY_WINDOW_BEFORE/AFTER_HOURS` или `ENTRY_STAY_UNTIL_CLOSE=true`) |
| 6 | Бонусы | уровень геймификации + баланс кошелька (заглушка программы бонусов) |
| 7 | Мои дети | список детей + добавление |
| 8 | Пополнить баланс | сумма → ссылка на оплату картой (ЮKassa / банк-эквайринг / тест) → webhook зачисляет на кошелёк |

Свип броней (автономно, поток каждые 5 мин): за `REMIND_BEFORE_HOURS` — напоминание «подтвердите»,
за `LAST_REMIND_BEFORE_HOURS` — пин, после `CONFIRM_DEADLINE_HOURS` — авто-отмена (рейтинг не падает).
No-show −0.5 к рейтингу (кнопка ресепшена), завершённое занятие +0.1.

## 5. Магазин (склад): два режима

### 5.1 Куда «адрес склада» — где лежат товары

| Режим | Где данные | Когда включается |
|---|---|---|
| **Серверный склад** | PostgreSQL клуба, таблица `warehouse_products` (колонки: name, article, sale_price, quantity, unit, photo_url, is_active, club_id) | `GET /api/v1/warehouse/products?club_id=1` отвечает 200 |
| **Киоск (эмуляция)** | файлы рядом с десктопом: `fitintel-desktop/shop_products.json`, журнал продаж `fitintel-desktop/shop_sales.json`, фото в `fitintel-desktop/shop_photos/` | серверный склад недоступен (500/сеть) — переключение автоматическое, строка над таблицей показывает режим |

Переключение обратно на сервер происходит само при его появлении. **Клуб без склада работает полностью
в режиме киоска** — это штатно.

### 5.2 Вкладка «Услуги» → «Магазин» (десктоп)

Колонки: **Наименование · Артикул · Фото · Количество · Цена ₽ · Ед.**

Кнопки (оба режима):
- **＋ Добавить товар** — диалог: наименование, артикул, количество, цена, ед., фото (URL, необязательно);
- **Изменить / Удалить** — выбранная строка (удаление — мягкое `is_active=false` на сервере);
- **Загрузить фото** — **файл с диска** (не URL!): сервер → `/app/static/products/`, киоск → копия в `shop_photos/`; превью 48px в таблице;
- **Продать** — количество + способ оплаты (нал/карта/СБП):
  - списание остатка;
  - **создаётся платёж в «Платежи» со статусом «Ожидает»** (категория «Товар», приход, клиент — служебный
    «Киоск (розница)», тел. `+70000000000`, создаётся автоматически; если не удалось — предупреждение с суммой);
  - кассир в «Бухгалтерия → Платежи» жмёт «✓ Подтвердить» → **фискальный чек через вашу кассу (АТОЛ)** → платёж в балансе смены.

### 5.3 Товары в боте (покупка из ЛК)

Видны **только серверный склад** (киоск боту недоступен — ответ «Товары доступны на ресепшене»).
Меню «1 → 2» → каталог с ценами/остатками → номер → списание с баланса кошелька
(`WalletService.withdraw`: проверка доступных средств, транзакция, аудит) → «Заберите на ресепшене».
Эндпоинт: `POST /api/v1/shop/buy-balance {"client_id","product_id","quantity"}`.

### 5.4 Пополнение баланса онлайн (меню «8»)

1. Бот просит сумму (50–50 000 ₽);
2. Создаётся платёж (status `pending`) и **ссылка на оплату**:
   - **ЮKassa** — если в `deploy/.env` заданы `YOOKASSA_ACCOUNT_ID` + `YOOKASSA_SECRET_KEY` (тестовый режим принудительно: `YOOKASSA_TEST_MODE=true`)
     (webhook ЮKassa: `https://<домен>/api/v1/yookassa/webhook`, секрет `YOOKASSA_WEBHOOK_SECRET`);
   - **банковский эквайринг** — через `app/services/bank/universal_bank.py` (при наличии адаптера);
   - **тестовый режим** — без ключей, ссылка-заглушка (пометка в ответе);
3. Оплата → webhook → **баланс кошелька зачислен автоматически** (кошелёк создаётся при необходимости).

Пополнение без онлайн-оплаты — только на ресепшене (платёж → зачисление на кошелёк).

## 9. Чек-лист «бот жив на телефоне»

1. `docker logs deploy-api-1 --tail 5` → «W5 booking sweep OK», без traceback;
2. Webhook MAX указывает на `https://<домен>/api/v1/max-bot/webhook`;
3. Токен вписан (`POST /max-bot/settings` или env), сервер перезапущен;
4. Телефон: `/start` → регистрация → меню; «5» → QR (без абонемента — понятный отказ);
5. Расписание → запись → касса: `/services/bookings/{id}/pay` → «5» — основание «(ребёнок)»/занятие;
6. «8» → ссылка (тест) → зачисление; «1 → 2» → покупка с баланса (нужен серверный товар).

## 10. Типовые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Бот молчит | webhook не принят MAX (нет публичного HTTPS) / токен не вписан | п.2.1, п.2 |
| «Нужна привязка» у нового | не прошёл мастер регистрации | пройти заново или `/max-bot/link` |
| Магазин «Склад недоступен: 500» | таблица склада/колонки старые | `shop_service` сам чинит схему; либо ручной ensure из `warehouse.py`; либо жить в киоске |
| 405 при сохранении услуги | старый `services.py` | обновлённый файл лежит в релизе (PUT) |
| Платёж из магазина не создался | схема кассы требует клиента | создаётся «Киоск (розница)»; иначе — предупреждение с суммой |
| QueuePool timeout | был ALTER на каждый запрос | исправлено (ensure один раз за процесс), пул 20/20/10с/30мин в `db/session.py` |
