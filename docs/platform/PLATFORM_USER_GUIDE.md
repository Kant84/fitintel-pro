# FitIntel Platform — полная инструкция пользователя (администратор платформы)

Версия 1.0 (24.10.2026). Аудитория: платформенные администраторы и служба поддержки FitIntel Pro.
Сопутствующие документы: `MTLS_PLATFORM_ACCESS.md` (криптография, CRL, файрвол), `PLATFORM_DEPLOY_GUIDE.md` (развёртывание), `REMOTE_ACCESS_WIREGUARD.md` (WireGuard, подключение клубов).

---

## 0. Архитектура в двух словах

```
 Админ платформы (браузер + клиентский сертификат .p12)
   │  HTTPS + mTLS, порт 8443
   ▼
 ПЛАТФОРМА (debianNOUT): панель (web), platform_api, license_studio_api,
   platform_db, wireguard (51829/udp)
   │  WireGuard-туннель 10.0.0.0/24
   ▼
 КЛУБ (nfs и далее любой): FitIntel API + агенты: /admin/console (веб-консоль),
   /admin/impersonate/start, heartbeat, ent_bridge
```

Два разных «секрета» — не путать:

| Секрет | Что это | Где лежит | Срок |
|---|---|---|---|
| **CLUB_ADMIN_KEY** | Секретный ключ доступа к конкретному клубу | `.env` клуба (CLUB_ADMIN_KEY=) + менеджер паролей платформы | бессрочный, ротируется вручную |
| **console_token** | Билет сеанса веб-консоли клуба | выдаётся панелью автоматически при «Войти» | 20 мин (настройка в панели), продлевается при активности |
| **клиентский сертификат** | Пропуск админа в панель платформы | устройство админа (.p12) + CA платформы | 825 дней |

## 1. Доступ администратора ПЛАТФОРМЫ (панель 8443)

### 1.1 Принцип

Общего логина/пароля у панели нет. Доступ = **персональный клиентский сертификат** (mTLS),
выпущенный CA платформы на email админа (CN сертификата = email). Все действия в аудите
подписаны этим CN. Один сертификат — на человека; «общего на всех» не существует.

### 1.2 Добавить нового администратора платформы

Выполняется на сервере платформы (debianNOUT) одной командой:

```bash
cd ~/fitintel-pro/deploy/platform
bash scripts/platform_admin_add.sh admin2@fixintel.ru
```

Скрипт автоматически:
1. выпускает клиентский сертификат `client_admin2@fixintel.ru.{crt,key,p12}` (в `nginx/certs/`);
2. добавляет CN в список `ADMIN_CNS` в `.env` (если его там ещё нет);
3. перезапускает `platform_api` (новый список вступает в силу).

Проверка:

```bash
grep ADMIN_CNS .env          # admin2@fixintel.ru в списке
ls -l nginx/certs/client_admin2@fixintel.ru.p12
```

### 1.3 Скачать и передать .p12 администратору

Файл нужно доставить на устройство админа **по защищённому каналу** (лично, мессенджер с
шифрованием; НЕ email). Удобный способ из любой папки сервера — временный контейнер-раздача:

```bash
# на debianNOUT:
mkdir -p /tmp/p12share
cp nginx/certs/client_admin2@fixintel.ru.p12 /tmp/p12share/admin2.p12
chmod 644 /tmp/p12share/admin2.p12
docker run --rm --name tmp-p12 -p 8898:80 -v /tmp/p12share:/usr/share/nginx/html:ro nginx:alpine
# консоль не закрывать до скачивания
```

**Windows (админ):**

```powershell
curl.exe -o "$env:USERPROFILE\Downloads\admin2.p12" http://192.168.101.125:8898/admin2.p12
certutil -user -p "" -importpfx "$env:USERPROFILE\Downloads\admin2.p12"
# затем: перезапуск Chrome -> https://<адрес панели>:8443/ -> выбрать сертификат admin2
```

**iPhone/iPad:** iOS **не принимает p12 без пароля** — пересоберите контейнер с паролем:

```bash
# на debianNOUT (контейнер из п.1.3 остановить):
cd nginx/certs
openssl pkcs12 -export -out /tmp/p12share/admin2.p12 -inkey client_admin2@fixintel.ru.key \
  -in client_admin2@fixintel.ru.crt -certfile ca.crt
# пароль при экспорте: fitintel (дважды), chmod 644, снова поднять контейнер
```

На iPhone: Safari → скачать → Файлы → открыть → Установить профиль → **Настройки → Основные →
Об этом устройстве → Доверие сертификатам → FitIntel Platform CA = вкл**. Открыть
`https://<адрес>:8443/`.

**Android:** Настройки → Безопасность → Установка сертификата → «Сертификат» → .p12
(пустой пароль допустим).

После передачи: `docker stop tmp-p12`, `rm -rf /tmp/p12share` (на debianNOUT).

### 1.4 Отозвать администратора (увольнение / потеря устройства)

```bash
cd ~/fitintel-pro/deploy/platform
bash scripts/platform_admin_remove.sh admin2@fixintel.ru
```

Скрипт: убирает CN из `ADMIN_CNS` → перезапускает api → вносит серийник сертификата в CRL
(метод R-строки, см. MTLS_PLATFORM_ACCESS.md §7) → пересоздаёт `ca.crl` → удаляет файлы
сертификата → перезапускает nginx. После этого админ отрезан везде: панель не откроется
(`certificate revoked`), даже если .p12 у него остался.

Ручная проверка отзыва:

```bash
curl --cacert nginx/certs/ca.crt --cert nginx/certs/client_admin2@fixintel.ru.crt \
     --key nginx/certs/client_admin2@fixintel.ru.key https://127.0.0.1:8443/health 2>&1 | tail -1
# ожидаем: certificate revoked (файлов уже нет — проверка только по CRL в nginx)
```

### 1.5 SSH/туннель администратора (для глубокой диагностики)

Для SSH к серверам клубов админу выдаётся отдельный **WireGuard-пир** (peer12 у andrei@fixintel.ru):
см. REMOTE_ACCESS_WIREGUARD.md §3. Для работы в панели WG не нужен — только сертификат.

## 2. Панель платформы: экраны

Открыть: `https://<адрес панели>:8443/` (из LAN: `https://192.168.101.125:8443/`, снаружи —
по белому IP; сертификат выбирается автоматически). Если спросит — выбрать свой CN.

| Вкладка | Что умеет |
|---|---|
| **Дашборд** | KPI: клубов / онлайн / приостановлено / клиентов в сети / проблемные лицензии; лента событий; автообновление 30 с. Онлайн-статус — по порогу `offline_threshold_sec` |
| **Клубы** | Таблица (бейджи online/offline/suspended, лицензия, версия, клиенты, last_seen); фильтры, поиск, **Экспорт CSV**; клик — карточка клуба; кнопки «Войти», «Приостановить/Возобновить» |
| **Лицензии** | По клубам: статус (active/grace/blocked), «Истекает», «Оплачено до», grace-до; кнопки +30/+90/+365. **Авто-продление**: если «Оплачено до» позже «Истекает» — срок сам подтягивается при следующем обращении |
| **Аудит** | Все действия админов (license.issue/renew, impersonate.start, club.suspend, settings.set...); фильтры actor/action/limit |
| **Настройки** | Платформенные параметры (см. §4) |

## 3. Доступ к серверу КЛУБА (секретный ключ CLUB_ADMIN_KEY)

### 3.1 Что это

`CLUB_ADMIN_KEY` — **секретный ключ клуба**: 64 hex-символа, уникальный для каждого клуба.
Хранится: в `.env` клуба (`CLUB_ADMIN_KEY=...`) и в менеджере паролей платформенного админа
(1Password/KeePass). **В git не коммитится.** Без него JWT/сертификат платформы к данным
клуба не допускаются (двухфакторность: mTLS-админ + ключ клуба).

### 3.2 Вход в клуб (impersonation)

1. Панель → «Клубы» → у нужного клуба кнопка **«Войти»**;
2. Ввести **CLUB_ADMIN_KEY** этого клуба (вручную, из менеджера паролей; не сохраняется);
3. Панель показывает **временные креды** `platform.admin` + пароль (TTL 5 минут, для входа
   в десктоп-клиент клуба) и кнопку **«Веб-консоль клуба»** — открывает консоль в браузере.

Каждый вход фиксируется в аудите платформы (`impersonate.start`).

### 3.3 Веб-консоль клуба (что внутри)

| Вкладка | Возможности |
|---|---|
| **Пользователи** | Создать (логин/телефон/роль/пароль-авто); таблица; карточка по клику: ФИО/телефон/email, **права** (галочки по 73 кодам), **экраны десктопа** (видимость), блок/разблок, сброс пароля, удаление (мягкое). «Сохранить» с изменёнными правами/экранами создаёт **персональный профиль** (скрытая роль user_<логин>); «Сбросить к роли» возвращает к стандартной |
| **Клиенты** | Поиск (фамилия/телефон/email), карточка: все поля, абонементы, платежи, визиты |
| **Health** | БД (latency), диск %, аптайм, версия |
| **Логи** | Последние N строк лога api (история — `docker logs deploy-api-1` на сервере клуба) |
| **Перезапуск API** | Кнопка: api перезапускается (~60 с), сессия прервётся |

Токен сеанса консоли: по умолчанию **20 минут**, **продлевается при каждом действии**
(пока работаете — не вылетите). Точное значение — настройка `console_token_ttl_min` (см. §4).

### 3.4 Ротация CLUB_ADMIN_KEY

Раз в год, при компрометации или уходе сотрудника, знавшего ключ:

```bash
# на сервере КЛУБА (nfs):
cd ~/fitintel-pro/deploy
NEW=$(openssl rand -hex 32)
sed -i "s/^CLUB_ADMIN_KEY=.*/CLUB_ADMIN_KEY=$NEW/" .env
docker compose -f docker-compose.prod.yml up -d --force-recreate api
echo "новый ключ: $NEW   (запишите в менеджер паролей, старый мёртв)"
```

Старый ключ перестаёт приниматься немедленно (проверка по значению в env контейнера).

### 3.5 Ключ при установке НОВОГО клуба

Генерируется при провижининге: `openssl rand -hex 32` → в `deploy/.env` клуба → в менеджер
паролей платформы. Клуб при этом получает также: пир WireGuard (peerN) и токен heartbeat
(`api_token` из карточки клуба в панели). Полный чек-лист: REMOTE_ACCESS_WIREGUARD.md §8.

## 4. Настройки платформы (вкладка «Настройки»)

| Ключ | Значение по умолчанию | Что делает |
|---|---|---|
| `console_token_ttl_min` | 20 | TTL токена веб-консоли клуба, мин (5–120). Новые сессии и продление при активности |
| `offline_threshold_sec` | 180 | Сколько секунд без heartbeat клуб считается online (бейджи на дашборде) |
| `license_alert_days` | 7 | Порог «истекает лицензия», дней (задел под алерты) |

Изменение: ввести значение → «Сохранить» (фиксируется в аудите `settings.set`). Применяется
без перезапусков: к новым сессиям/проверкам немедленно.

## 5. Добавление нового клуба (кратко)

1. Панель → «Клубы» → создать (POST /platform/clubs) → сохранить `api_token` (показывается один раз);
2. debianNOUT: увеличить `PEERS` в compose на 1, `docker compose up -d`, забрать `peerN.conf`;
3. Клуб: `wg-quick` поднять (см. REMOTE_ACCESS §4; на nfs сервис `fitintel-wg`);
4. Панель: присвоить клубу `wireguard_ip` (SQL UPDATE или карточка);
5. Выдать CLUB_ADMIN_KEY (§3.5), настроить heartbeat (cron каждые 5 мин);
6. Выпустить лицензию: «Лицензии» → +365; активировать в клубе (ключ + пароль SuperAdmin из ключа).

## 6. Типовые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Панель: `400 No required SSL certificate` | p12 не установлен в браузер/ОС | импорт .p12 (§1.3), выбрать сертификат |
| `certificate revoked` | сертификат отозван / просрочен | выпустить заново (§1.2) |
| Панель: `403 CN not allowed` | CN нет в ADMIN_CNS | §1.2 (add-скрипт) |
| Консоль клуба: `401 invalid or expired token` | 20 мин бездействия | вернуться в панель → «Войти» заново |
| `403 invalid admin key` при «Войти» | неверный CLUB_ADMIN_KEY | взять из менеджера паролей; при ротации — новый |
| `409 club has no wireguard_ip` | клубу не присвоен IP туннеля | §5 п.4 |
| Страница «не кликается», SyntaxError в консоли | кэш браузера / расширение (значок «К») | Ctrl+Shift+R; проверить в инкогнито; отключить расширение для адреса панели |
| `Internal Server Error` в консоли | смотреть traceback: `docker compose -f docker-compose.prod.yml logs --since=5m api` (nfs) |
