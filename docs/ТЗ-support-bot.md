# ТЕХНИЧЕСКОЕ ЗАДАНИЕ — умный Бот MAX для техподдержки FitIntel Pro

> Источник истины по боту поддержки. Принято 07.11.2026 (объединённые версии 1–3).
> Реализация: `support_bot/` + `deploy/support-bot/`. Состояние в `areas/support-bot.md` (память).

## 1. Назначение и среда
Интеллектуальный чат-бот в MAX для техподдержки фитнес-клубов — FitIntel Pro. Отвечает на типовые вопросы (текст + скриншоты), эскалирует сложные случаи администраторам, ведёт аналитику. Вся работа — внутри интерфейса MAX.
- Сервер: 192.168.101.125 (Docker). Домен: fixintel.ru (webhook). API MAX: platform-api.max.ru (api2 — dev).
- Хостинг бота: `deploy/support-bot/docker-compose.yml` (контейнеры support-bot, support-bot-db).

## 2. Роли и права (гибкая система)
1. **Владелец (Owner)** — полный доступ, назначение ролей, настройка бота, /grant /revoke /rights.
2. **Главный администратор (Superadmin)** — база знаний, график, администраторы, полная аналитика.
3. **Администратор (Admin)** — ответы на тикеты, управление участниками чата; аналитики и настроек по умолчанию нет.
- Флаги прав: view_stats, manage_kb, manage_schedule, manage_admins, manage_chat (последнее — у Admin по умолчанию).
- Аккаунт владельца многопользовательский: режимы «Пользователь ПО» / «Админ поддержки» / «Авто» (переключатель-кнопки, только для admin, см. регламент п.8 памяти).

## 3. Функциональные требования
### 3.1 Идентификация клиента
По активной лицензии в FitIntel Platform (API платформы). Активна → привязка клуба; no_license → «Ваша лицензия неактивна. Обратитесь к администратору платформы» + эскалация. (Сейчас: префикс ключа по /platform/clubs + /platform/clubs/{slug}/license; deeplink ?start=префикс из desktop.)

### 3.2 База знаний
БД (таблица kb_articles: вопрос, ключевые слова, ответ, категория, screenshots[]). Поиск по кнопкам/функциям десктопа. Скриншоты прикрепляются к ответам (uploads→CDN→photos.token). Приём скриншотов ОТ клиента — сохранять в тикет. Веб-редактор базы — только Owner/Superadmin (Flask/FastAPI + пароль).

### 3.3 Эскалация и SLA (10 мин)
Нет ответа / «позовите человека» → «Передал вопрос специалисту. Ожидайте» → тикет в чат поддержки. Назначение: из отметившихся на смене (round-robin). SLA: 10 мин — напоминание; 20 мин — переназначение следующему + лог причины. Ответ админа → клиенту. Тикет закрывается. Клиент слово «тикет» не видит.

### 3.4 Администраторы, график, отметки
- Автоотметка «на смене» при первом сообщении в чате поддержки (вариант А); /checkin (вариант Б); 09:00 «Подтвердите выход» с кнопкой (вариант В) — если уже писал, отметка есть.
- График: /schedule add <username> <дни> <время>. Не отметившиеся не назначаются; никто не отметился → Главному админу.
- /add_admin <username> → авто-пространство в чате.

### 3.5 Интерфейс
- **Клиенты**: только чат с ботом. Главное меню inline-кнопками: «Клиенты», «Абонементы», «Платежи», «Face ID», «Вендинг», «Отчёты», «Связаться с администратором»; уточняющие кнопки внутри разделов.
- **Администраторы**: отдельный интерфейс — общий чат поддержки с вкладками; кнопки на тикете: «Ответить», «Переназначить», «Закрыть»; команды /reply, /assign, /close.
- Разделение по клубам: чаты на клуб (≤10) или теги #клуб в тикетах.

## 4. Аналитика
Метрики: обращения за день (по клубам/клиентам), топ-5 вопросов, пробелы базы (текст+дата), среднее время ответа, нагрузка админов. Ежедневный отчёт 18:00 — Owner/Superadmin/флаг view_stats.

## 5. Архитектура
Python (FastAPI), PostgreSQL, webhook /bot/webhook, APScheduler (напоминания/чек-ины/отчёты), веб-редактор KB по паролю.

## 6. Критерии приёмки
Идентификация <2 с; ответ <3 с; мгновенные уведомления клиенту и админу; SLA 10/20 мин; автоотметка на смене; /grant /revoke /rights; авто-пространство новому админу; отчёт 18:00 авто; приём скриншотов от клиента; всё логируется; веб-KB только Owner/Superadmin.

## 7. Этапы
