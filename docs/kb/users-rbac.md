# users-rbac — пользователи, роли, права, экраны

> Категория: users-rbac · Проверено для: 1.6.2 · Для кого: администратор, superadmin, владелец.

## Как создать пользователя (сотрудника)
Ключевые слова: создать пользователя, новый сотрудник, завести логин
**Ответ.** «Пользователи → Создать пользователя»: Логин* (уникальный), Email* (уникальный, формат name@domain.ru — обязателен!), Пароль* (минимум 8 символов), Роль* (Администратор/Менеджер/Тренер/Ресепшен/Кассир/Бухгалтер/Поддержка/Владелец/Охрана/СКУД/Платформенная поддержка) → OK. Роль назначается автоматически (ИНСТРУКЦИЯ §19.3, RBAC.md §5.1).
📷 [SCR-rbac-01: форма «Новый пользователь»]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Роли: кто что видит (кратко)
Ключевые слова: роли, кто что видит, матрица ролей, 9 ролей
**Ответ.** 12 ролей: SuperAdmin — всё (18 вкладок); Администратор — 17; Менеджер — 13; Кассир — 8–9; Ресепшен — 5; Бухгалтер — 6; Тренер — 5; Владелец (Директор) — контроль (аудит, удаление); Поддержка (вендор) — чтение; Платформенная поддержка — сервис платформы; Охрана/СКУД — контроль доступа; Клиент — личный кабинет; Устройство — API СКУД. **Живые счётчики прав: Admin 75, Manager 19, Cashier 11, Accountant 8, Client 8, Trainer 4** (матрица «Настройки → Роли и права»: 12 ролей / 75 прав).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как выдать или ограничить права роли
Ключевые слова: роли и права, матрица прав, выдать право, permissions
**Ответ.** «Настройки → Роли и права» → роль слева → галочки прав справа → «💾 Сохранить изменения». Формат прав «объект.действие» (payments.refund, users.delete). Применяется мгновенно. Guard не даст снять критичные права у системных ролей и выдать их роли «device» (RBAC.md §4–5, §8).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Экраны ролей (видимость вкладок)
Ключевые слова: экраны ролей, видимость, ui-config, матрица экранов
**Ответ.** «Настройки → Экраны ролей» (только superadmin): роль → галочки экранов → «Сохранить». Строгая модель: не отмечено = роль не видит экран вообще. У superadmin экран «Экраны ролей» заблокирован — защита от самоблокировки. «Сбросить к умолчанию» вернёт дефолт (ИНСТРУКЦИЯ §22.3, RBAC.md §4).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Сброс пароля сотруднику
Ключевые слова: сбросить пароль, забыл пароль пользователя
**Ответ.** «Пользователи» → выделить → «✎ Изменить → Сбросить пароль» → сообщите новый. При первом входе сотрудник задаст свой. Доступно администратору (ИНСТРУКЦИЯ §19.5).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Увольнение: как закрыть доступ
Ключевые слова: уволить, деактивировать пользователя, отключить доступ
**Ответ.** «Пользователи → 🗑 Удалить» (подтверждение) — мягкая деактивация: вход невозможен немедленно, история действий сохраняется в «Истории» для разбора. Роли снимать не нужно — доступ исчез с учёткой. SuperAdmin удалить нельзя (ИНСТРУКЦИЯ §19.4, RBAC.md §5.3).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Ошибка 500 после создания пользователя (/auth/me)
Ключевые слова: 500 после входа, auth me, кривой email
**Ответ.** В карточке пользователя email в невалидном формате (user@ или name@local). Email обязателен и проверяется — поправьте на name@domain.ru (RBAC.md §8, TROUBLESHOOTING §17.7).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Сколько прав у роли и где это видно
Ключевые слова: количество прав, права роли, 15 прав
**Ответ.** «Пользователи» — колонка «Прав» показывает итог по всем ролям пользователя (объединение, дедуп по коду). Фактические счётчики (живая матрица): Admin 75, Manager 19, Cashier 11, Accountant 8, Client 8, Trainer 4. Диагностика: `GET /users/{id}/permissions`, матрица `GET /rbac/matrix` (RBAC.md §3, ИНСТРУКЦИЯ §19.1).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».
