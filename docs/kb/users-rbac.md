# users-rbac — пользователи, 12 ролей, права, экраны (14 статей)

> Категория: users-rbac · Проверено для: 1.6.2 по экранам «Пользователи», «Роли и права», «Экраны ролей».
> Права — тонкие (RBAC): ~75 у администратора; экраны не отмеченные в матрице ролей НЕ видны.

## Создание нового сотрудника (пользователя)
Категория: users-rbac
Вариации запроса: новый сотрудник, создать пользователя, добавить менеджера, завести учётку
📷 Скриншоты: scr-users-01.png

**Пошагово (admin).**
1. «Пользователи» → «➕ Новый сотрудник».
2. Обязательные поля: ФИО, email (логин!), роль (одна или несколько).
3. Пароль: задайте временный (сотрудник сменит при первом входе — окно смены откроется само) или отправьте приглашение.
4. «Сохранить». Ожидание: сотрудник в списке, может войти по email.

**Типичные ошибки.** Email уже занят — у пользователя уже есть учётка; пустой email — назначение ролей упадёт с 400.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## 12 ролей в системе: кто что видит
Категория: users-rbac
Вариации запроса: роли, список ролей, администратор менеджер кассир, какие роли есть
📷 Скриншоты: scr-users-01.png

**Ответ (счётчики прав — живые значения 1.6.2).**
1. **Администратор** — всё (~75 прав). Настройки, касса, пользователи, СКУД, удаления.
2. **Директор** — аналитика и отчёты, касса (чтение).
3. **Менеджер** (~19 прав) — клиенты, продажи, расписание, рассылки.
4. **Кассир** (~11) — платежи, касса, чеки, клиенты (чтение/создание).
5. **Бухгалтер** (~8) — платежи (чтение), проводки, отчёты, зарплата, экспорт 1С.
6. **Тренер** (~4) — своё расписание, отметка посещений, свои клиенты.
7. **Клиент** (~8) — личный кабинет/мини-приложение.
8. **Ресепшен** — впуск/выпуск, поиск клиентов, шкафчики.
9. **Охрана/СКУД** — входы/выходы, мониторинг турникета, журнал отказов.
10. **Платформенная поддержка** — помощь клубу, без доступа к деньгам (impersonation через ключ платформы).
11. **Маркетолог** — рассылки, Новости, сегменты.
12. **HR/Кадры** — сотрудники, графики, документы.

Точные права каждой роли: «Настройки → Роли и права».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Назначение и смена роли сотруднику
Категория: users-rbac
Вариации запроса: назначить роль, сменить роль, поменять права сотруднику
📷 Скриншоты: scr-users-05.png

**Пошагово (admin).**
1. «Пользователи» → двойной клик по сотруднику → «Роль и права».
2. Отметьте галочки ролей (можно несколько). Ожидание: счётчик «эффективных прав» обновился.
3. «Сохранить». Ожидание: зелёная плашка «Сохранено» — права применяются мгновенно, перелогин не нужен.

**Типичные ошибки.** 400 при сохранении — пустой email сотрудника; снятие последней роли у самого себя заблокировано (anti-lockout) — сначала назначьте новую роль.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Матрица ролей»: эффективные права с разбором
Категория: users-rbac
Вариации запроса: матрица ролей, эффективные права, откуда право, разбор прав
📷 Скриншоты: scr-users-01.png

**Ответ.** Вкладка «Матрица ролей» в «Настройки → Роли и права»: для выбранного сотрудника показывает дерево прав с источником — из какой роли пришло каждое право (прямая галочка роли, наследование, отдельное индивидуальное право).
**Пошагово.**
1. «Роли и права» → «Матрица ролей» → выберите сотрудника.
2. Раскрывайте ветки: отмеченное галочкой — действует; серая подсветка — источник.
3. Индивидуальное право (вне ролей) добавляется здесь же: галочка → «Сохранить», сотруднику уходит запись в аудит.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Экраны ролей: почему у сотрудника нет вкладки
Категория: users-rbac
Вариации запроса: экраны ролей, нет вкладки, не видит раздел, матрица экранов
📷 Скриншоты: scr-set-03b-roles-dropdown.png, scr-set-03.png

**Ответ.** Строгая модель: экран не отмечен для роли = не виден в sidebar вообще. Экраны: Главная, Музыка, Клиенты, Входы/Выходы, Абонементы, Услуги, Расписание, Бухгалтерия, MAX сообщения, Уведомления, AI центр, Пользователи, История, Магазин, Face ID, Настройки, Банки, Браслеты/Карты, Параметры клуба.
**Пошагово.**
1. «Настройки → Экраны ролей» → выберите роль.
2. Отметьте нужные экраны → «Сохранить».
3. Сотрудник выходит/входит — вкладки появились.

**Типичные ошибки.** Искать причину в правах — причина именно в экранах; «Экраны ролей» недоступны вашей роли — только admin.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Сброс пароля сотруднику
Категория: users-rbac
Вариации запроса: сбросить пароль, забыл пароль сотрудник, восстановить доступ менеджеру
📷 Скриншоты: scr-users-01.png

**Пошагово (admin).**
1. «Пользователи» → сотрудник → «Сбросить пароль».
2. Задайте временный пароль и передайте лично (не в общий чат).
3. Сотрудник входит → система сама открывает окно обязательной смены пароля → новый пароль 8+ символов.
   Ожидание: вход выполнен, пароль сменён.
4. Действие фиксируется в аудите доступа.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Увольнение: как закрыть доступ
Категория: users-rbac
Вариации запроса: уволить, отключить сотрудника, заблокировать учётку, уволенный ходит в систему
📷 Скриншоты: scr-users-01.png

**Пошагово (admin).**
1. «Пользователи» → карточка сотрудника → «Деактивировать» (учётка сохраняется, вход закрыт).
2. Снимите все роли и экраны.
3. Браслеты/QR сотрудника — в «Браслеты/Карты → QR сотрудников» → блокировка.
4. Ожидание: вход невозможен (401), карточка помечена «Неактивен»; история действий сохранена в аудите.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Индивидуальные права вне ролей
Категория: users-rbac
Вариации запроса: индивидуальное право, дать право одному человеку, исключение из роли
📷 Скриншоты: scr-users-01.png

**Пошагово (admin).**
1. «Настройки → Роли и права → Матрица ролей» → сотрудник.
2. Отметьте конкретное право (например `payments.refund` бухгалтеру) → «Сохранить».
3. Ожидание: право действует немедленно; в матрице подсвечено как индивидуальное; запись в аудите.
4. Индивидуальные права не копируются при смене роли — учитывайте при переводах.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Ошибка 500 при сохранении пользователя
Категория: users-rbac
Вариации запроса: 500 users, не сохраняется сотрудник, ошибка при создании пользователя
📷 Скриншоты: scr-users-01.png

**Пошагово.**
1. Проверьте email: уникальный, без пробелов, с @ (типовая причина 500/400).
2. Телефон — формат +7XXXXXXXXXX, если заполняется.
3. Уберите не-ASCII из полей, если копировали из Word (скрытые символы).
4. Повторите. Не помогло — IT: логи api в момент сохранения.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Документы сотрудника (AES-256-GCM)
Категория: users-rbac
Вариации запроса: документы сотрудника, загрузить скан, договор трудовой
📷 Скриншоты: scr-users-07.png, scr-users-11.png, scr-users-10.png, scr-users-09.png, scr-users-06.png

**Пошагово.**
1. Карточка сотрудника → «Документы» → «➕ Загрузить»: трудовой договор, паспорт, медкнижка и т.п.
2. Файлы хранятся **зашифрованными** (AES-256-GCM) — доступны только ролям с правом на документы.
3. Скачивание/просмотр фиксируется в аудите.
4. Увольнение — документы сохраняются, доступ сотрудника закрывается.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Impersonation (помощь платформы клубу)
Категория: users-rbac
Вариации запроса: impersonation, войти от имени клуба, помощь платформы, ключ клуба
📷 Скриншоты: scr-users-01.png

**Ответ.** Платформенная поддержка может работать «глазами» клуба по ключу `CLUB_ADMIN_KEY` (эндпоинты admin_access/admin_console) — для диагностики без пароля клуба. Действия помощника видны в аудите с пометкой impersonation. Включение — только по запросу клуба; ключ хранится на сервере в `deploy/.env`.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
