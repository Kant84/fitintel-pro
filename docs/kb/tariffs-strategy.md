# clients: стратегия тарифов (8 статей)

> Категория: clients-subs · Модели тарифов, сетка, заморозки, скидки, акции, корпораты, пробники.

## Типы тарифов: какой выбрать
Категория: clients-subs
Вариации запроса: типы тарифов, срок лимит безлимит, какой тариф создать

**Три модели.**
1. **По сроку** (30 дней, безлимит входов) — базовый абонемент.
2. **По лимиту** (8 визитов/30 дней) — для нерегулярных посетителей; дешевле безлимита.
3. **По сроку + лимит** (12 занятий/30 дней с тренером) — услуговые пакеты.
Создание: «Тарифы → Создать тариф» → код/название/цена/дней/лимит/тип. Продаётся сразу после сохранения.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Конструктор тарифной сетки клуба
Категория: clients-subs
Вариации запроса: тарифная сетка, примеры тарифов, какие тарифы должны быть

**Каркас сетки.**
1. Входной (1 день/1 визит) — разовый, для новичков.
2. Базовый (безлимит 30 дн) — основной.
3. Средний (безлимит 90 дн) — средний чек выше, удержание лучше.
4. Годовой (12 мес, рассрочка) — лояльные.
5. Лимитированные (8/12 визитов) — ценочувствительные.
6. Семейный/парный — скидка за кол-во.
7. Корпоративный (юрлица) — отдельный прайс.
Цены — с шагом, который подталкивает к более длинному периоду (выгода очевидна).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Заморозки: правила в тарифе
Категория: clients-subs
Вариации запроса: заморозка сколько раз, правила заморозки, лимит заморозок

**Настройка.** В тарифе — допустимые заморозки (если тариф поддерживает): при продаже укажите; при заморозке система сдвигает срок окончания на дни заморозки.
**Регламент клуба.**
- Бесплатные заморозки: N дней/год (обычно 14–30).
- Сверх лимита — платно (услуга «Продление заморозки») или по мед. справке бесплатно.
- Мед. заморозка — без лимита (документ в карточку).
Количество оставшихся заморозок видно в «Пакеты/Услуги».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Скидки и наценки: где задаются
Категория: clients-subs
Вариации запроса: скидка в продаже, персональная скидка, наценка тариф

**Где.**
1. В момент продажи — поле скидки в окне продажи (процент/сумма).
2. Персональная скидка клиента — «СЧЁТ → Скидки» (применяется автоматически).
3. Тарифные скидки — отдельные тарифы со сниженной ценой (акционные).
**Контроль.** Скидки видны в чеке и проводках; журнал — разбор причин (аудит кто продал со скидкой).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Акционные тарифы: создание и старт/стоп
Категория: clients-subs
Вариации запроса: акционный тариф, сезонная акция, ограничить продажу

**Пошагово.**
1. «Тарифы → Создать тариф» → код SALE_..., цена со скидкой, срок действия самого абонемента.
2. Контроль периода продажи — регламент: продавать акционный тариф только в даты акции (менеджеры инструктируются; при необходимости — деактивация тарифа после акции, галочка через «✎»).
3. Остаток акции — в рассылках («осталось 3 дня»).
4. По окончании — деактивировать (или переименовать).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Корпоративные тарифы (юрлица)
Категория: clients-subs
Вариации запроса: корпоративный тариф, абонемент для компании, юрлицо клиент

**Схема.** Корпоративный клиент — карточка клиента (название компании в ФИО/комментарии) + договор (шаблон contract) + оплата безналом/переводом. Тариф — отдельный (скидка объёма) или стандартный. Учёт сотрудников компании — как гости/отдельные карточки (по регламенту). Отчёт по корпоративу — фильтр категории клиента + выгрузка.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Пробный тариф и конверсия в базовый
Категория: clients-subs
Вариации запроса: пробное занятие, пробный тариф, конверсия пробника

**Схема.** Пробный визит — тариф «Пробный (1 визит)» по сниженной цене/бесплатно (цена 0 — если регламент позволяет).
**Конверсия.**
1. После визита — менеджер звонит в течение дня (пока «горячий»).
2. Оффер: стоимость пробного засчитывается при покупке базового (кодовое слово/комментарий в продаже).
3. Не купил → воронка «Давно не посещали» через 3–7 дней.
Контроль: % пробников → базовый — метрика менеджера.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Перенос остатка со старого тарифа
Категория: clients-subs
Вариации запроса: остаток перенести, переход на другой тариф, зачёт остатка

**Сценарий.** Клиент переходит на другой тариф с неиспользованным сроком.
**Порядок.**
1. Возврат неиспользованной части (по правилам клуба: пропорционально или фикс на карточку) — «↩ Возврат» с комментарием «переход на тариф X».
2. Продажа нового тарифа (способ «Внутренний баланс» — если возвращали на кошелёк).
3. Оба действия — в один день, с комментариями (аудит).
Массовые переходы (смена прайса) — через поддержку/регламент.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
