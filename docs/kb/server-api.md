## Назначение API и базовые правила
Категория: server
Вариации запроса: api что умеет, rest, авторизация bearer

**Общее.** REST API под `/api/v1`. ## Платежи: endpoints и статусы
Категория: payments
Вариации запроса: api платежи, create complete refund, статусы payment

**Endpoints (app/api/v1/payments.py).**
- `POST /payments` — создать (право `payments.create`); способ оплаты; статус pending.
- `GET /payments/me` / `/client/{id}` — списки.
- complete — подтверждение (`payments.update`): сначала фискальный чек, потом статус; смена закрыта → 400.
- refund — возврат (`payments.refund`, поля amount/reason/refund_to_balance).
- online + webhook — онлайн-оплата (подпись `X-Payment-Signature`, HMAC).
Статусы: pending → completed (refunded). Авто-чек на email через ReceiptService.

## Вендинг: сессии, код, confirm
Категория: vending
Вариации запроса: api вендинг, purchase session confirm, код 6 цифр

**Endpoints (app/api/v1/vending.py).**
- create_session — код 6 цифр, TTL 10 мин, статус PENDING.
- poll — статус сессии (автомат опрашивает).

- Покупка по браслету (uid) и журнал продаж по автомату (`X-Device-Token`).

## Ошибки API: коды и что делать
Категория: errors
Вариации запроса: коды api 400 401 403 409 422 429 500, расшифровка

**Шпаргалка.** 400 — валидация (поля/смена закрыта); 401 — неверный токен/логин-пароль; 403 — нет права (RBAC) или нет согласия биометрии; 404 — нет объекта/неверный путь; 409 — конфликт (уже в клубе/уже оплачено); 422 — бизнес-отказ с причиной в detail (checkaccess — норма); 429 — лимит; 500 — сервер (логи api). Детально — errors.md.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)» (для server-тем — IT клуба с логами).

## Версионирование и совместимость desktop↔API
Категория: desktop
Вариации запроса: версия api и desktop, совместимость, обновление клиента

**Правило.** Desktop и API должны быть одной версии («Помощь → О программе»). API обратно совместим в пределах минорных версий; на мажорное обновление сервера — обновите desktop на всех ПК (Setup поверх). Расхождение версий — источник странных ошибок (например, «api-клиент без put/post» на «Клиенту» у desktop 1.6.1).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)» (для server-тем — IT клуба с логами).
