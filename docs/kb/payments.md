## Как провести платёж (принять оплату за абонемент)
Категория: payments
Вариации запроса: провести платёж, принять оплату, как пробить абонемент, оплата клиента оформление

**Пошагово.**
1. Откройте карточку клиента (двойной клик в «Клиенты») → кнопка «Продать услугу» (или раздел «Пакеты/Услуги» → «Продать»).
2. Выберите услугу/абонемент из справочника, период, при необходимости — скидку.
3. «К оплате» → «Подтвердить» → в окне платежа выберите способ: наличные / карта / кошелёк клиента.
   Ожидание: при наличных/карте откроется подтверждение платежа в «Платежи»; при кошельке — списание с баланса.
4. Для наличных/карты: «Бухгалтерия → Платежи» → платёж «Ожидает» → «✓ Подтвердить» (пробьётся чек).
   Ожидание: статус «Подтверждён», чек, проводка Дт 50/57 Кт 90.1.

**Типичные ошибки.** Подтверждение без открытой смены (ошибка 400); способ оплаты выбрали неверно — исправляется только возвратом + новым платежом.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Пополнение кошелька (внутренний баланс) клиента
Категория: payments
Вариации запроса: пополнить баланс, кошелёк клиента, зачислить деньги на счёт, внутренний счёт

**Пошагово.**
1. Карточка клиента → раздел «СЧЁТ → Баланс» → кнопка «Пополнить».
2. Введите сумму и способ пополнения (нал/безнал) → «OK».
3. При нал/безнал появится платёж «Ожидает» — подтвердите его в «Платежи» (чек обязателен, это реальные деньги).
   Ожидание: баланс вырос, в истории баланса появилась запись.
4. Оплата услуг с кошелька: при продаже выберите способ «Кошелёк» — спишется без чека (деньги уже прошли через кассу при пополнении).

**Типичные ошибки.** Пополнение без подтверждения платежа — баланс не вырастет.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Оплата ЮKassa: подключение (пошагово)
Категория: payments
Вариации запроса: юкасса подключить, yookassa настройка, онлайн оплата подключение, эквайринг юкасса

**Пошагово (admin + доступ в кабинет ЮKassa).**
1. Кабинет ЮKassa → «Интеграция» → скопируйте `shopId` и `Секретный ключ`.
2. «Настройки → Банки» → выберите «ЮKassa» → заполните Shop ID и Secret → «Сохранить».
3. В кабинете ЮKassa укажите webhook: `https://<домен-клуба>/api/v1/payments/yookassa/webhook`.
4. Проверьте, что домен доступен из интернета по HTTPS (webhook прилетает снаружи).
5. Нажмите «Проверить связь» в настройках банка. Ожидание: зелёный статус.
6. Тестовая оплата: создайте платёж 1 ₽ через мини-приложение и оплатите тестовой картой 5555 5555 5555 4477 (любая дата/CVV).
   Ожидание: платёж сам перешёл в «Подтверждён» (webhook), чек ушёл.

**Типичные ошибки.** Webhook не доходит: домен закрыт извне/не HTTPS; забыли активировать банк (кнопка «Сделать активным»).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Оплата прошла в ЮKassa, а в FitIntel платёж Ожидает»
Категория: payments
Вариации запроса: оплата прошла баланс не вырос, webhook не пришёл, деньги списались а не зачислились, платёж завис

**Пошагово.**
1. Подождите 2–3 минуты — webhook иногда идёт с паузой.
2. Проверьте, что webhook настроен и домен доступен извне (статья «ЮKassa: подключение», шаг 3–4).
3. В кабинете ЮKassa → «Интеграция → Уведомления»: там видно, уходят ли webhook'и и какие коды ответа получает ЮKassa. Ожидание: ответы 200.
4. Если webhook ушёл с ошибкой — посмотрите логи api (`docker compose logs --tail=100 api`) и приложите в обращение.
5. Временное решение: найдите платёж в «Платежи» и подтвердите вручную (предварительно сверившись с кабинетом ЮKassa!).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Задвоился платёж после оплаты
Категория: payments
Вариации запроса: двойной платёж, списалось два раза, дубль платежа, повторная оплата

**Пошагово.**
1. Сверьте с кабинетом ЮKassa/банком: реально ли было два списания.
2. В FitIntel оставьте один платёж, второй (дубль) — «✖ Отменить» (если «Ожидает») или «↩ Возврат» (если «Подтверждён»).
3. Реальное списание по дублю вернётся через банк — сроки зависят от банка клиента (обычно до 3 дней).

**Причина.** Клиент дважды нажал «Оплатить»/обновил страницу оплаты; защита от дублей есть на подтверждении, но не на создании платежа.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Рекуррентные платежи (автосписание)
Категория: payments
Вариации запроса: рекурренты, автосписание, автопродление абонемента, сохранённая карта

**Пошагово.**
1. Клиент должен один раз оплатить с галочкой «Сохранить карту» (согласие на автосписания — обязательно).
2. При продаже/продлении выберите способ «Рекуррент (сохранённая карта)» → списание пройдёт без участия карты.
3. Статус и историю автосписаний смотрите в истории платежей клиента.

**Типичные ошибки.** Карта протухла/недостаточно средств — рекуррент падает, клиенту уходит уведомление; платёж придётся провести вручную.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Способы оплаты в FitIntel — расшифровка
Категория: payments
Вариации запроса: способы оплаты, нал безнал кошелёк что значит, виды оплаты в платежах

**Ответ.**
- **Наличные** — реальные деньги в ящике; чек обязателен; проводка Дт 50.
- **Безнал (карта/эквайринг)** — терминал/ЮKassa; чек обязателен; проводка Дт 57.
- **Кошелёк** — внутренний баланс клиента; чек НЕ нужен (деньги прошли через кассу при пополнении); списание Дт счёта клиента.
- **Рекуррент** — безнал по сохранённой карте.
- **Бонусы** — оплата бонусами (если включено `BONUS_*` в параметрах клуба).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Оплата бонусами
Категория: payments
Вариации запроса: бонусы, оплатить бонусами, начисление бонусов, сгорание бонусов

**Пошагово.**
1. Убедитесь, что бонусы включены: «Настройки → Параметры клуба» → ветка `BONUS_*` (начисление %, срок жизни).
2. При продаже выберите способ «Бонусы» (доступен, если на балансе достаточно).
   Ожидание: списание бонусов, в «СЧЁТ → Бонусы» — запись.
3. Начисление: происходит автоматически по правилам параметров после подтверждённых платежей.
4. Срок жизни бонусов — в параметрах (`BONUS_TTL_DAYS`); просроченные сгорают.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Вендинг: покупка кодом из мини-приложения
Категория: payments
Вариации запроса: вендинг код, купить в автомате кодом, код для автомата, оплата автомата

**Пошагово (для клиента клуба).**
1. Откройте мини-приложение клуба в MAX → раздел вендинга → выберите товар.
2. Подтвердите покупку с баланса. Ожидание: на экране — код из 4–6 цифр, срок жизни кода — 10 минут (жёсткое значение системы).
3. Наберите код на клавиатуре автомата → автомат выдаёт товар.
4. Деньги списались с кошелька моментально; операция видна в «Вендинг → Журнал».

**Для сотрудника.** Журнал операций: «Вендинг» (вкладка sidebar) — время, сумма, автомат, статус.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Вендинг: покупка браслетом (RFID)
Категория: payments
Вариации запроса: вендинг браслетом, автомат считывает карту, покупка картой в автомате

**Пошагово.**
1. Приложите браслет к считывателю автомата.
2. Автомат списывает с кошелька (MDB-контракт с FitIntel) и выдаёт товар.

**Типичные ошибки.** «Отказ: недостаточно средств» — пополните кошелёк клиента (статья «Пополнение кошелька»); «Отказ: автомат не в сети» — IT: сеть автомата.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Регистрация автомата (X-Device-Token)
Категория: payments
Вариации запроса: добавить автомат, токен автомата, x-device-token, привязка вендинга

**Пошагово (admin/IT).**
1. «Вендинг → Настройки» → «+ Добавить автомат»: имя, расположение.
2. Система выдаёт `X-Device-Token` — впишите его в прошивку/настройки автомата (заголовок при каждом запросе).
3. Автомат обязан вызывать `confirm` после выдачи товара — иначе деньги вернутся (резерв).
4. Проверка: тестовая покупка кодом → в журнале статус «Успешно».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Платёж ушёл в минус / корректировка баланса
Категория: payments
Вариации запроса: минус на балансе, отрицательный баланс, корректировка, списать ошибочное начисление

**Пошагово.**
1. Откройте «СЧЁТ → Баланс» клиента — там видна история движений: найдите ошибочную запись.
2. Если источник — ошибочный платёж: «↩ Возврат» (сторно + чек возврата).
3. Если нужна ручная корректировка без чека (опечатка при пополнении): пополнение/списание кошелька с комментарием; каждая операция фиксируется в аудите.
4. У клиента появился долг (минус) — он не сможет оплачивать кошельком, пока долг не закроется.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

   Ожидание после 1–3: кнопка активна.

## Как узнать, какой банк/эквайринг сейчас активен
Категория: payments
Вариации запроса: активный банк, какой эквайринг работает, где смотреть банк

**Пошагово.**
1. «Настройки → Банки» — активный банк подсвечен (баннер «Активен» на карточке банка).
2. Возможные подвкладки: Т-Банк, ЮKassa, Сбер, Альфа, Райффайзен (вкладка «Банки» в sidebar — 5 банков).
3. Смена активного: «Сделать активным» на нужной карточке → webhook активного банка перестанет приниматься, нового — начнёт.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
