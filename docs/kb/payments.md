# payments — платежи, возвраты, ЮKassa, кошелёк

> Категория: payments · Проверено для: 1.6.2 · Для кого: кассир, менеджер, администратор, бухгалтер.

## Как провести платёж (пошагово)
Ключевые слова: провести платёж, принять оплату, создать платёж
**Ответ.** 1) «Бухгалтерия → Платежи», выберите клиента (поиск по ФИО/телефону). 2) «＋ Провести платёж»: сумма; способ (Наличные/Карта/СБП/Перевод/Онлайн/Абонемент/QR/Внутренний баланс/Другое); направление (Приход/Расход); категория (Абонемент/Услуга/Товар/Прочее); комментарий. 3) OK — платёж создан со статусом «Ожидает» (ИНСТРУКЦИЯ §15.3, §28).
📷 [SCR-pay-01: форма «Провести платёж»]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как подтвердить платёж и пробить чек
Ключевые слова: подтвердить платёж, пробить чек, завершить платёж
**Ответ.** Выделите платёж «Ожидает» → «✓ Подтвердить». Сервер сначала пробивает фискальный чек на ККТ, потом переводит платёж в «Завершён» — деньги попадают в баланс смены и идёт автопроводка. Требование: смена открыта. Уже подтверждённый повторно не подтвердить (ИНСТРУКЦИЯ §15.4).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Чем «Отмена платежа» отличается от «Возврата»
Ключевые слова: отмена платежа, отмена или возврат, разница
**Ответ.** «↩ Возврат» — возврат полной или частичной суммы с любой причиной (например «Клиент передумал»). «✕ Отмена платежа» — технически тоже возврат, но полной суммы с причиной «Отмена платежа» (ошибка кассира/дубль). В отчётах отличайте по причине. Отдельного статуса CANCELLED в API нет (ИНСТРУКЦИЯ §29.3).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как пополнить баланс клиента (кошелёк)
Ключевые слова: пополнить баланс, кошелёк клиента, deposit
**Ответ.** Способ 1 (касса): проведите платёж со способом «Внутренний баланс» и подтвердите — зачислится на кошелёк. Способ 2 (API/экран): `POST /wallet/client/{id}/deposit` (право `wallet.deposit`). Баланс виден в карточке клиента; у кошелька есть замороженная часть (`frozen_balance`) — например, под неоплаченную бронь (USER_GUIDE «Кошелёк»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Выгрузка платежей для бухгалтерии
Ключевые слова: экспорт csv, выгрузка платежей, 1с, бухгалтерия
**Ответ.** «Платежи → ⇩ Экспорт CSV» — файл платежей клиента (UTF-8 с BOM, Excel откроет кириллицу). Для 1С: `GET /accounting/export/1c` и `/accounting/export/buh` из раздела «Бухгалтерия → 1С» (ИНСТРУКЦИЯ §15.2, §10).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Подключение онлайн-оплаты (ЮKassa) — что понадобится
Ключевые слова: юкасса, yookassa, онлайн оплата, подключить оплату
**Ответ.** 1) Кабинет ЮKassa (yookassa.ru) → shopId + секретный ключ (тестовый без договора). 2) Desktop → «Параметры клуба → Настройки приложения» (или «Временные параметры»): `WALLET_PAY_PROVIDER=yookassa`, `YK_SHOP_ID`, `YK_SECRET_KEY`. 3) Webhook в кабинете: `https://<домен-клуба>/api/v1/yookassa/webhook`. 4) Тест: карта 5555 5555 5555 4444 (успех) / …4477 (отказ). Подробно — YOOKASSA_RUNBOOK.md «5 минут».
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Оплата прошла, а баланс не вырос (ЮKassa)
Ключевые слова: оплата прошла деньги не пришли, webhook не дошёл, баланс не пополнился
**Ответ.** Зачисление делает webhook, не форма оплаты. Проверки: 1) Webhook в кабинете настроен на HTTPS-адрес, доступный снаружи. 2) Тест webhook: POST пустого тела → ожидается 403 (endpoint жив, фильтр работает). 3) Логи: `docker logs deploy-api-1 --since 30m | grep -i yookassa`. 4) Провайдер без ключей (`WALLET_PAY_PROVIDER=test`) зачисляет мгновенно — для демо (YOOKASSA_RUNBOOK «Диагностика»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Двойное зачисление от повторного webhook
Ключевые слова: задвоился платёж, дубль webhook, идемпотентность
**Ответ.** Не должно происходить: событие фиксируется по `event_key` (`yookassa_webhook_events`), повтор — ответ `already`. Если задвоилось — смотрите таблицу `yookassa_webhook_events` и логи; второй платёж отмените возвратом. Проверка секрета/подписи обязательна (YOOKASSA_RUNBOOK «Безопасность»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Автоплатежи (рекурренты) — как настроить списание
Ключевые слова: автоплатёж, рекуррент, списание за продление
**Ответ.** API `/recurring/*`: расписание (день/неделя/месяц) + rebill-токен сохранённой карты. При сбое — ретраи с паузой 2^попытка часов, после max_retries — failed. Управление: пауза/возобновление/отмена расписания, история списаний, тестовый «fail-next». Боевая привязка карт — через ЮKassa (ADMIN_GUIDE §4, YOOKASSA_RUNBOOK).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Что значат способы оплаты в списке
Ключевые слова: способы оплаты, нал безнал, сбп, перевод, внутренний баланс
**Ответ.** Наличные → наличный ящик (Дт 50). Карта/СБП/Онлайн/Перевод → безнал (Дт 57). «Внутренний баланс» → списание с кошелька клиента. «Абонемент (зачёт)» → оплата абонементом без движения денег. В балансе смены нал и безнал — РАЗДЕЛЬНО (ИНСТРУКЦИЯ §15.2).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Оплата в автомате кодом из мини-приложения MAX
Ключевые слова: вендинг, автомат, код оплаты, оплата из приложения
**Ответ.** Клиент выбирает товар на экране автомата → автомат показывает 6-значный код (10 минут) → клиент в мини-приложении MAX: «Оплата на автомате» → вводит код → списание с баланса кошелька. При сбое выдачи — автовозврат. Контракт для прошивки автомата: VENDING.md (ИНСТРУКЦИЯ FAQ §36).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Бонусы при пополнении кошелька
Ключевые слова: бонусы, процент пополнения, баллы
**Ответ.** Начисление — по правилам «Параметры клуба → Бонусы» (категория × событие `topup`, fix/percent). Если правила нет — fallback `WALLET_BONUS_PERCENT` (по умолчанию 5%). Бонусы начисляются в XP геймификации. Тестовый сценарий: пополнение 100 ₽ → +5 бонусов (Docs_MAX_miniapp §«Правила бонусов»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».
