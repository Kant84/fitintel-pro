> Категория: settings-help · Проверено для: 1.6.2 по экранам «Настройки» (хаб 10 подвкладок) и меню «Помощь».

## Структура «Настройки»: 10 подвкладок-хаба
Категория: settings-help
Вариации запроса: настройки где, хаб настроек, подвкладки настроек, что где в настройках
📷 Скриншоты: scr-set-01.png

**Ответ.** Вкладка «Настройки» — хаб с 10 подвкладками:
1. **Мастер первого запуска** — пошаговая настройка нового клуба.
2. **Интерфейс** — тема (светлая/тёмная/контраст), шрифт, масштаб.
3. **Подключения** — профили серверов, проверка связи.
4. **Уведомления** — SMTP/SMS/MAX/webpush (дублирует вкладку «Уведомления»).
5. **Касса** — драйвер ККТ, адрес АТОЛ, ОФД.
6. **Расписание** — сетка, слоты записи (`SLOT_MINUTES`), онлайн-запись.
7. **Пользователи и роли** — сотрудники, роли/права, экраны ролей.
8. **Параметры клуба** — instance-конфигурация: `QR_TTL_MINUTES`, `SLOT_MINUTES`, фичи (`GYM_ACCESS`, `VENDING_ENABLED`), API-ключи интеграций.
9. **Service-аккаунты** — технические учётки (для интеграций/автоматизации).
10. **Аудит доступа** — журнал действий (см. users-rbac.md).

**Пошагово.** Откройте «Настройки» → нужная подвкладка → правка → «💾 Сохранить».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Где лежат логи desktop и как их отправить
Категория: settings-help
Вариации запроса: логи, журнал ошибок, где логи, отправить логи в поддержку
📷 Скриншоты: scr-set-01.png

**Ответ.**
- Desktop: «Помощь → Поддержка разработчика (MAX)» — обращение уходит АВТОМАТИЧЕСКИ с логами и версиями. Это предпочтительный способ.
- Вручную: логи лежат рядом с профилем приложения (`%APPDATA%\FitIntel\logs` на Windows).
- Сервер: `/opt/fitintel-pro/logs/` (`app.log`, `error.log`, `access.log`) — для IT клуба.

**Пошагово.**
1. Воспроизведите ошибку.
2. «Помощь → Поддержка разработчика (MAX)» → опишите действия и время.
3. Ожидание: обращение создано, вложены логи — ждите ответа в чате MAX.

**Если не помогло:** support@fixintel.ru — приложите лог-файл и версию («Помощь → О программе»).

## Табло (F11) для ресепшена/зала
Категория: settings-help
Вариации запроса: табло, f11, второй экран, экран для зала, индикация прохода
📷 Скриншоты: scr-set-01.png

**Пошагово.**
1. Подключите второй монитор (ТВ) к ПК ресепшена.
2. В desktop нажмите **F11** — окно переходит в режим табло (полный экран, без элементов управления).
3. На табло выводятся: индикатор прохода (ФИО + цвет кружка: зелёный — впущен, красный — отказ), счётчики, при желании — фото/QR.
4. Второй F11 / Esc — вернуть рабочее окно.

**Типичные ошибки.** Табло на том же экране перекрывает работу — выведите окно на второй монитор (Win+Shift+стрелка).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Горячие клавиши desktop
Категория: settings-help
Вариации запроса: горячие клавиши, hotkeys, f5, f11, ctrl+n, ускорение работы
📷 Скриншоты: scr-set-01.png

**Ответ (основные).**
- **F5** — обновить данные текущего экрана.
- **F11** — табло (полный экран).
- **Ctrl+N** — новый клиент.
- **Ctrl+Z** — отмена последнего действия (меню «Правка»).
- **Enter** в полях поиска — выполнить поиск.
- **Esc** — закрыть диалог/выйти из табло.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Обновление данных вручную (F5) и автообновление
Категория: settings-help
Вариации запроса: обновить, f5, автообновление, данные не свежие
📷 Скриншоты: scr-set-01.png

**Ответ.** Экраны подтягивают данные при открытии; F5 — принудительное обновление (после действий коллег). Индикатор прохода и входы/выходы обновляются по SSE (пуши с сервера) — задержки до пары секунд норма. Если события турникета не появляются без F5 — проверьте сеть (SSE-подключение), см. errors.md «Сервер недоступен».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

**Пошагово.**

## Проверка связи с сервером
Категория: settings-help
Вариации запроса: проверить связь, ping сервера, тест подключения, связь с клубом
📷 Скриншоты: scr-set-01.png

**Пошагово.**
1. «Настройки → Подключения» → «Проверить связь».
   Ожидание: зелёный статус + версия API.
2. Нет статуса — смотрите ошибку: таймаут (сеть/IP), 401 (проблема авторизации не на этом этапе), 404 (неверный путь — должен заканчиваться на `/api/v1`).
3. Альтернатива: открыть `http://<IP-сервера>/api/v1/health/` в браузере — ожидание JSON `{"status":"ok"}`.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
