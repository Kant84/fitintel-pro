## «Токен истёк» — полный разбор
Категория: errors
Вариации запроса: токен истёк, token expired баннер, снова просит войти

**Причина.** Access-токен живёт 30 минут; обычно desktop сам обновляет его по refresh-токену.
**Пошагово.**
1. Подождите 5–10 секунд — клиент обновляет токен сам. Ожидание: баннер исчез.
2. Не исчез: «Файл → Выход» → войдите заново.
3. Постоянно повторяется: проверьте сеть до сервера, флажок «Запомнить меня»; IT — логи api на ошибки refresh (инвалидation сессий после смены пароля — норма).
📷 Скриншоты: scr-err-01-token-expired.png

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Expecting value: line 1 column 1 (char 0)» — разбор
Категория: errors
Вариации запроса: expecting value, json ошибка, не json ответ

**Причина.** Ответ сервера не JSON: просроченный токен (HTML-заглушка), 5xx-страница, прокси/файрвол отдал свою страницу.
**Пошагово.**
1. F5 / выйти-войти. Ожидание: ошибка не повторяется.
2. После обновления сервера — подождать 30 сек (прогрев) и повторить.
3. Стабильно на одном действии → IT: `docker compose logs --tail=100 api` в момент ошибки; текст traceback — в обращение.
📷 Скриншоты: scr-err-11-music-json.png

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Ошибка сохранения: api-клиент без put/post»
Категория: errors
Вариации запроса: api-клиент без put post, не сохраняется клиенту, ошибка сохранения настроек

2. 1.6.1 — обновите desktop (Setup v1.6.2 поверх).
3. После обновления повторите сохранение на «Уведомления → Клиенту».
📷 Скриншоты: scr-err-19-clientu-api.png

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## 422 при создании клиента: разбор валидации
Категория: errors
Вариации запроса: 422 клиент, не создаётся клиент, ошибка валидации

**Причина.** Сервер отклонил данные формы.
**Типовые причины и исправления.**
- Телефон не в формате +7XXXXXXXXXX (пробелы/дефисы) → только цифры после +7.
- Email без @ или с пробелами.
- Дата рождения в будущем / неверный формат (ДД.ММ.ГГГГ).
- Пустое ФИО.
Исправьте подсвеченное поле → «Сохранить». Ожидание: карточка создана.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## 409 при входе: «Клиент уже находится в клубе»
Категория: errors
Вариации запроса: 409 вход, уже в клубе, повторный вход

**Пошагово.**

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Касса вернула ошибку: 1» — АТОЛ
Категория: errors
Вариации запроса: касса вернула ошибку 1, атол ошибка 1, фн
📷 Скриншоты: scr-err-07-kassa-error-1.png

**Причина.** Ошибка от ККТ через ДТО 10: чаще всего ФН (переполнен/истёк), нет бумаги, или 24 часа без закрытия смены.
**Пошагово.**
1. На самой ККТ: состояние ФН, бумага.
2. Пробейте Z-отчёт на кассе (если просит закрыть смену), затем «🔓 Открыть смену» в FitIntel.
3. Тестовый чек 1 ₽.
4. Не помогло — журнал ККТ (кнопка «Журнал» в настройках кассы) + поддержка АТОЛ/ОФД.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Платёж уже подтверждён»
Категория: errors
Вариации запроса: платёж уже подтверждён, двойное подтверждение, повторно нажал
📷 Скриншоты: scr-err-08-already-confirmed.png

**Пошагово.**
1. F5 — обновите «Платежи». Ожидание: платёж уже «Завершён» — второй раз не нужен.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## WinError 10061 при активации лицензии
Категория: errors
Вариации запроса: winerror 10061, connection refused активация, лицензия не активируется
📷 Скриншоты: scr-err-14-license-winerror.png

**Причина.** Desktop не достучался до сервера: неверный адрес, порт закрыт, сервер лежит.
**Пошагово.**
1. Адрес в окне активации = адрес API (`http://<IP>/api/v1`).
2. `ping <IP>` с ПК.
3. Открыть `http://<IP>/api/v1/health/` в браузере ПК → ожидание JSON.
4. Нет JSON → IT: контейнеры (`docker compose ps`), файрвол (INSTALL_SERVER.md §9).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## BadJwtToken (webpush Apple)
Категория: errors
Вариации запроса: badjwttoken, webpush apple, пуши на айфоне не работают
📷 Скриншоты: scr-err-16-apple-badjwttoken.png

**Причина.** Apple принимает только корректный JWT (ES256); сбитое время сервера или неверные VAPID-ключи → BadJwtToken.
**Пошагово.**
1. Время на сервере: `date` — расхождение > пары минут ломает JWT. Исправить → перезапуск контейнеров.
2. «Уведомления → Web Push»: VAPID-ключи заполнены → «Сохранить».
3. Подписка — строго из настроек клуба (не сторонние тестовые страницы).
4. Тестовая отправка повторно.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## 400 при назначении роли (roles/assign)
Категория: errors
Вариации запроса: 400 roles assign, не сохраняется роль, ошибка назначения
📷 Скриншоты: scr-err-12-users-400.png

**Пошагово.**
1. Роль существует: «Настройки → Роли и права» → список.

4. Повторите: карточка сотрудника → «Роль и права» → галочки → «Сохранить».

## 535 «Application password is REQUIRED»
Категория: errors
Вариации запроса: 535, mail.ru пароль приложения, smtp 535

**Причина.** mail.ru/Яндекс принимают только пароль приложения, не обычный пароль почты.
**Пошагово.**
1. Войдите в почту отправителя в браузере.
2. Настройки → Безопасность → «Пароли приложений» → создать (название «FitIntel»).
3. Впишите 16 символов в «Уведомления → Email → SMTP пароль» → «Сохранить» → «Тест».
Ожидание: тестовое письмо ушло.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Не удалось отменить: …» запись позже 24 часов
Категория: errors
Вариации запроса: не удаляется запись, поздно отменить, cancel window

**Причина.** Онлайн-отмена доступна до `CANCEL_WINDOW` (24 ч на nfs); позже — только клуб.
**Пошагово.**
1. Сотрудник: «Расписание» → запись → «Отменить запись» → подтверждение (права сотрудника).
2. Клиенту: объяснить правило; при уважительной причине — отмена сотрудником, лимит посещения вернётся (если списывался заранее).
3. Правило в настройках: «Настройки → Расписание» (`CANCEL_WINDOW`).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
