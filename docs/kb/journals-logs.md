# desktop+server: журналы и логи (15 статей)

> Категория: desktop/server · Каждый журнал системы: что фиксирует, где смотреть, типичные ошибки.

## Журнал История — назначение и политика
Категория: desktop
Вариации запроса: журнал истории что хранит, что фиксируется, хранение

**Что фиксируется.** Создание/изменение/удаление по сущностям: Пользователи, Клиенты, Платежи, Абонементы, Визиты, Роли. Каждая запись: Когда | Кто | Действие | Сущность | ID | Детали (старые/новые значения).
**Политика.** Срок хранения — по настройке («Срок хранения…»: 30/180/365/730/0 дней); старше срока удаляются автоматически. Разбор споров — фильтры «Кто» + «Действие».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал Аудит доступа — события
Категория: desktop
Вариации запроса: аудит доступа события, кто смотрел документы, просмотр лицензии

**Что фиксируется.** Логины (успешные/неуспешные), просмотры чувствительных данных (документы сотрудников, лицензии), изменения прав и ролей, снятие кассы, анонимизация, имперсонация. Фильтры: сотрудник/тип/период. Экспорт — XLSX/CSV. Доступ: admin/бухгалтер (право аудита).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал уведомлений — статусы
Категория: desktop
Вариации запроса: статусы уведомлений, sent pending failed, журнал писем

**Статусы.** `sent` — ушло; `pending` — в очереди (до минуты норма); `failed` — ошибка в колонке «Ошибка» (535 SMTP, таймаут, нет привязки MAX). Смотреть: «Уведомления → 📋 Журнал → 🔄 Обновить журнал». По failed — текст ошибки показывает, что чинить.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал MAX: рассылки и чаты
Категория: desktop
Вариации запроса: журнал max рассылки, статус сообщения, отправить ожидающие

**Где.** «MAX сообщения → Журнал → Обновить»: Создано | Кому | Тип | Статус | Текст. «📤 Отправить ожидающие» → «Отправка: sent=X failed=Y». failed = нет привязки user_id или бот не настроен (статья notifications.md «Бот MAX не отвечает»).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал СКУД: отказы и проходы
Категория: desktop
Вариации запроса: журнал турникета, отказы где, кто получил отказ

**Где.** «Входы/Выходы» — счётчик «Отказов» (клик фильтрует таблицу); расширенный журнал — в сервисе ITCService/ent_bridge (`journalctl -u ent_bridge`). По UID отказа — карточка клиента и причина (нет абонемента/лимит/долг/блок).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Логи desktop: расположение и состав
Категория: desktop
Вариации запроса: логи программы, appdata logs, где ошибки desktop

**Расположение.** Windows: `%APPDATA%\FitIntel\logs` (файлы по дням). Состав: INFO (действия, запросы), ERROR (исключения с traceback). Перед обращением — воспроизведите ошибку и приложите последний файл (или отправьте через «Помощь → Поддержка разработчика (MAX)» — логи прикрепятся сами).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Логи сервера: app/error/access
Категория: server
Вариации запроса: логи сервера где, app.log error.log, журнал api

**Где.** `/opt/fitintel-pro/logs/`: `app.log` (инфо), `error.log` (ошибки), `access.log` (запросы nginx). Docker: `docker compose logs --tail=100 api`, `... db`. systemd: `journalctl -u itcservice`, `journalctl -u ent_bridge`. Ищите по времени сбоя (фиксируйте время с ПК пользователя).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал вендинга
Категория: vending
Вариации запроса: журнал автомата, статусы вендинга, продажи автомата

**Статусы (по коду).** PENDING — код выдан; PAID — оплачен (резерв на кошельке); CONFIRMED — автомат подтвердил выдачу; DECLINED — отказ; REFUNDED — возврат на кошелёк (невыдача/таймаут). Журнал: «Вендинг → Журнал» с фильтрами по автомату/статусу/периоду.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал платежей и webhook ЮKassa
Категория: payments
Вариации запроса: журнал webhook, события юкассы, payment_id

**Где смотреть.** В FitIntel — «Платежи» (статусы, `id` платежа). В кабинете ЮKassa → «Интеграция → Уведомления»: уходят ли webhook'и и коды ответов (200 = принят). Расхождение = webhook не дошёл/не обработан (payments.md «Оплата прошла — Ожидает»). Защита — заголовок `X-Payment-Signature` (HMAC).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Логи импорта (A&A, CSV)
Категория: desktop

## Ротация логов на сервере
Категория: server
Вариации запроса: ротация логов, журнал растёт, очистка логов

**Что делать.** systemd: `journalctl --vacuum-size=200M`. Docker: логи контейнеров — по настройкам compose (max-size/max-file); ручная чистка: `docker system prune` (не трогает запущенные). Регулярно проверяйте `df -h` — логи и бэкапы частые едоки диска.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал бэкапов
Категория: server
Вариации запроса: бэкапы журнал, когда последний бэкап, проверка бэкапов

**Автоматика.** Ежедневно 03:00 (backup_postgres.py + install_cron.sh), ротация — настраивается. Проверка: каталог бэкапов (`/opt/fitintel-pro/backups` или путь из скрипта) — свежий файл за сегодня; размер адекватный. Раз в месяц — тестовое восстановление на отдельный ПК/VM.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
