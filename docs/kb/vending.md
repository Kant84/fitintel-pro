# vending — оплата в автоматах

> Категория: vending · Проверено для: 1.6.2 · Для кого: администратор, интегратор автоматов.

## Как клиент платит в автомате (код с экрана)
Ключевые слова: вендинг, автомат, код оплаты, оплата из приложения
**Ответ.** 1) Клиент выбирает товар на экране автомата. 2) Автомат показывает 6-значный код (и QR с ним), код живёт 10 минут. 3) Клиент в мини-приложении MAX: «Оплата на автомате» → вводит код → списание с баланса кошелька. 4) Автомат опрашивает статус и выдаёт товар при PAID. При сбое выдачи — автоматический возврат на баланс (VENDING.md, ИНСТРУКЦИЯ FAQ).
📷 [SCR-vend-01: экран автомата с 6-значным кодом]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Оплата браслетом (приложил — списалось)
Ключевые слова: rfid вендинг, браслет автомат, купить браслетом
**Ответ.** Автомат с RFID-ридером: клиент прикладывает браслет → `POST /api/v1/vending/purchase` с UID → ответ `allow:true` + списание + `balance_after`. Недостаточно средств — `allow:false` с доступным остатком в `reason` (VENDING.md «Канал 1»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как зарегистрировать автомат в системе
Ключевые слова: зарегистрировать автомат, device token, vending_devices
**Ответ.** SQL на сервере клуба: `INSERT INTO vending_devices (id, name, api_token, location) VALUES (gen_random_uuid(), 'Автомат 1', '<случайный токен 32+ символа>', 'Холл');`. Токен прописывается в прошивку автомата (заголовок `X-Device-Token`). Для MVP: `openssl rand -hex 32` (VENDING.md «Авторизация»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Журнал продаж автомата
Ключевые слова: журнал вендинга, продажи автомата, sales
**Ответ.** `GET /api/v1/vending/sales?limit=50` — позиции: клиент, товар, цена, статус (PENDING → PAID → CONFIRMED/REFUNDED, DECLINED — отказ). Статусы продажи и логика возвратов — VENDING.md «Журнал».
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Подтверждение выдачи обязательно
Ключевые слова: confirm, dispensed, выдача товара, failed
**Ответ.** После физической выдачи автомат обязан вызвать `POST /api/v1/vending/confirm` со статусом `dispensed` (выдан) или `failed` (сбой → автовозврат на баланс). Без confirm продажа останется в PAID (VENDING.md «Подтверждение выдачи»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Контракт для прошивки контроллера автомата (MDB)
Ключевые слова: mdb, контроллер автомата, прошивка, адаптер
**Ответ.** Готовый контракт API для MDB-адаптера: маппинг сессии VEND на /purchase (RFID) или пару /session + опрос (по коду), ожидание allow/PAID до выдачи, обязательный /confirm после. Документ для разработчика прошивки — VENDING.md «Примечания для MDB-адаптера». Эмулятор для стенда: `tools/mock_vending.py`.
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».
