## Как впустить клиента вручную (без турникета)
Категория: visits-access
Вариации запроса: впустить вручную, ручной вход, открыть турникет без карты, пропустить клиента
📷 Скриншоты: scr-visits-01.png

**Пошагово.**
1. Вкладка «Входы/Выходы» → кнопка «🟢 Впустить» (вверху панели счётчиков).
2. В открывшемся диалоге найдите клиента: начните вводить ФИО или телефон → выберите из списка.
   Ожидание: карточка клиента с подсветкой: действующий абонемент (зелёный) / нет (красный).
3. При отсутствии абонемента система предложит оформить — откройте карточку («Продать услугу») или откажитесь.
4. «✓ Впустить». Ожидание: новая строка в таблице визитов, счётчик «Сейчас в зале» +1, на индикаторе прохода — ФИО + зелёный кружок.

**Типичные ошибки.** Искать клиента по номеру абонемента вручную — используйте поиск по ФИО/телефону; впуск без абонемента без фиксации причины — журнал аудита всё фиксирует.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Как выпустить клиента вручную
Категория: visits-access
Вариации запроса: выпустить, завершить визит, закрыть визит вручную, клиент ушёл без отметки

**Пошагово.**

   Ожидание: визит закрыт со временем выхода, «Сейчас в зале» −1.
3. Если клиент ушёл раньше — время выхода фактическое, тарификация посуточная/почасовая учтётся по правилам тарифа.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Турникет не пускает: чек-лист за 2 минуты
Категория: visits-access
Вариации запроса: турникет не пускает, не работает турникет, карта не срабатывает, отказ на входе, контроллер молчит
📷 Скриншоты: scr-visits-01.png

**Пошагово (по порядку, не пропуская).**
1. **Карта вообще не реагирует** (нет звука/подсветки считывателя): питание контроллера/считывателя, кабель. IT.
2. **Реагирует, но «Отказ»**: проверьте клиента — действующий абонемент? («Клиенты» → карточка → «Пакеты/Услуги»). Нет — оформите.
3. **Абонемент есть, «Отказ»**: проверьте лимит входов/долг/чёрный список в карточке («Блоки»).
4. **«Отказ» у ВСЕХ клиентов**: связь контроллера с сервером. IT: `curl -u itc:<пароль> -X POST http://127.0.0.1/api/v1/skud/checkaccess -d '{"uid":"..."}'` → 422 норма, 401 — рассинхрон пароля (статья «401 на /skud/*» в errors.md).
5. **Открывается ли турникет вручную?** Впуск из desktop («Впустить») проходит — проблема в контроллере/прошивке; не проходит — в связи контроллер→сервер.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)». + номер контроллера/считывателя и время отказа.

## Привязка браслета к клиенту (через ACR1252)
Категория: visits-access
Вариации запроса: привязать браслет, записать карту, acr1252, uid браслета, как привязать rfid
📷 Скриншоты: scr-visits-01.png

**Пошагово.**
1. Подключите USB-считыватель ACR1252 к ПК ресепшена (драйвер ставится автоматически).
2. Вкладка «Браслеты/Карты» → кнопка «➕ Привязать».
3. Поднесите браслет к считывателю. Ожидание: поле UID заполнилось само (16 hex-символов).
4. Найдите клиента (ФИО/телефон) → выберите тариф доступа → «Сохранить».
   Ожидание: браслет в списке с привязкой к клиенту; тест на турникете — пускает.

**Важно.** НЕ используйте USB-хабы между ACR1252 и ПК — считыватель пропадает (известная проблема). Втыкайте напрямую в порт ПК.
**Типичные ошибки.** UID прочитался, но клиент не найден — создайте карточку клиента заранее; браслет MIFARE с пустым сектором — запись происходит на этапе привязки автоматически.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Браслет утерян: перевыпуск
Категория: visits-access
Вариации запроса: потерял браслет, перевыпуск карты, заблокировать утерянный, новый браслет
📷 Скриншоты: scr-visits-01.png

**Пошагово.**
1. «Браслеты/Карты» → найдите старый браслет (по клиенту) → «✖ Блокировать».
   Ожидание: статус «Заблокирован» — турникет его больше не примет.
2. Выдайте новый браслет: «➕ Привязать» → поднесите новый → тот же клиент и тариф → «Сохранить».
3. Старый при возможности найдите и сотрите/передайте в IT.
4. История привязок клиента хранится в карточке («ПРОЧЕЕ → История»).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Считыватель не найден» при привязке
Категория: visits-access
Вариации запроса: считыватель не найден, acr1252 не видит, не читает браслет, usb считыватель
📷 Скриншоты: scr-visits-01.png

**Пошагово.**
1. Вытащите ACR1252 из USB и вставьте напрямую в порт ПК (без хабов, без удлинителей).
2. Дождитесь звука подключения Windows (~3 сек) → повторите «Привязать».
3. Проверьте в «Диспетчере устройств» → «Устройства чтения смарт-карт»: ACR1252 без жёлтых значков.
4. Перезапустите desktop («Файл → Выход», запуск заново) — дескриптор порта мог зависнуть.
   Ожидание: при поднесении браслета UID читается.
5. Не помогло — другой порт USB / другой ПК; считыватель редко, но умирает.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## QR-код на вход: статический и динамический
Категория: visits-access
Вариации запроса: qr код вход, статический qr, динамический qr, как клиенту показать qr
📷 Скриншоты: scr-visits-01.png

**Ответ.**
- **Статический QR** — постоянный код клиента; включается в «Браслеты/Карты» → «QR клиента»; живёт, пока не отключён администратором.
- **Динамический QR** — из мини-приложения MAX: «Мой QR»; одноразовый, живёт `QR_TTL_MINUTES` (параметр клуба, по умолчанию 2 минуты); после показа/прохода — перевыпуск.

**Пошагово (сотруднику).** Клиент без браслета: попросите открыть мини-приложение → «Мой QR» → поднесите экран к сканеру турникета. Ожидание: турникет открылся, визит создан.

**Типичные ошибки.** Динамический QR «протух» — перевыпустить; «Подпись недействительна» у всех — рассинхрон `QR_SECRET_KEY` (статья в errors.md).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Face ID на турникете: как работает
Категория: visits-access
Вариации запроса: face id турникет, лицо вместо карты, распознавание на входе, биометрия турникет
📷 Скриншоты: scr-visits-01.png

**Ответ.** Клиент с зарегистрированным лицом и согласием 152-ФЗ проходит турникет по лицу: камера → распознавание → проверка абонемента → проход. Порог схожести настраивается («Face ID → Настройки», стандарт 0.6). В журнале прохода отметка «Face».

**Пошагово (если не пускает по лицу).** 1) свет/очки/капюшон — попросите снять; 2) согласие активно (карточка → «Согласия»); 3) шаблон старый → перерегистрация; 4) порог 0.6–0.7 под обстановку клуба. Подробно — статья «ОТКАЗ: auth» в errors.md и faceid.md.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Считыватели турникета: замена/проверка

📷 Скриншоты: scr-visits-01.png

**Ответ.** Турникет использует считыватели EM-Marine/Wiegand, подключённые к контроллеру (ITC/ЭРА). Сотруднику клуба: проверка — поднести заведомо рабочую карту; нет реакции — питание/кабель (IT). ## Режим «Скан = вход» в меню «Вид»

Вариации запроса: скан равно вход, сканирование на ресепшене, режим входа по скану, вид скан

**Ответ.** Меню «Вид → Скан = вход (вкл)»: когда включён, поднесение браслета к USB-считывателю ACR1252 на ресепшене НЕ открывает карточку, а сразу регистрирует вход клиента (как турникет). Удобно на стойке без турникета. Выключите — скан снова просто находит карточку клиента.

## Расхождение «Сейчас в зале» и реальности
Категория: visits-access
Вариации запроса: в зале больше чем людей, сейчас в зале неправильно, висят визиты, не закрываются визиты
📷 Скриншоты: scr-visits-01.png

**Пошагово.**
1. «Входы/Выходы» → фильтр «В клубе» — список висящих визитов.
2. Каждый физически ушедший → «🔴 Выпустить» с фактическим временем.
3. Причины накопления: турникет не фиксирует выход (карта не приложена), ручные впуски без выпуска, сбой контроллера. После зачистки сверьте вечером.
4. Повторяется регулярно → IT: регламент вечерней сверки + проверка событий выхода с контроллера (в журнале ITCService).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
