# errors — коды ошибок и общие сбои

> Категория: errors · Проверено для: 1.6.2 · Для кого: все роли + IT клуба.

## «Сервер не подключён» / «Сервер недоступен» внизу окна
Ключевые слова: сервер недоступен, сервер не подключён, нет связи, connection refused
**Ответ.** 1) Проверьте сеть: `ping <IP-сервера>` с этого ПК. 2) Проверьте адрес:
«Настройки → Сервер API» должен быть `http://<IP>/api/v1`. 3) Проверьте сервер:
`curl http://<IP>/api/v1/health/` — должен вернуть JSON с `"status":"ok"`. 4) Если curl не отвечает — сервер или контейнеры лежат: см. INSTALL_SERVER.md §9 (IT-специалисту клуба).
📷 [SCR-errors-01: статус-бар desktop «Сервер недоступен»]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами.

## «Неверный логин или пароль» (осталось попыток: N)
Ключевые слова: неверный пароль, не входит, 401, login failed
**Ответ.** Проверьте раскладку клавиатуры и Caps Lock; пароль чувствителен к регистру. Логин — email. Если пароль выдан временным — после входа откроется обязательная смена (ИНСТРУКЦИЯ §4.3).
**Если не помогло:** администратор клуба сбрасывает пароль: «Пользователи → Сбросить пароль».

## «Аккаунт заблокирован. Попробуйте через 5 минут»
Ключевые слова: блокировка, 423, заблокирован аккаунт
**Ответ.** После 5 неверных попыток входа учётка блокируется на 5 минут — это защита. Подождите; пароль не подбирайте дальше. Если пароль точно верный, а блокировка повторяется — сбросьте пароль администратору.
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## «Нет прав: payments.create» / ошибка 403
Ключевые слова: 403, нет прав, forbidden
**Ответ.** У вашей роли нет нужного права — сервер отклонил операцию (это не сбой).
Администратору: «Настройки → Роли и права» → выбрать вашу роль → отметить право галочкой → «💾 Сохранить». Права применяются мгновенно, перезаход не нужен (RBAC.md §5.2).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Нет нужной вкладки в меню слева
Ключевые слова: нет вкладки, нет экрана, пропал раздел, пустое меню
**Ответ.** Экран не отмечен для вашей роли (строгая модель: не отмечено = не видно). Администратору: «Настройки → Экраны ролей» → выбрать роль → отметить экран → «Сохранить». Пользователь увидит после перелогина (ИНСТРУКЦИЯ §6.2, §22.3).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Ошибка 429 (слишком много запросов)
Ключевые слова: 429, rate limit, слишком много запросов
**Ответ.** Сработал лимит запросов (nginx: API 10 зап/с, вход 5/мин, боты 30/с). Подождите 1–2 минуты и повторите. Если лимит появляется постоянно при обычной работе — обратитесь к IT клуба (настройка LAN-whitelist в nginx.conf, INSTALL_SERVER.md §16).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## 502 Bad Gateway сразу после обновления или перезапуска сервера
Ключевые слова: 502, bad gateway, сервер не отвечает после обновления
**Ответ.** Скорее всего сервер ещё прогревается: проверка БД ~25 секунд, первые запросы тяжёлые. Подождите 20–30 секунд и повторите. НЕ перезапускайте по кругу. Если через 2 минуты всё ещё 502 — контейнер api падает: логи `docker compose logs --tail=100 api` (IT клуба, INSTALL_SERVER.md §9.2).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)» + логи api.

## «Смена закрыта» при пробитии чека (ошибка 400)
Ключевые слова: смена закрыта, чек не пробивается, 400
**Ответ.** Фискальный чек пробивается только в открытой кассовой смене. «Бухгалтерия → Платежи → 🔓 Открыть смену», затем повторите «✓ Подтвердить» на платеже. Платёж со статусом «Ожидает» никуда не делся (ИНСТРУКЦИЯ §15.4, FISCAL_GUIDE).
📷 [SCR-errors-02: красное предупреждение «Смена закрыта» над платежами]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## 502 «Касса недоступна» / «Касса вернула ошибку: N»
Ключевые слова: касса недоступна, атол, ккт, 502 касса
**Ответ.** Нет связи с ККТ. 1) «Платежи → ⚙ Настройки кассы»: адрес должен быть `http://<IP-кассы>:16732` (АТОЛ ДТО 10). 2) Проверьте сеть до кассы: `ping <IP-кассы>` (IT клуба). 3) Если стоит тестовый mock — он должен быть запущен. Тестовый чек после настройки — 1 ₽ (FISCAL_GUIDE).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)» + журнал ККТ.

## Платёж есть, а денег в кассе нет / платёж «Ожидает»
Ключевые слова: ожидает, платёж не подтверждён, баланс не тот
**Ответ.** Деньги попадают в кассу только после «✓ Подтвердить» (тогда пробивается чек). Выделите платёж «Ожидает» → «✓ Подтвердить». Помните: нал и безнал считаются РАЗДЕЛЬНО — сверяйте нужную строку баланса (ИНСТРУКЦИЯ §15.2).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Письмо клиенту не приходит / висит «PENDING»
Ключевые слова: письмо не приходит, pending, email очередь, спам
**Ответ.** 1) Проверьте папку «Спам». 2) «Уведомления → Email»: SMTP заполнен и сохранён. 3) Для mail.ru/Яндекса нужен ПАРОЛЬ ПРИЛОЖЕНИЯ, а не пароль ящика (иначе «535 Application password is REQUIRED»). 4) Журнал «Уведомления → Журнал» покажет статус и ошибку. Отправка всегда через очередь — письмо может уйти с паузой до минуты (EMAIL_SETUP_GUIDE).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Бот MAX не отвечает клиентам
Ключевые слова: бот молчит, max не отвечает, webhook
**Ответ.** 1) «Клиенту → Каналы»: статус webhook «установлен» (кнопка «Установить webhook»). 2) Токен бота верный. 3) Бот не может написать первым — клиент должен запустить его самым первым сообщением. 4) Webhook требует публичный HTTPS-домен, а не IP локалки (docs_MAX_bot_shop.md §2, §10).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## «Клиент уже находится в клубе» (ошибка 409)
Ключевые слова: уже в клубе, 409, повторный вход
**Ответ.** У клиента уже есть незакрытый визит. Не создавайте второй вход — найдите активный визит в «Входы/Выходы» и закройте его («🔴 Выпустить» или «✓ Завершить»), затем впускайте заново (ИНСТРУКЦИЯ §30).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## «Откройте шкафчик №N перед выходом!»
Ключевые слова: шкафчик закрыт, не выпускает, выход заблокирован
**Ответ.** Турникет не выпускает клиента с закрытым бесплатным шкафчиком. Откройте шкафчик №N (администратор: «Браслеты/Карты → Аренда шкафчика» или через устройства), затем повторите выпуск (ИНСТРУКЦИЯ §11.4, §30.5).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## QR не проходит / «Подпись недействительна»
Ключевые слова: qr не работает, подпись недействительна, код не читается
**Ответ.** 1) Динамический QR живёт 5 минут и одноразовый — перевыпустите (мини-приложение, «Мой QR»). 2) Статический QR проверьте в «Браслеты/Карты». 3) Если подпись недействительна — несовпадение ключа на сервере (IT клуба: `QR_SECRET_KEY` в `.env`, TROUBLESHOOTING §«Интеграции»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## «Вечный круг» — снова просит сменить пароль
Ключевые слова: вечный круг, постоянно смена пароля, is_first_login
**Ответ.** Это не баг: при первом входе флаг обязательной смены сбрасывается только после УСПЕШНОЙ смены пароля. Введите старый (временный) пароль в поле «Старый пароль» и новый дважды — окно закроется (ИНСТРУКЦИЯ §4.3, TROUBLESHOOTING §Desktop).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## 401 на запросах турникета (/skud/*) — для IT клуба
Ключевые слова: skud 401, турникет не пускает всех, itc 401
**Ответ.** Контроллер шлёт старый пароль. Пароль ITC — в `deploy/.env` (`ITC_BASIC_PASSWORD`); он должен совпадать в трёх точках: `.env` сервера (после правки `docker compose up -d --force-recreate api`), реестр ITCService (BasicAuthPass), `/etc/fitintel/bridge.env` (itc_password) → `systemctl restart ent_bridge`. Проверка: старый пароль → 401, новый → 422 (ITCService_SETUP.md §«Безопасность»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».
