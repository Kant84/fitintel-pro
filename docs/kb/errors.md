## «Сервер не подключён» / «Сервер недоступен» внизу окна
Категория: errors
Вариации запроса: сервер недоступен, нет связи с сервером, не подключается, connection refused, программа не грузится, висит статус сервер

**Причина.** Desktop не достучался до API клуба: сеть, неверный адрес сервера или упали контейнеры.

**Пошагово.**
1. Проверьте интернет на этом ПК (любой сайт в браузере). Ожидание: открывается. Нет — проблема сети ПК.
2. «Настройки → Подключения» → адрес сервера вида `http://<IP-сервера>/api/v1`. Нажмите «Проверить связь». Ожидание: зелёный статус.
3. IT клуба с сервера: `curl http://127.0.0.1/api/v1/health/` → ожидание JSON `"status":"ok"`. Нет ответа → `docker compose up -d` (INSTALL_SERVER.md §9).
4. С ПК: `ping <IP-сервера>` → ожидание ответов. Нет → файрвол/сеть между ПК и сервером.

**Типичные ошибки.** Адрес без `/api/v1`; серверу сменили IP, а в профиле подключения старый.
📷 [SCR-errors-01: статус-бар «Сервер недоступен»]
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

## «Неверный логин или пароль» (осталось попыток: N)
Категория: errors
Вариации запроса: не входит, пароль не подходит, неверный пароль, 401 при входе, login failed, не принимает пароль

**Причина.** Опечатка, раскладка/Caps Lock, либо пароль действительно другой.

**Пошагово.**
1. Проверьте раскладку (RU/EN) и Caps Lock — пароль чувствителен к регистру.
2. Логин — email целиком (`manager@club.ru`), не имя и не телефон.
3. Введите пароль заново. Ожидание: вход выполнен; счётчик попыток не уменьшается.
4. Пароль выдан временным? После входа откроется смена пароля: «Старый пароль» = временный, новый — дважды.

**Типичные ошибки.** Email без домена; пароль скопирован с пробелом; окно смены временного пароля закрыли крестиком — пароль остался временным.
**Если не помогло:** администратору: «Пользователи» → двойной клик по сотруднику → «Сбросить пароль».

## «Аккаунт заблокирован. Попробуйте через 5 минут»
Категория: errors
Вариации запроса: заблокирован аккаунт, 423, блокировка после попыток, пишет подождите 5 минут

**Причина.** Защита: 5 неверных паролей подряд = пауза 5 минут.

**Пошагово.**
1. Ничего не вводите 5 минут (таймер идёт от последней попытки).
2. За паузу уточните пароль у администратора.
3. Войдите ОДИН раз, аккуратно. Ожидание: вход выполнен.

**Типичные ошибки.** Жать «Войти» во время блокировки — таймер продлевается.
**Если не помогло:** «Сбросить пароль» администратором или Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

## «Нет прав: <действие>» / ошибка 403
Категория: errors
Вариации запроса: 403, нет прав, forbidden, запрещено, не даёт сделать, недостаточно прав

**Причина.** У роли нет конкретного права — это RBAC, не сбой.

**Пошагово.**
1. Запомните право из ошибки (например `payments.create`).
2. Администратору: «Настройки → Роли и права» → ваша роль → найти ветку `payments` → галочка `create` → «💾 Сохранить». Ожидание: зелёная плашка «Сохранено».
3. Повторите действие сразу, без перелогина.

**Типичные ошибки.** Право отметили другой роли; сохранение прервали.
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

3. Выйти и войти заново. Ожидание: вкладка в sidebar.

**Типичные ошибки.** «Экраны ролей» сам не отмечен вашей роли — инструмент доступен только администратору.

## Ошибка 429 (слишком много запросов)
Категория: errors
Вариации запроса: 429, rate limit, слишком много запросов, просит подождать

**Причина.** Лимитер nginx: API 10 зап/с, вход 5/мин, боты 30/с. Обычно — скрипт/пинговалка или реально тяжёлая панель.

**Пошагово.**
1. Подождите 1–2 минуты, повторите действие. Ожидание: проходит.
2. Если 429 постоянно при обычной работе — попросите IT клуба добавить LAN-адреса клуба в whitelist лимитера (INSTALL_SERVER.md §16).
3. Проверьте, не крутится ли на сервере сторонний скрипт, долбящий API.

**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

## 502 Bad Gateway сразу после обновления или перезапуска сервера
Категория: errors
Вариации запроса: 502, bad gateway, сервер не отвечает после обновления, после ребута не работает

**Причина.** API прогревается: проверка БД ~25 сек, первые запросы тяжёлые.

**Пошагово.**
1. Подождите 20–30 секунд, обновите окно (F5). Ожидание: работает.
2. НЕ перезапускайте контейнеры по кругу — это только продлевает прогрев.
3. Через 2 минуты всё ещё 502 → IT клуба: `docker compose ps` (api должен быть Up) и `docker compose logs --tail=100 api` (INSTALL_SERVER.md §9.2).

**Типичные ошибки.** Путать «контейнер стартовал» с «приложение прогрелось» — healthy бывает не сразу.
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО. + логи api за последние 2 минуты.

## «Смена закрыта» при пробитии чека (ошибка 400)
Категория: errors
Вариации запроса: смена закрыта, чек не пробивается, ошибка 400 при оплате, не подтверждается платёж, касса пишет смена не открыта

**Причина.** Фискальный чек пробивается только в открытой кассовой смене.

**Пошагово.**
1. Вкладка «Бухгалтерия» → подвкладка «Платежи».
2. Нажмите «🔓 Открыть смену». Ожидание: баннер «Смена открыта, кассир …» (или «Смена уже открыта» — тоже норма).
3. Вернитесь к платежу, выделите его → «✓ Подтвердить». Ожидание: чек пробит, статус «Подтверждён».

**Типичные ошибки.** Платёж «Ожидает» никуда не делся при закрытой смене — он дождётся подтверждения.

## 502 «Касса недоступна» / «Касса вернула ошибку: N»
Категория: errors
Вариации запроса: касса недоступна, атол, ккт, 502 касса, нет связи с кассой, касса вернула ошибку 1

**Причина.** Нет связи с ККТ (АТОЛ ДТО 10) или сама ККТ в ошибке.

**Пошагово.**
1. «Платежи → ⚙ Настройки кассы»: адрес должен быть `http://<IP-кассы>:16732` (для mock — `:18004`).
2. С сервера/ПК кассы: `ping <IP-кассы>` и открыть в браузере `http://<IP-кассы>:16732` — ожидание: отвечает веб-интерфейс ДТО.
3. Если отвечает, но «ошибка: 1» — на самой ККТ: проверьте ФН (не переполнен/не истёк), бумагу, закройте смену на кассе при 24-часовом предупреждении.
4. После правок — тестовый чек на 1 ₽.

**Типичные ошибки.** АТОЛ живёт на ПК кассира, а не на сервере — ping делать с ТОГО ПК; ДТО обновилось и сменило порт.
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО. + журнал ККТ (кнопка «Журнал» в настройках кассы).

## Платёж есть, а денег в кассе нет / платёж «Ожидает»
Категория: errors
Вариации запроса: ожидает, платёж не подтверждён, баланс не тот, деньги не пришли в кассу

**Причина.** В кассу попадает только ПОДТВЕРЖДЁННЫЙ платёж (тогда же пробивается чек).

**Пошагово.**
1. «Платежи» → найдите платёж со статусом «Ожидает».
2. Проверьте реальность оплаты у клиента (чек банка/карта). Не подтверждайте «вслепую».
3. Выделите платёж → «✓ Подтвердить» → при необходимости поправьте способ оплаты (нал/безнал). Ожидание: статус «Подтверждён», чек, проводка.
4. Сверяйте баланс ПО ВИДАМ: наличные и безнал — разные строки.

**Типичные ошибки.** Сверять наличные по строке «безнал»; подтверждать платёж до получения денег.
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

## Письмо клиенту не приходит / висит «PENDING»
Категория: errors
Вариации запроса: письмо не приходит, pending, email очередь, письмо в спаме, не уходит почта

**Пошагово.**
1. Попросите клиента проверить «Спам»/«Промоакции».
2. «Уведомления → Email»: SMTP сервер/порт/логин заполнены, «Сохранить» нажато. Ожидание: зелёный статус.
3. Ящик mail.ru/Яндекс? Нужен ПАРОЛЬ ПРИЛОЖЕНИЯ (создаётся в настройках почты), а не обычный пароль — иначе «535 Application password is REQUIRED».
4. «Уведомления → Журнал»: найдите письмо — там точная ошибка SMTP. Ожидание: либо «sent», либо текст ошибки.
5. Помните: отправка через очередь — пауза до минуты норма.

**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

## Бот MAX не отвечает клиентам
Категория: errors
Вариации запроса: бот молчит, max не отвечает, webhook не работает, клиенты пишут боту тишина

**Пошагово.**
1. «Уведомления → Клиенту → Каналы»: статус webhook должен быть «установлен»; если нет — «Установить webhook». Ожидание: статус «MAX: подключён».

3. Бот НЕ может написать первым — клиент должен запустить бота (кнопка «Запустить»/«Начать» в MAX) минимум один раз.
4. Webhook требует публичный HTTPS-домен (не IP локалки) — проверьте, что домен клуба доступен извне.

**Типичные ошибки.** Клиент не нажимал «Начать»; домен недоступен из интернета.

Категория: errors

**Причина.** Прошлый выход не зафиксировался (турникет не считал карту, ручной впуск без выхода).
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.

## 401 на запросах турникета (/skud/*) — для IT клуба
Категория: errors
Вариации запроса: skud 401, турникет не пускает всех, itc 401, контроллер не авторизуется

**Причина.** Контроллер/сервис шлёт пароль, который сервер уже не принимает (после ротации или рассинхрона).

**Пошагово.**
1. Пароль живёт в `deploy/.env` (`ITC_BASIC_USER`/`ITC_BASIC_PASSWORD`). После правки: `docker compose up -d --force-recreate api`.
2. Он должен совпадать в трёх точках: `deploy/.env` сервера; реестр ITCService на ПК с ITCService (`BasicAuthPass`); `/etc/fitintel/bridge.env` (`itc_password`) → `systemctl restart ent_bridge`.
3. Проверка с сервера: старый пароль → `401`, новый → `422` на `POST /api/v1/skud/checkaccess`.
   Ожидание: NEW=422 (авторизация прошла).

**Типичные ошибки.** Обновили только .env — контроллер по-прежнему со старым; 502 сразу после up — прогрев 20–30 сек.
**Если не помогло:** Ескалация: desktop «Помощь → Поддержка разработчика (MAX)» — обращение уйдёт с логами и версией ПО.
