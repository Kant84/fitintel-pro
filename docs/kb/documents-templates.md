# desktop: шаблоны и документы (10 статей)

> Категория: desktop/clients-subs · Шаблоны, переменные, генерация, подпись, PDF, кадровые документы.

## Типы документов: что выбрать
Категория: desktop
Вариации запроса: типы документов contract act agreement, какой тип выбрать

**Типы шаблонов.** contract (договор), act (акт), agreement (соглашение), scan (скан), receipt (квитанция), other (прочее). Выбор — по смыслу документа: договор оказания услуг → contract; акт выполненных работ → act; допсоглашение → agreement. Тип влияет на подстановки и группировку в журнале «Документы».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Подстановки {client} {tariff} {days}: полный список
Категория: desktop
Вариации запроса: переменные шаблона, подстановки в документе, список переменных

**Переменные.** Основные: {client} (ФИО), {tariff} (название тарифа), {days} (срок действия). Расширенные: {{client_name}}, {{date}}, {{phone}}, {{email}}, {{club}}, {{price}} — если не подставилось, значит переменная не поддерживается этим типом документа: проверьте на тестовой генерации перед массовой печатью.
**Тест.** Сгенерируйте документ тестовому клиенту → прочтите результат → поправьте шаблон.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Шаблон договора на абонемент: сборка
Категория: clients-subs
Вариации запроса: шаблон договора абонемента, договор продажи собрать, типовой договор

**Пошагово.**
1. «Документы → 📝 Создать шаблон» → Название «Договор абонемента» → Тип contract.
2. Текст: преамбула (клуб/клиент через {client}), предмет (тариф {tariff}, срок {days}), права/обязанности, порядок заморозки/возврата, реквизиты, подписи.
3. «💾 Сохранить шаблон».
4. Тест: «Сгенерировать» → тестовый клиент → проверить подстановки.
5. Юридическое согласование текста — на стороне клуба (шаблон — заготовка, не юрзаключение).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Генерация пачки документов перед продажей
Категория: clients-subs
Вариации запроса: документы клиенту при продаже, распечатать договор продажи

**Процесс.**
1. Продажа абонемента → оплата → «Документы → Сгенерировать» → шаблон договора → клиент.
2. Печать («🖨») → подпись клиента и клуба.
3. Скан подписанного — в «Документы» клиента (раздел «Документы» карточки).
4. Один экземпляр — клиенту, один — клубу (регламент хранения).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Подпись документа в системе: статус и смысл
Категория: desktop
Вариации запроса: подписать документ, статус подписан, электронная подпись

**Смысл.** Кнопка «✍ Подписать» фиксирует факт подписания (простая подпись в диалоге) → статус «(подписан)» зелёным. Это учётный статус, не УКЭП/электронная подпись. Для юридической силы — бумажный подписанный оригинал/скан в карточке. Аудит фиксирует кто и когда подписал.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## PDF из документа: качество и хранение
Категория: desktop
Вариации запроса: сохранить документ в pdf, качество pdf, архив документов

**Пошагово.** Выделить документ → «📥 PDF» → «Сохранить в PDF» → выбрать папку → «<Название>.pdf», «Сохранено: путь».
**Хранение.**
- PDF + скан подписанного — в карточке клиента/сотрудника («Документы»).
- Месячный архив PDF отчётов — бухгалтеру.
- Общий диск клуба — с доступом по ролям (152-ФЗ).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Шаблоны для сотрудников (трудовой договор)
Категория: users-rbac
Вариации запроса: шаблон трудового договора, договор сотрудника, кадровые документы

**Пошагово.**
1. «Документы → 📝 Создать шаблон» → «Трудовой договор» → тип contract; переменные: {client} → для сотрудника используйте общий шаблон с ручным заполнением полей (или генерируйте и правьте текст до печати).
2. Печать → подписи → скан в карточку сотрудника («Документы», AES-256-GCM).
3. Увольнение — документы сохраняются (кадровый архив).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Документ не генерируется: причины
Категория: desktop
Вариации запроса: не создаётся документ, ошибка генерации, шаблон не работает

**Типовые причины.**
1. Шаблон не выбран/не сохранён — проверьте список «📄 Шаблоны».
2. Переменная с опечаткой ({clent} вместо {client}) — текст останется как есть, проверьте шаблон.
3. Клиент не выбран — «Выберите клиента».
4. 500 — сервер: логи api; текст ошибки — в обращение.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Акт инвентаризации как документ
Категория: desktop
Вариации запроса: акт инвентаризации документ, создать акт, оформление акта

**Пошагово.**
1. Проведите инвентаризацию («Коммерция/Магазин → Остатки → Инвентаризация») — система сформирует документ списания/оприходования.
2. Откройте его в «Бухгалтерия → Документы» → «📥 PDF».
3. Подписи материально ответственных → скан в документы.
4. Проводки — автоматически (сверьте с ОСВ).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
