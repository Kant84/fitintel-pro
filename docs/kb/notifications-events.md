# notifications: события и каналы детально (17 статей)

> Категория: notifications · Пять событий «Клиенту», дайджест, рассылки, webpush/Telegram/SMS, чеки.

## Событие «Оплата/пополнение» (чек и баланс)
Категория: notifications
Вариации запроса: событие оплата, чек после оплаты, уведомление о платеже клиенту
📷 Скриншоты: scr-notif-03.png

**Что отправляется.** Подтверждённый платёж: текст с суммой/способом; чек на email (при включённом чеке и заполненном email клиента).
**Настройка.** «Уведомления → Клиенту» → галочка события → «✏» текст (переменные {name}, {sum}…) → «💾 Сохранить».
**Проверка.** «Тест» → журнал: статус sent. Не ушло — нет привязанного канала/email (failed в журнале).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Событие «Абонемент истекает» (за N дней)

📷 Скриншоты: scr-notif-03.png

## Ежедневный дайджест на email клуба
Категория: notifications
Вариации запроса: дайджест, ежедневная сводка, утренний отчёт на почту
📷 Скриншоты: scr-notif-03.png

**Что внутри.** Выручка (нал/безнал), посещаемость, новые клиенты, риск оттока, ожидающие платежи, важные события дня.
**Настройка.** «Уведомления → Email»: галочка дайджеста, email получателя(ей), время (ЧЧ:ММ, по умолчанию 09:00) → «Сохранить Email».

**Сбой.** Не приходит → SMTP (535/таймаут), время по серверу (часовой пояс).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Рассылки: типы и аудитории
Категория: notifications
Вариации запроса: рассылка типы, акция напоминание инфо, кому слать
📷 Скриншоты: scr-notif-03.png

**Типы.** Акция / Напоминание / Инфо (поле «Тип» в форме рассылки «MAX сообщения → Рассылка»).
**Аудитории.** Клиенты / Тренеры / Все / Конкретный клиент (список).
**Каналы.** MAX (привязанные), Telegram, email — по доступным привязкам.
**Антиспам.** 1–2 рассылки в неделю; каждая — с возможностью отписки/обращения.
**Результат.** «в очереди N, sent=X, failed=Y»; failed — проверить привязки.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Автонапоминания 3/14 дней без визита
Категория: notifications
Вариации запроса: 3 дня без визита, 14 дней пропал, автонапоминания правила
📷 Скриншоты: scr-notif-03.png

**Правила.** Истечение абонемента ≤3 дней → напоминание о продлении; нет визитов 14+ дней (с активным абонементом) → «пропал»; без повторов в день.
**Запуск.** «Уведомления → Клиенту → Автонапоминания» (или «MAX сообщения → Возврат клиентов») → «🔔 Сгенерировать напоминания сейчас» → «Создано напоминаний: N».
**Отправка.** «Журнал → 📤 Отправить ожидающие» → sent/failed.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Web Push: VAPID и подписка клиента
Категория: notifications
Вариации запроса: web push настройка, vapid ключи, подписка пуши
📷 Скриншоты: scr-notif-04.png

**Настройка (admin).**
1. «Уведомления → Web Push» → галочка включения.
2. VAPID public/private/sub — сгенерировать (кнопка) или вставить свои → «Сохранить Web Push».
3. Клиент подписывается из мини-приложения/браузера (диалог подписки).
**Тест.** «Тест» → канал webpush → «Отправить тест».
**Apple.** iOS/Safari — подписка только из PWA/настроек клуба; BadJwtToken — время сервера (errors.md).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## SMS: экономика и когда использовать
Категория: notifications
Вариации запроса: sms когда, стоимость смс, экономия на уведомлениях
📷 Скриншоты: scr-notif-03.png

**Экономика.** ~46 ₽/смс (SMSC, незарегистрированная подпись). Массовые рассылки по SMS съедят бюджет — переводите на MAX/Telegram/email (бесплатно).
**Когда SMS.** Срочное: смена расписания «завтра в 7 утра», инциденты, клиенты без мессенджеров.
**Настройка.** «Уведомления → SMS»: smsc.ru логин/пароль/подпись → «Сохранить SMS» → тест.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Чек клиенту на email: механика
Категория: notifications
Вариации запроса: чек на email как работает, автоматическая отправка чека
📷 Скриншоты: scr-notif-03.png, scr-notif-07-check-email.png

**Механика.** Подтверждение платежа → ReceiptService.auto_send_for_payment → письмо с чеком на email из карточки клиента (при включённом событии оплаты и настроенном SMTP).
**Проверка.** «Уведомления → Журнал»: письмо sent/failed.
**Типовые причины failed.** Нет email в карточке; письмо в спаме (попросить добавить адрес в контакты); 535 SMTP.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Тестовая отправка по каналам
Категория: notifications
Вариации запроса: тест уведомлений, проверить канал, отправить тест
📷 Скриншоты: scr-notif-08-sent-ok.png, scr-notif-05.png

**Пошагово.**
1. «Уведомления → 📨 Тест» → Канал (email/sms/webpush).
2. Получатель: из базы (список + «🔄») или вручную (email/+7…).
3. Текст → «📨 Отправить тест». Ожидание: «Отправлено ✓» или «Ошибка: …».
4. «📊 Отправить дайджест» — тест сводки.
**Интерпретация ошибок.** 535 — пароль приложения; таймаут — порт/хост; sms — баланс/подпись; webpush — VAPID/подписка.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Отписка и антиспам правила
Категория: notifications
Вариации запроса: отписка от рассылок, антиспам, как не попасть в бан
📷 Скриншоты: scr-notif-03.png

**Правила.**
1. Рекламные рассылки — только клиентам с согласием на рекламу (карточка → «Согласия»).
2. Частота: 1–2 в неделю; обязательна отписка (ссылка/команда в тексте).
3. Транзакционные (чеки, записи) — без ограничений.
4. Репутация домена: массовую рекламу — с отдельного поддомена/сервиса рассылок, иначе пострадают и транзакционные письма (спам).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал уведомлений как диагностический инструмент
Категория: notifications
Вариации запроса: журнал для диагностики, failed почему, статусы разбор
📷 Скриншоты: scr-notif-03.png

**Пошагово.**
1. «Уведомления → 📋 Журнал → 🔄 Обновить журнал».
2. Найдите проблемное письмо (поиск по клиенту/дате).
3. Статус failed → раскройте: текст ошибки показывает причину (535, таймаут, нет канала).
4. Исправьте настройку канала → «Тест» → повторная отправка ожидающих (если применимо).
Ожидание: запись со статусом sent.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
