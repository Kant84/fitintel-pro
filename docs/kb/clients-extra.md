# clients: карточка клиента по разделам (17 статей)

> Категория: clients-subs · Все 17 разделов карточки клиента 1.6.2: что в каждом и как работать.

## Карточка клиента: структура 17 разделов
Категория: clients-subs
Вариации запроса: карточка клиента разделы, из чего состоит карточка, дерево карточки

**Структура карточки (1.6.2).**
- Анкета: ФИО, пол, дата рождения, фото.
- Контакты: телефон, email, адрес, Telegram/MAX-привязки.
- Документы: паспорт/договор (сканы, доступ ограничен).
- Пакеты/Услуги: абонементы, остатки, заморозки.
- Замечания: внутренние пометки персонала.
- Согласия: 152-ФЗ, биометрия, реклама.
- Аудит: история изменений карточки.
- СЧЁТ: Чеки · Баланс · Бонусы · Скидки.
- ПРОЧЕЕ: Сообщения · История (визиты/платежи) · Блоки · Автомобили · Гость.
Открытие: двойной клик в «Клиентах».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Анкета»
Категория: clients-subs
Вариации запроса: анкета клиента, фото клиента, основные данные

**Что редактировать.** ФИО, пол, дата рождения (форматы: ДД.ММ.ГГГГ/ГГГГ-ММ-ДД/ДД.ММ.ГГ), фото (jpg/png до 2 МБ; видно в поиске/табло). Ошибки: «Неверный формат даты» — исправьте формат. ФИО — корректно: чек/договоры берут его отсюда.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Контакты»
Категория: clients-subs
Вариации запроса: контакты клиента, телефон email сменить, привязки

**Что редактировать.** Телефон (+7XXXXXXXXXX — уникален!), email (уникален — логин ЛК), адрес, привязки MAX user_id/Telegram (кнопка перехода на экран привязок). Дубль телефона/email → ошибка сервера: ищите дубль. Без email — не уйдут чеки/уведомления по email.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Документы»
Категория: clients-subs
Вариации запроса: документы клиента, паспорт скан, договор в карточке

**Что здесь.** Сканы паспорта/договора/медсправок. Загрузка: «➕» → файл (jpg/png/pdf до разумного размера). Доступ: ограничен ролями (admin/ресепшен по праву); просмотр фиксируется в аудите. Хранение — в защищённом хранилище сервера (152-ФЗ).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Пакеты/Услуги»
Категория: clients-subs
Вариации запроса: пакеты услуги клиента, абонементы в карточке, остаток визитов

**Что видно.** Все абонементы/услуги: статус (ACTIVE/FROZEN/EXPIRED/CANCELLED), сроки, счётчик «осталось/лимит», история заморозок. Действия: «➕ Продать», «❄ Заморозить»/«▶ Разморозить», «↩ Возврат» (по регламенту). Турникет сверяется именно с этим разделом.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Замечания»
Категория: clients-subs
Вариации запроса: замечания клиенту, внутренние пометки, комментарий

**Назначение.** Внутренние пометки для персонала (противопоказания, особенности, конфликты). Клиент их НЕ видит. Добавление: «➕» → текст → сохранить; правка/удаление — в списке. Всё фиксируется в аудите. Используйте корректно: без оскорблений (трудовые/юридические риски).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Согласия»
Категория: clients-subs
Вариации запроса: согласия клиента, 152-фз подписать, биометрия согласие

**Список.** Согласие на обработку ПДн (152-ФЗ) — базовое; биометрия — для Face ID; рекламные рассылки — для маркетинга. Подписание: «➕ Подписать» → распечатать шаблон (desktop «Помощь → 152-ФЗ») → клиент подписывает → отметить дату/номер. Отзыв биометрии — удаляет шаблоны лиц автоматически.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Раздел «Аудит» карточки
Категория: clients-subs
Вариации запроса: аудит карточки, кто менял данные клиента, история правок

**Что видно.** Кто и когда менял поля карточки (старые/новые значения): телефоны, ФИО, баланс, статусы. Применение: разбор споров («я не менял номер»), контроль доступа к данным. Экспорт — для разбора инцидентов (152-ФЗ).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## СЧЁТ → Чеки
Категория: clients-subs
Вариации запроса: чеки клиента, история чеков, все покупки клиента

**Что видно.** Все чеки клиента: дата, сумма, способ, ККТ/ФД, ссылка/номер чека. Поиск чека для возврата/жалобы — здесь. Выгрузка — в историю платежей «Платежи» (расширенные фильтры).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## СЧЁТ → Баланс
Категория: clients-subs
Вариации запроса: баланс клиента, кошелёк история, отрицательный баланс

**Что видно.** Текущий баланс кошелька + история движений (пополнения/списания/возвраты). Пополнение — кнопка «Пополнить» (платёж с подтверждением). Минус = долг: оплата кошельком заблокирована до погашения. Ручные корректировки — с комментарием (аудит).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## СЧЁТ → Бонусы
Категория: clients-subs
Вариации запроса: бонусы клиента, история бонусов, сгорание бонусов

**Что видно.** Баланс бонусов, начисления (по правилам `BONUS_*`), списания. Срок жизни бонусов — `BONUS_TTL_DAYS` (параметр клуба); просроченные сгорают автоматически (запись в истории). Оплата бонусами — при продаже способ «Бонусы».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## СЧЁТ → Скидки
Категория: clients-subs
Вариации запроса: скидки клиента, персональная скидка, история скидок

**Что видно.** Назначенные персональные скидки: процент, основание, срок. Назначение — при продаже (поле скидки) или администратором. История — для контроля (кто и когда дал скидку). Не путать с акциями/тарифными скидками.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ПРОЧЕЕ → Сообщения
Категория: clients-subs
Вариации запроса: сообщения клиенту история, переписка в карточке

**Что видно.** История отправленных сообщений: рассылки, автонапоминания, чаты MAX (при синхронизации). Статусы (sent/failed) — переход в журнал уведомлений. Применение: «мы вам писали» — подтверждение факта и времени.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ПРОЧЕЕ → История
Категория: clients-subs
Вариации запроса: история клиента визиты платежи, что покупал клиент

**Что видно.** Хронология: визиты (вход/выход/длительность), платежи, продажи, заморозки, сообщения. Фильтры по типу и дате. Полная картина клиента за период — для менеджера (LTV, частота).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ПРОЧЕЕ → Блоки
Категория: clients-subs
Вариации запроса: блоки клиента, чёрный список в карточке, снять блок

**Что здесь.** Активные блокировки: чёрный список (срок/бессрочно), долг, заметки о запретах. Назначение: «➕ Блок» → причина, срок. Снятие: «Снять блок» (аудит!). Турникет читает этот раздел: блок = отказ.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ПРОЧЕЕ → Автомобили
Категория: clients-subs
Вариации запроса: автомобили клиента, госномер, парковка в карточке

**Что здесь.** Госномера/марки/цвета автомобилей клиента. Добавление: «➕» → данные → сохранить. Применение: шлагбаум/парковка (проверка по списку), поиск клиента по номеру авто. Удаление — при смене авто.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ПРОЧЕЕ → Гость
Категория: clients-subs
Вариации запроса: гость клиента, сопровождающие, гостевой визит

**Что здесь.** Список гостей клиента (ФИО, документ). Добавление: «➕ Добавить гостя». Гостевой визит: «Впустить» → галочка «С гостем» → выбор гостя. Оплата — по регламенту клуба (гостевой тариф). История гостей — в журнале визитов.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
