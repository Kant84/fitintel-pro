# desktop: Платежи (экран) (15 статей)

> Категория: desktop · Экран «Платежи»: выбор клиента, ряд кнопок платежей, ряд кнопок смены,
> строка балансов, подвкладки «Платежи клиента» / «Проводки (бухгалтерия)».

## Выбрать клиента (выпадающий список с поиском)
Категория: desktop
Вариации запроса: выбрать клиента в платежах, список клиентов платежи, клиент не выбран

**Пошагово.**
1. Вверху экрана «Клиент:» — начните печатать ФИО или телефон → выберите человека.
2. Ожидание: подвкладка вернётся на «Платежи клиента», всё ниже работает для него.
3. Не выбран клиент — кнопки платежей не работают.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Провести платёж (форма «Провести платёж»)
Категория: desktop
Вариации запроса: провести платёж, кнопка провести, форма платежа, создать платёж

**Пошагово.**
1. Выберите клиента → «＋ Провести платёж». Ожидание: форма.
2. Сумма — число (запятая/точка; ≤0 → «Сумма должна быть положительным числом»).
3. Способ оплаты — Наличные/Карта/СБП (по QR)/Перевод/Онлайн-оплата/Абонемент (зачёт)/QR-код/Внутренний баланс/Другое.
4. Направление — Приход (клиент платит) / Расход (выдача денег).
5. Категория — (пусто)/Абонемент/Услуга/Товар/Прочее; Комментарий — текст (попадёт в чек и проводку).
6. «OK». Ожидание: платёж создан со статусом «Ожидает» (в кассу ещё НЕ входит).
7. Смена закрыта — красное предупреждение: чек не пробьётся, пока не «Открыть смену».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Подтвердить платёж (фискальный чек)
Категория: desktop
Вариации запроса: подтвердить, чек не пробился, статус ожидает подтверждение

**Пошагово.**
1. Подвкладка «Платежи клиента» → выделите платёж «Ожидает».
2. «✓ Подтвердить». Ожидание: сервер пробивает фискальный чек на АТОЛ → статус «Завершён» → деньги в балансе смены → автопроводка.
3. Закрытая смена → «Смена закрыта…» и платёж останется «Ожидает».
4. Уже подтверждённый → «Платёж уже подтверждён или недоступен».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Возврат платежа (форма «Возврат платежа»)
Категория: desktop
Вариации запроса: возврат, оформить возврат, форма возврата, частичный возврат

**Пошагово.**
1. Выделите платёж → «↩ Возврат». Ожидание: форма.
2. Сумма возврата (пусто = полная; можно частичную).
3. Причина возврата* — без неё «Причина возврата обязательна».
4. «OK». Ожидание: «Возврат оформлен»: баланс уменьшен (нал из наличных, безнал из безналичных) + сторно-проводка.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Отмена платежа (полный возврат)
Категория: desktop
Вариации запроса: отмена платежа, отменить полностью, кнопка отмена платежа

**Пошагово.**
1. Выделите платёж → «✕ Отмена платежа» → «Отменить платёж полностью? Будет оформлен возврат полной суммы.» → Да.
2. Ожидание: возврат с причиной «Отмена платежа».
3. Отличие от «Возврат»: та же механика, фиксированная причина.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Открыть смену
Категория: desktop
Вариации запроса: открыть смену, кнопка открыть смену, смена не открыта

**Пошагово.**
1. «🔓 Открыть смену». Ожидание: смена открыта на сервере.
2. Уже открыта → «Смена уже открыта» (норма, ничего не сломано).
3. Право: Кассир/Администратор/Бухгалтер (иначе 403).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Закрыть смену (окно-отчёт)
Категория: desktop
Вариации запроса: закрыть смену, отчёт закрытия, сверка при закрытии

**Пошагово.**
1. «🔒 Закрыть смену». Закрытая смена → «Смена уже закрыта».
2. Ожидание: окно-отчёт: «Закрытая смена: Наличные X / Безнал Y» + «Остаток на кассе (не снят бухгалтером): нал / безнал».
3. Сверьте наличные с ящиком до закрытия.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Строка балансов: текущая смена vs остаток прошлых смен
Категория: desktop
Вариации запроса: балансы на экране, текущая смена нал безнал, остаток прошлых смен

**Ответ.** «Текущая смена — нал: X ₽ | безнал: Y ₽ || Остаток прошлых смен (не снят): нал A ₽ | безнал B ₽». Нал и безнал раздельно, не суммируются. Считаются только подтверждённые («Завершён») платежи после открытия смены. «Обновить статус» — опросить сервер.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Настройки кассы (АТОЛ): окно и поля
Категория: desktop
Вариации запроса: настройки кассы, атол адрес, окно настроек кассы, драйвер офд

**Пошагово (роль admin).**
1. «⚙ Настройки кассы». Ожидание: баннер «Сейчас: драйвер X | адрес Y | ОФД Z. Пустые поля = без изменений.».
2. Драйвер — АТОЛ / Штрих-М.
3. Адрес кассы http://IP:порт — пусто = не менять.
4. Логин ДТО / Пароль ДТО — пусто = не менять.
5. ОФД — ofd-ru / taxcom / первый-офд / yandex.
6. «OK». Ожидание: «Настройки кассы сохранены».
7. Не admin → 403.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Сумма должна быть положительным числом»
Категория: desktop
Вариации запроса: сумма не принимается, ошибка суммы, не создаётся платёж сумма

**Пошагово.**
1. Сумма — число больше 0; запятая или точка как разделитель.
2. Пробелы/буквы уберите → «OK» заново.
3. Расход (выдача денег) — тоже положительным числом, направление задаётся полем «Направление».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Красное предупреждение «Смена закрыта» при создании платежа
Категория: desktop
Вариации запроса: смена закрыта предупреждение, чек не пробьётся, красная плашка платежи

**Пошагово.**
1. Платёж создан («Ожидает»), но чек не пробьётся.
2. «🔓 Открыть смену» → затем «✓ Подтвердить» платёж.
3. Ожидание: чек пробит, статус «Завершён».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
