# desktop: Настройки и Подключения (11 статей)

> Категория: desktop · Экран «Настройки» — хаб с подвкладками (в 1.6.2 — 10 подвкладок).
> Экран «Подключения»: список профилей (Название|Тип|Хост|Порт|База), «Добавить»/«Изменить»/«Удалить»/«Тест».

## Настройки-хаб: из каких подвкладок состоит
Категория: desktop
Вариации запроса: подвкладки настроек, структура настроек, что где в настройках, хаб настроек

**Ответ.** «Настройки» — хаб (подвкладки перетаскиваются мышкой). В 1.6.2: Мастер первого запуска · Интерфейс (тема/шрифт/масштаб) · Подключения · Уведомления · Касса · Расписание · Пользователи и роли · Параметры клуба · Service-аккаунты · Аудит доступа. У каждой подвкладки — свои поля и «💾 Сохранить».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Интерфейс: тема и шрифт
Категория: desktop
Вариации запроса: тема в настройках, тёмная тема, шрифт интерфейса, масштаб

**Пошагово.**
1. «Настройки → Интерфейс».
2. Тема — Светлая/Тёмная/Контрастная; Шрифт — размер/семейство; Масштаб — ползунок.
3. «💾 Сохранить». Ожидание: интерфейс применился сразу (настройка локальна для ПК/профиля).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Параметры клуба: instance-значения
Категория: desktop
Вариации запроса: параметры клуба, qr ttl, slot minutes, фичи включить, instance config

**Ответ.** «Параметры клуба» — реестр настроек клуба (ключ=значение): `QR_TTL_MINUTES` (на nfs = 2 мин), `SLOT_MINUTES` (= 45), `CANCEL_WINDOW` (= 24 ч), фичи `GYM_ACCESS`/`VENDING_ENABLED` и т.д. Правка — по ключу → «Сохранить». Меняйте осознанно: значения влияют на поведение онлайн-записи, QR, вендинга.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Service-аккаунты
Категория: desktop
Вариации запроса: service аккаунты, технические учётки, сервисный доступ

**Ответ.** «Service-аккаунты» — технические учётные записи для интеграций/автоматизации (без UI-ролей). Создание: имя → токен/ключ → права на API. Храните ключи в менеджере паролей; ротация — перевыпуск.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Аудит доступа (в Настройках)
Категория: desktop
Вариации запроса: аудит в настройках, журнал доступа, кто смотрел данные

**Ответ.** «Аудит доступа» — журнал: логины, просмотры чувствительных данных (документы/лицензии), изменения прав, снятие кассы. Фильтры по сотруднику/типу/периоду; экспорт XLSX/CSV. Доступен ролям admin/бухгалтер (по праву аудита).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Подключения: добавить профиль
Категория: desktop
Вариации запроса: добавить подключение, новый профиль, профиль сервера

**Пошагово.**
1. «Подключения» → «＋ Добавить». Ожидание: форма.
2. Название* (пусто → «Введите название»), Тип — PostgreSQL/Firebird/MySQL/SQLite, Хост, Порт (по умолчанию 5432), База, Пользователь, Пароль (сохранять локально — галочка).
3. «OK». Ожидание: профиль в списке.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Тест профиля подключения
Категория: desktop
Вариации запроса: тест подключения, проверить связь профиль, кнопка тест

**Пошагово.**
1. Выделите профиль → «Тест».
2. Ожидание: «✅ Успешное подключение к «Название» (Хост:Порт/База)» или красная ошибка с причиной (хост/порт/логин-пароль/база не существует).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Изменить/удалить профиль
Категория: desktop
Вариации запроса: изменить подключение, удалить профиль, правка хоста

**Пошагово.**
1. «✎ Изменить» — форма с текущими значениями → правка → «OK».
2. «🗑 Удалить» → «Удалить профиль «Название»?» → Да → «Профиль удалён».
3. Активный профиль сервера клуба не удаляйте — desktop потеряет связь (пересоздайте с тем же адресом `http://<IP>/api/v1`).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Подключение успешно» — а desktop не работает
Категория: desktop
Вариации запроса: тест ок а не работает, профиль тест проходит, ошибка после успешного теста

**Пошагово.**
1. Тест проверяет БД-профиль; рабочее подключение desktop — HTTP-профиль сервера (`http://<IP>/api/v1`). Проверяйте в «Настройки → Подключения» адрес API и статус на Главной/окне входа.
2. Неверный тип профиля (PostgreSQL вместо HTTP-адреса сервера) — создайте профиль с адресом API.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Порт по умолчанию 5432 и другие порты
Категория: desktop
Вариации запроса: порт подключения, 5432, какой порт указывать

**Ответ.** Поле «Порт» по умолчанию 5432 (PostgreSQL). Для HTTP-профиля API порт обычно 80 (http://IP:80 → http://IP). Уточняйте у IT клуба.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Сохранение пароля профиля локально
Категория: desktop
Вариации запроса: сохранить пароль галочка, пароль профиля, безопасность

**Ответ.** Галочка «сохранять пароль локально» — пароль хранится в локальной конфигурации desktop (шифрованно). Без галочки — спрашивать при подключении. На общих ПК галочку не включайте; выход из учётки обязателен в конце смены.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
