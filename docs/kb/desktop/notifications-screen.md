# desktop: Уведомления (экран) (12 статей)

> Категория: desktop · Экран «Уведомления»: в 1.6.2 — 6 подвкладок (Email/SMS/WebPush/Клиенту/Тест/Журнал).
> Поля Email: SMTP хост/порт/логин/пароль/От кого/время дайджеста. SMS: smsc.ru. WebPush: VAPID.

## Настроить Email (SMTP) с экрана
Категория: desktop
Вариации запроса: настроить email на экране, smtp поля, кнопка сохранить email

**Пошагово (admin).**
1. «Уведомления → 📧 Email» → галочка «Включить Email-уведомления».
2. Поля: SMTP хост (плейсхолдер smtp.yandex.ru), SMTP порт (465=SSL, 587=TLS), SMTP логин, SMTP пароль, От кого (email), Время ежедневного дайджеста (ЧЧ:ММ, по умолчанию 09:00).
3. «💾 Сохранить Email». Ожидание: «Сохранено ✓».
4. mail.ru — пароль ПРИЛОЖЕНИЯ, иначе 535 (notifications.md).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Подвкладка «Клиенту» (1.6.2): 5 событий
Категория: desktop
Вариации запроса: клиенту события, настройка уведомлений клиенту, что отправляем клиентам

**Ответ.** 5 событий, каждое — галочка + редактируемый текст (переменные {name}, {date}…):
1. Оплата/пополнение (чек и баланс).
2. Запись/перенос (подтверждение с датой/временем).
3. Абонемент истекает (за N дней).
4. Абонемент истёк (утром дня истечения).
5. Аренда шкафчика истекает.
**Пошагово.** Галочка → «✏» текст → «💾 Сохранить». Ожидание: «Сохранено». Ошибка «api-клиент без put/post» — desktop <1.6.2, обновитесь (errors.md).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Порт 465 vs 587
Категория: desktop
Вариации запроса: какой порт smtp, 465 или 587, ssl tls

**Ответ.** 465 = SSL (сразу шифрованное соединение), 587 = TLS (STARTTLS). mail.ru — 465; Яндекс — 465 или 587 по настройкам. Неверный порт → таймаут/ошибка в журнале.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Пароль в поле SMTP — где хранится
Категория: desktop
Вариации запроса: пароль smtp хранение, точки в поле, безопасность пароля

**Ответ.** Пароль вводится точками и хранится на сервере клуба (в БД настроек), не в открытом виде на ПК. Меняется полем «SMTP пароль» → «Сохранить». Ротация: обновите пароль приложения у почтовика и здесь одновременно.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Ошибка: …» в тесте — расшифровка типовых
Категория: desktop

**Ответ.** 535 — пароль приложения обязателен (mail.ru); таймаут — порт/хост/файрвол; «authentication failed» — логин/пароль; по SMS — баланс smsc/подпись; webpush — VAPID-ключи/подписка.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Каналы приоритета (MAX → Telegram → SMS)
Категория: desktop
Вариации запроса: приоритет каналов, куда уходит клиенту, max телеграм смс выбор

**Ответ.** Уведомления клиенту уходят по привязанным каналам: MAX (основной, бесплатно) → Telegram → SMS (платно, только при отсутствии мессенджеров). Не привязан ни один канал — сообщение не уйдёт (в журнале failed).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Дубли уведомлений клиенту
Категория: desktop
Вариации запроса: два уведомления подряд, дубли писем, повторная отправка

**Пошагово.**
1. Проверьте, что клиенту привязаны не ОБА канала (MAX + Telegram) без необходимости.
2. Журнал: одна запись sent = мессенджер/повтор на его стороне; две записи = действие выполнено дважды (двойной клик).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
