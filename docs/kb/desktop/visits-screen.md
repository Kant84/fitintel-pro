# desktop: Входы/Выходы (10 статей)

> Категория: desktop · Экран «Входы/Выходы»: карточки Сегодня/Неделя/Месяц, поиск, таблица визитов,
> кнопки «🟢 Впустить» / «🔴 Выпустить» / «Завершить» / «Обновить».

## Впустить клиента (форма «Впустить клиента (вход)»)
Категория: desktop
Вариации запроса: впустить, ручной вход, форма впуска, пропустить клиента

**Пошагово.**
1. «Входы/Выходы» → «🟢 Впустить». Ожидание: форма.
2. Клиент* — список; Способ — Ручной (ресепшен)/Карта/QR/Face ID; Зона — текст (по умолчанию main).
3. «OK». Ожидание: создан визит. Сервер проверяет: нет ли уже активного входа («Клиент уже находится в клубе»), активный абонемент, лимит визитов, время тарифа.
4. При настроенном турникете уйдёт команда открытия (её отсутствие не считается ошибкой).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Выпустить клиента (с открытием турникета)
Категория: desktop
Вариации запроса: выпустить, открыть выход, кнопка выпустить

**Пошагово.**
1. Выделите строку со статусом ACTIVE.
2. «🔴 Выпустить» → подтверждение «Открыть выход для: ФИО? Визит будет закрыт.» → Да.
3. Ожидание: визит закрыт (время выхода, длительность), турникет открылся.
4. Не ACTIVE → ««Выпустить» можно только для визита со статусом ACTIVE». Ничего не выделено → «Выделите в таблице строку с активным визитом».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Завершить» визит без открытия турникета
Категория: desktop
Вариации запроса: завершить визит, закрыть без турникета, клиент ушёл не отметился

**Пошагово.**
1. Выделите ACTIVE → «Завершить» (без открытия турникета — клиент физически ушёл).
2. Ожидание: визит закрыт. Уже закрыт → «Этот визит уже закрыт».
3. Используйте, когда выход не записался (карту не приложили).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Карточки Сегодня/Неделя/Месяц
Категория: desktop
Вариации запроса: счётчики входов, сегодня неделя месяц, статистика визитов на экране

**Ответ.** Три карточки сверху — число визитов: за сегодня, за неделю, за месяц. Обновляются по кнопке «Обновить»/F5. Нули при живом клубе → см. «Почему 0 визитов».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Поиск по таблице визитов
Категория: desktop
Вариации запроса: найти визит, поиск по фио в входы, фильтр визитов

**Ответ.** Поиск фильтрует по ФИО, телефону, статусу. Наберите часть — список сузится. Очистка — весь список обратно. Для длинной истории задавайте период/листайте.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Клиент уже находится в клубе» при впуске
Категория: desktop
Вариации запроса: уже в клубе, повторный вход, 409 впуск

**Пошагово.**
1. Откройте «Входы/Выходы» — найдите его активный визит.
2. «🔴 Выпустить» или «Завершить» старый.
3. «🟢 Впустить» заново. Ожидание: новый визит создан.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Отказ при впуске: абонемент/лимит/время тарифа
Категория: desktop
Вариации запроса: не пускает ручной вход, отказ впуск, нет абонемента впуск

**Пошагово.**
1. Прочтите текст отказа в форме/ответе сервера.
2. Проверьте карточку клиента: «Пакеты/Услуги» (активен? срок?), лимит визитов, время посещения по тарифу.
3. Устраните (продление/докупка) → «🟢 Впустить» снова.
4. Принудительный впуск «вопреки» — регламент клуба; действие уйдёт в аудит.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Способы входа в форме (Ручной/Карта/QR/Face ID)
Категория: desktop
Вариации запроса: способ входа, ручной карта qr face id в форме, зачем способ

**Ответ.** Поле «Способ» фиксирует, как клиент прошёл: Ручной (ресепшен) — на стойке; Карта/QR/Face ID — фиксация способа при ручном впуске (например, пропустили по QR с телефона). В отчётах видно распределение способов.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Почему 0 визитов, а клиенты ходят
Категория: desktop
Вариации запроса: визиты не пишутся, таблица пустая, счётчики ноль

**Пошагово.**
1. «Обновить»/F5. Ожидание: данные перечитаны.
2. Проверьте, что визиты создаются: впустите тестово («🟢 Впустить») — строка появилась?
3. Турникетные проходы не попадают → связь контроллер→API (skud-hardware.md «curl checkaccess»).
4. IT: логи api на момент прохода.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
