# desktop: Абонементы и Тарифы (11 статей)

> Категория: desktop · Экран «Абонементы»: таблица Клиент|Тариф|Начало|Конец|Статус|Осталось визитов;
> статусы ACTIVE(зел)/FROZEN(син)/EXPIRED(крас)/CANCELLED(сер). Экран «Тарифы»: код/название/цена/дней/визитов/тип.

## Продать абонемент (форма «Продажа абонемента»)
Категория: desktop
Вариации запроса: продать абонемент, кнопка продать, форма продажи, оформить подписку

**Пошагово.**
1. «Абонементы» → «＋ Продать абонемент». Ожидание: форма.
2. Клиент* — список «Фамилия Имя (телефон)» (первые 200); начните печатать для фильтра.
3. Тариф* — список активных «Название — цена RUB».
4. Дата начала* — по умолчанию сегодня (ГГГГ-ММ-ДД).
5. «OK». Ожидание: абонемент создан; дата окончания посчитана по длительности тарифа.
6. Список пуст (нет клиентов/тарифов) → «Нужны клиенты и тарифы».

**Типичные ошибки.** Клиент не в списке — сначала создайте его в «Клиентах»; деньги не списались — продажа = создание абонемента, платёж оформляется отдельно (payments.md).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Заморозить абонемент (форма «Заморозка»)
Категория: desktop
Вариации запроса: заморозить, кнопка заморозить, форма заморозки, приостановить абонемент

**Пошагово.**
1. «Абонементы» → выделите строку со статусом ACTIVE.
2. «❄ Заморозить». Ожидание: форма «Заморозка».
3. «Заморозить до (ГГГГ-ММ-ДД)» — дата или пусто = без срока; «Причина» — свободный текст.
4. «OK». Ожидание: статус FROZEN (синий). При разморозке срок сдвинется на замороженные дни.

**Типичные ошибки.** Кнопка доступна только для ACTIVE; у FROZEN — «▶ Разморозить».
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Разморозить абонемент
Категория: desktop
Вариации запроса: разморозить, снять заморозку, активировать обратно

**Пошагово.**
1. «Абонементы» → выделите FROZEN.
2. «▶ Разморозить» — без формы, сразу выполняется. Ожидание: статус ACTIVE, дата окончания сдвинута на срок заморозки.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Осталось визитов» в таблице — как читать
Категория: desktop
Вариации запроса: осталось визитов, счётчик визитов, лимит исчерпан, сколько осталось

**Ответ.** Колонка «Осталось визитов»: для лимитированного тарифа — число (например 5/8: осталось/лимит). Пусто/«—» — безлимит. При исчерпании турникет даёт отказ (причина в журнале). Докупка — продажа нового/доп. визитов.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Создать тариф (форма «Новый тариф»)
Категория: desktop
Вариации запроса: создать тариф, новый тариф, добавить цену, форма тарифа

**Пошагово.**
1. «Тарифы» → «Создать тариф». Ожидание: форма.
2. Код* (A-Z, 0-9, _; станет ЗАГЛАВНЫМ), Название* (пусто → «Название обязательно»), Цена*, Дней действия* (по умолчанию 30).
3. Лимит визитов (пусто = без лимита) — для лимитированного тарифа пустое поле → 30.
4. Тип — Лимитированный / Безлимитный.
5. «OK». Ожидание: тариф в таблице.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Редактировать и удалить тариф (кнопки в строке ✎/✕)
Категория: desktop
Вариации запроса: редактировать тариф, удалить тариф, кнопки в строке тарифа

**Пошагово.**
1. «Тарифы» → в строке тарифа: «✎» — форма «Редактировать: Название» (поля заполнены) → «OK» → «Тариф обновлён».
2. «✕» — подтверждение «Удалить тариф N (КОД)? Это действие нельзя отменить!» → Да → «Тариф удалён».
3. По тарифу с продажами лучше не удалять — правьте ✎ (цена/название); удаление со продажами может быть запрещено сервером.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Статус EXPIRED у абонемента — продление
Категория: desktop
Вариации запроса: expired красный, истёк абонемент, продление просроченного

**Пошагово.**
1. «Абонементы» — EXPIRED подсвечен красным.
2. «＋ Продать абонемент» → тот же/новый тариф. Ожидание: новый активный период после создания (деньги — отдельным платежом).
3. Автоматических «возвратов дней» из просроченного нет — новый абонемент начинается с даты продажи.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## CANCELLED (серый) — что означает
Категория: desktop
Вариации запроса: cancelled, серый статус, отменённый абонемент

**Ответ.** Абонемент отменён (возврат/аннуляция продажи). Турникет не принимает. История сохраняется. Ошибочная отмена — разбор через поддержку с аудитом (кто отменил).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Дата окончания посчиталась неверно
Категория: desktop
Вариации запроса: неправильная дата окончания, сколько дней длится, длительность тарифа

**Ответ.** Дата окончания = дата начала + «Дней действия» тарифа. Заморозка продлевает срок на замороженные дни при разморозке. Проверьте: «Тарифы → ✎» (дней действия) и историю заморозок в карточке клиента.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Клиента нет в списке при продаже абонемента
Категория: desktop
Вариации запроса: нет клиента в списке, список клиентов пуст, первые 200

**Ответ.** Список клиентов в форме — первые 200 записей с сервера. Печатайте ФИО/телефон — список фильтруется. Совсем пусто → «Нужны клиенты и тарифы»: сначала создайте клиента («Клиенты → ＋»), проверьте, что есть активные тарифы.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Лимит визитов по умолчанию 30 — откуда
Категория: desktop
Вариации запроса: откуда 30 визитов, лимит по умолчанию, пустой лимит, лимит абонементов, увеличить лимит, максимум визитов

**Ответ.** В форме тарифа для типа «Лимитированный» пустое поле «Лимит визитов» подставляет 30. Задайте своё число или переключите тип на «Безлимитный» (лимит не используется).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
