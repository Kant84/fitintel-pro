# desktop: Пользователи, Роли, Экраны ролей (11 статей)

> Категория: desktop · Экран «Пользователи»: таблица Логин|Email|Роли|Прав|Статус, «Показать удалённых»,
> «Создать пользователя»/«Удалить». «Роли и права» — просмотр матрицы. «Экраны ролей» — видимость экранов.

## Создать пользователя (окно «Новый пользователь»)
Категория: desktop
Вариации запроса: создать пользователя, новый сотрудник, добавить учётку, форма пользователя

**Пошагово (admin).**
1. «Пользователи» → «Создать пользователя». Ожидание: форма.
2. Логин* (уникальный), Email* (уникальный), Пароль* (минимум 8 символов), Роль* — список с сервера.
3. «OK». Ожидание: пользователь создан, роль назначена автоматически.
4. Дубль → «Пользователь с таким email/username уже существует».

**Типичные ошибки.** Пароль <8 символов; email без @. Список ролей в форме — из справочника ролей сервера (в 1.6.2 — 12 ролей, назначаются галочками в карточке сотрудника).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Удалить пользователя (и почему superadmin нельзя)
Категория: desktop
Вариации запроса: удалить пользователя, убрать сотрудника, superadmin нельзя удалить

**Пошагово.**
1. Выберите строку → «Удалить» → «Удалить пользователя «логин» безвозвратно?» → Да.
2. Ожидание: технически — безопасная деактивация (вход невозможен, история сохраняется).
3. superadmin → «superadmin нельзя удалить» (защита).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Показать удалённых» — переключатель
Категория: desktop
Вариации запроса: удалённые пользователи, показать удалённых, учётки deleted

**Ответ.** По умолчанию таблица показывает активных. Переключатель «Показать удалённых» — видны учётки «deleted_…» (деактивированные). Полезно для аудита и восстановления доступа (через сброс пароля/поддержку).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Колонка «Прав» в таблице пользователей
Категория: desktop
Вариации запроса: число прав, колонка прав, сколько прав у сотрудника

**Ответ.** «Прав» — суммарное число эффективных прав пользователя (по ролям + индивидуальные). Живые ориентиры 1.6.2: Admin ~75, Manager ~19, Cashier ~11, Accountant ~8, Trainer ~4, Client ~8. Точное значение — в карточке сотрудника «Роль и права» / матрице.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Экран «Роли и права» — просмотр матрицы
Категория: desktop
Вариации запроса: роли и права экран, матрица ролей просмотр, кто что может

**Ответ.** Экран просмотра матрицы RBAC: таблица Роль | Код | Кол-во прав | Права (первые 6; наведите курсор — всплывёт полный список). «Обновить» — перечитать с сервера. Редактирование прав — на стороне сервера/API (в 1.6.2 — через «Настройки → Роли и права»/матрицу; экран здесь информационный).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Экраны ролей: отметить видимые экраны
Категория: desktop
Вариации запроса: экраны ролей настройка, отметить экраны, видимость разделов

**Пошагово (admin).**
1. «Экраны ролей» → «Роль:» — список ролей с сервера.
2. Таблица: «Виден» (галочка) | Экран | Код. Подсказка: «Отметьте экраны, которые будут видны выбранной роли. Не отмеченное роль не видит вообще».
3. «Сохранить». Ожидание: «Роль X: видимых N, скрытых M».
4. «Сбросить к умолчанию» → подтверждение → возврат к дефолтному набору.
5. «Обновить» — перечитать матрицу.

**Типичные ошибки.** Строгая модель: ни одной отметки = пользователь не увидит ни одного раздела; у superadmin галочка «Экраны ролей» заблокирована (защита от самоблокировки).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Пользователь с таким email уже существует»
Категория: desktop
Вариации запроса: дубль email, не создаётся пользователь, уже существует

**Пошагово.**
1. Найдите существующую учётку («Пользователи» → поиск/«Показать удалённых»).
2. Если это тот же человек — сбросьте пароль вместо создания новой учётки.
3. Если другой — используйте другой email (каждый сотрудник — свой email).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Статус «Отключён» в таблице
Категория: desktop
Вариации запроса: отключён красным, статус пользователя, деактивирован

**Ответ.** «Статус»: Активен (зелёный) / Отключён (красный). Отключённый не может войти (401). История действий сохранена. Восстановление — через поддержку/администратора (снятие деактивации).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
