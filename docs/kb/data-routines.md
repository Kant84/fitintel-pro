## Импорт клиентов из CSV (A&A): формат файла
Категория: clients-subs
Вариации запроса: формат csv импорта, колонки импорта, как подготовить файл
📷 Скриншоты: scr-set-13.png

**Формат.** Разделитель — точка с запятой `;`, кодировка UTF-8, первая строка — заголовки.
**Колонки.** `ФИО;Телефон;Email;Дата рождения;Пол;Категория;Статус;Фото(URL)`.
**Подготовка.**
1. Телефоны — только цифры с +7 (без пробелов/дефисов).
2. Даты — ДД.ММ.ГГГГ.
3. ФИО — одной колонкой через пробел.
4. Уберите дубли до импорта (сервер отсечёт, но журнал будет чище).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Импорт: типовые ошибки и журнал
Категория: clients-subs
Вариации запроса: ошибки импорта, не импортировались, журнал импорта
📷 Скриншоты: scr-set-13.png

**Типовые ошибки.**
- Неверный разделитель (запятая вместо `;`) → все в одной колонке.
- Кодировка Windows-1251 → кракозябры.
- Телефон с пробелами → запись пропущена (журнал).
- Дубль телефона/email → пропуск с пометкой.
**Пошагово.** «Интеграции → 🔗 A&A → 📥 Импорт CSV» → «📝 Журнал → 🔄 Обновить» → разбор строк с ошибками → правка файла → повторный импорт.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Перенос данных при смене сервера
Категория: server
Вариации запроса: перенос данных, миграция базы, новый сервер данные
📷 Скриншоты: scr-set-13.png

**Пошагово (IT).**
1. Бэкап БД с текущего сервера (`backup_postgres.py` или pg_dump).
2. На новом: установка по INSTALL_SERVER.md → тот же `deploy/.env`.
3. Накатить дамп (статья server-admin «Восстановление из бэкапа»).
4. Перенести файлы: загрузки (фото/документы), статика, license-файлы.
5. Запуск → health → desktop на новый IP.
6. Старый сервер не выключать до сверки (параллельная запись = конфликт).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Анонимизация: когда обязательна
Категория: clients-subs
Вариации запроса: когда анонимизировать, запрос на удаление, сроки 152-фз
📷 Скриншоты: scr-fin-10.png

**Обязательные случаи.**
1. Письменный запрос субъекта ПДн (предоставить/удалить).
2. Истечение целей обработки (карточка неактуальна, нет взаимодействия N лет — по политике клуба).
3. Требование Роскомнадзора.
**Порядок.** Запрос → анонимизация (admin) → подтверждение клиенту → запись в аудите. Срок ответа — по закону (обычно 10 рабочих дней).

## Ручные правки в БД (предупреждение)
Категория: server
Вариации запроса: правка базы руками, sql в базу, update напрямую
📷 Скриншоты: scr-set-13.png

**Правило.** Ручные SQL-правки — крайняя мера и только с бэкапом: целостность связей и аудит могут пострадать.

**Если необходимо.** Бэкап → транзакция → проверка → коммит; действие и причину — в журнал IT клуба; при сомнениях — поддержка.
