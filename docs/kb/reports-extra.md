## Операционный свод: состав и применение
Категория: desktop
Вариации запроса: операционный свод отчёт, что внутри, ежедневный обзор

**Что показывает.** Ключевые цифры дня/периода: выручка, визиты, новые клиенты, продажи, возвраты, инциденты. **Применение.** Утренний обзор вчерашнего дня администратором/директором; база для ежедневного дайджеста на email. Формирование: «Отчёты → Операционный свод → период → Сформировать».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Посещаемость по дням: чтение графика
Категория: desktop
Вариации запроса: посещаемость по дням, график визитов, динамика посещений

**Что показывает.** Визиты по дням за период (столбцы/линия). **Как читать.** Пики — дни максимальной нагрузки (планирование персонала); провалы — дни для акций/мероприятий; тренд — рост/падение интереса. Сравнивайте однодневные недели (пн vs пн), а не просто день ко дню (сезонность).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Загруженность по часам: микропланирование
Категория: desktop
Вариации запроса: загруженность по часам отчёт, часы пик, почасовая статистика

## Давно не посещали (30 дн.): работа со списком
Категория: clients-subs
Вариации запроса: давно не посещали отчёт, 30 дней список, обзвон пропавших

**Что показывает.** Клиенты без визитов 30+ дней (даты «С/по» игнорируются — порог зашит). **Применение.**
1. Выгрузить CSV.
2. Разделить: активный абонемент (риск оттока — звонок/оффер) vs истёкший (продление).
3. Обзвон/рассылка с персональным предложением.
4. Результат — в статистике визитов (вернулся/нет).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Окончание абонементов (14 дн.): пайплайн продлений
Категория: clients-subs
Вариации запроса: окончание абонементов отчёт, продления список, работа с продлениями

**Что показывает.** Абонементы, заканчивающиеся в ближайшие 14 дней. **Пайплайн.**
1. Ежедневно: список → звонки/сообщения (за 14–7 дней — мягкое напоминание, за 3–1 — оффер продления).
2. Скидка продления (если настроена в тарифе) — аргумент.
3. Не продлил в день X — «Абонемент истёк» → возврат клиентов (14 дней).
4. Контроль: % продлений — ключевая метрика удержания.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

Вариации запроса: продажи и оплаты отчёт, выручка по категориям, разбор продаж

**Что показывает.** Платежи за период: по категориям (Абонемент/Услуга/Товар/Прочее), способам (нал/безнал), статусам. **Применение.**

## P&L: структура и типовые ошибки чтения
Категория: cash-fiscal
Вариации запроса: p&l как читать, прибыль убыток структура, отчёт p&l ошибки

**Структура.** Доходы (выручка по видам) − Себестоимость − Расходы (кассовые, по счету 91.2) + Прочие = Прибыль.
**Типовые ошибки.**
- Смотреть только выручку, игнорируя расходы.
- Расходы без комментариев — «чёрный ящик» (требуйте описания в РКО).
- Сравнивать месяцы с разным числом дней — используйте среднедневные показатели.
- Период: P&L берёт месяц из поля «по».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ОСВ: контрольные суммы и расхождения
Категория: cash-fiscal
Вариации запроса: осв сверка, расхождения осв, контроль баланса

**Контроль.** Обороты Дт = обороты Кт (по всем счетам). Сальдо: 50 (касса) = физические деньги; 57 (эквайринг) = незачисленный безнал; 90.1 — накопленная выручка.
**Расхождения.**
- 50 ≠ касса → пропущенные ПКО/РКО или не подтверждённые платежи.
- 57 «висит» → не сверён эквайринг (webhook'и/зачисления).
- 91.2 растёт без дела → расходы без комментариев.
Разбор — с бухгалтером по журналу проводок.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Баланс: «сходится/не сходится»
Категория: cash-fiscal
Вариации запроса: баланс не сходится, активы пассивы отчёт, контроль баланса

**Что показывает.** Активы (50/51/57/62) vs Пассивы (60/66/90/99) на дату. **«Не сходится»** — ошибка в проводках (пропущенная сторно, ручная правка). **Пошагово.**
1. ОСВ за тот же месяц — поиск счёта с аномалией.
2. Журнал проводок — построчно по дате расхождения.
3. Ручные правки БД — исключить (см. data-routines «Ручные правки»).
4. Не нашли — бухгалтер + поддержка с выгрузкой проводок.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Экспорт любого отчёта: куда и зачем
Категория: desktop
Вариации запроса: экспорт отчётов, куда выгружать, форматы отчётов

**Форматы.** CSV (UTF-8 с BOM — Excel), из таблиц — XLSX/PDF. **Куда.**
- Excel — анализ, графики, сводки для директора.
- 1С/бухгалтерия — XML (CommerceML) через «Интеграции → 1С».
- Печать — «🖨 Печать» для бумажного экземпляра (подписи/архив).
**Регламент.** Ежедневные своды — email-дайджест; месячные — XLSX бухгалтеру + архив PDF.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
