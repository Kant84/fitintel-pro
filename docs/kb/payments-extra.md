## ЮKassa: механика платежа start-to-finish
Категория: payments
Вариации запроса: юкасса как работает, цепочка платежа, payment id
📷 Скриншоты: scr-fin-01.png

**Цепочка (по коду payments.py + YOOKASSA_RUNBOOK.md).**
1. Платёж создаётся со способом «Онлайн-оплата» → клиенту ссылка/QR на оплату.
2. Клиент платит в ЮKassa.
3. ЮKassa шлёт webhook на `https://<домен>/api/v1/payments/yookassa/webhook` (подпись `X-Payment-Signature`, HMAC — проверяется).
4. Сервер подтверждает платёж: статус «Завершён», чек, уведомление клиенту.
5. Расхождение = webhook не дошёл/не прошёл проверку → «Ожидает» (статья «Оплата прошла — Ожидает»).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Рекурренты: жизненный цикл
Категория: payments
Вариации запроса: рекуррент цикл, автосписание этапы, сохранённая карта срок
📷 Скриншоты: scr-fin-01.png

**Жизненный цикл (по коду recurring.py).**
1. Клиент платит онлайн с галочкой «Сохранить карту» (согласие обязательно) → сохраняется рекуррентный токен.
2. Автопродление/автосписание → сервер создаёт рекуррентный платёж по токену.
3. Успех → «Завершён» + чек + уведомление.
4. Отказ (карта протухла/нет средств) → уведомление клиенту; продление вручную.
**Управление.** Отвязка карты — клиентом в приложении/ресепшеном (привязки).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Частичный возврат и рассрочка
Категория: payments
Вариации запроса: частичный возврат, рассрочка платежа, оплата частями
📷 Скриншоты: scr-fin-01.png

**Частичный возврат.** «↩ Возврат» → сумма < суммы платежа → причина. Чек возврата на часть; баланс вида оплаты уменьшается на часть.
**Рассрочка.** Несколько платежей на одну продажу: внесли часть → остаток позже; контроль долга — баланс клиента/пакет услуги (остаток в «Пакеты/Услуги»).
**Запрет.** Не редактируйте подтверждённый платёж — только возврат + новый платёж (аудит!).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Возврат на карту vs наличные: правила
Категория: payments
Вариации запроса: возврат наличными за карту, как вернуть деньги, куда возврат
📷 Скриншоты: scr-fin-01.png

**Правило.** Возврат — тем же способом, что оплата: безнал → на карту/реквизиты (сроки банка до 3–10 дней), наличные → из кассы (деньги в ящике). «Нал за карту» — нарушение кассовой дисциплины: исключения только по письменному решению директора с фиксацией (аудит, комментарий в платеже).

## Автоматическая отправка чека: условия
Категория: payments
Вариации запроса: авточек условия, когда чек уходит сам, receipt service
📷 Скриншоты: scr-fin-01.png

**Условия (ReceiptService.auto_send_for_payment).**
1. Платёж подтверждён.
2. У клиента в карточке есть email.
3. Событие «Оплата/пополнение» включено на «Клиенту».
4. SMTP настроен и работает (тест «Отправлено ✓»).
5. В настройках платежа/клуба — автоотправка включена.
Проверка: «Уведомления → Журнал» → запись со статусом sent. Не сработало — идите по списку: email → событие → SMTP → журнал.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Ошибка «Касса недоступна: No connection adapters»
Категория: errors
Вариации запроса: no connection adapters, касса недоступна адаптеры
📷 Скриншоты: scr-err-06-kassa-no-conn.png

**Причина.** В адресе кассы нет схемы/хоста: «192.168.1.5:16732» вместо «http://192.168.1.5:16732».
**Пошагово.**
1. «Платежи → ⚙ Настройки кассы» → адрес должен начинаться с `http://`.
2. «Сохранить» → тестовый чек 1 ₽.
3. Доступность: открыть адрес в браузере с сервера/ПК кассы.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

Категория: payments

📷 Скриншоты: scr-fin-01.png

**Защита.** Подтверждение платежа идемпотентно: повторное «Подтвердить» → «Платёж уже подтверждён или недоступен». Онлайн — защита по id платежа/подписи webhook.
**Если списалось дважды (банк).**
1. Сверьте с кабинетом банка/ЮKassa (два платежа?).
2. В FitIntel — один платёж; дубль — возврат/отмена в банке (сроки банка).
3. Клиенту — объяснение + контроль возврата.
