## Как оформить возврат денег клиенту: полный регламент (карта, наличные, частичный возврат)
Ключевые слова: возврат, возврат денег, чек возврата, sellReturn, РКО, возврат по карте, частичный возврат, отмена платежа, фискальный чек возврата
**Ответ.**
Возврат — обратная кассовая операция с чеком расхода (sellReturn по протоколу АТОЛ). Отмена отличается: возможна только в день операции до закрытия смены и без чека. Регламент ниже покрывает три сценария: полный возврат на карту, наличный возврат, частичный возврат; плюс диагностика всех типовых ошибок кассы.
**Сценарий 1. Полный возврат на карту.**
1. «Бухгалтерия → Платежи». Поиск — ФИО или телефон, Enter.
2. Откройте платёж: три проверки — способ «Карта», статус «Подтверждён», сумма.
3. Если «Ожидает» — сначала «Подтвердить» в карточке платежа.
4. «Вернуть» → диалог возврата: сумма по умолчанию полная, менять не нужно.
5. Причина — обязательное поле: «отказ от услуги», «двойное списание» — текст уйдёт на чек.
6. «Выполнить возврат»: команда sellReturn уходит на ДТО 10 (адрес в «Платежи → Настройки кассы», стандарт `http://<IP-кассы>:16732`).
7. Дождитесь печати чека возврата на кассе — без чека эквайринг возврат не проведёт.
8. Журнал: строка с минусом и статусом «Возвращён».
9. Зачисление на карту клиента: 1–3 рабочих дня, номер чека продиктуйте — банк ищет по нему быстрее.
**Сценарий 2. Наличный возврат.**
1. Шаги 1–5 как в сценарии 1, но платёж со способом «Наличные».
2. После «Выполнить возврат» деньги выдаются из кассы через «Касса → Расход» с тем же основанием.
3. X-отчёт в конце смены: возврат виден отдельной строкой — сверяется с наличностью в ящике.
**Сценарий 3. Частичный возврат.**
1. Диалог возврата: в поле «Сумма» впишите часть, меньше исходной.
2. Причина обязательна; комментарий фиксирует, за что именно возврат (например, «возврат за 3 занятия из 10»).
3. Остаток услуги/абонемента не меняется — возврат только денежный.
4. Повторные частичные возвраты — каждый отдельным чеком.
**Проверка.**
- «Бухгалтерия → Платежи»: исходная операция и возврат, суммы до копейки.
- Чек возврата физически на руках: тип «возврат прихода», ФН и номер документа внизу.
- Баланс клиента (внутренний) не изменился.
**Возможные ошибки.**
- «Касса недоступна: No connection adapters» — адрес кассы без http:// или без порта :16732; проверьте «Настройки кассы».
- «Касса вернула ошибку: 1» — ДТО 10 не запущен на ПК кассы; запустите, проверьте трей.
- «Expecting value: line 1 column 1 (char 0)» — касса вернула HTML: откройте `http://IP:16732` в браузере, перезапустите ДТО 10.
- «Платёж уже подтверждён» — отмена невозможна, только возврат.
- Чек не напечатался, деньги ушли: «Настройки кассы → X-отчёт», затем звонок оператору ФН для восстановления чека.
- Возврат висит «Ожидает» — связь с эквайрингом прерывалась: подтвердите повторно.
- 422 в карточке — пустая причина или сумма больше исходной.
**FAQ.**
- Можно ли отменить вчерашний платёж? Нет — только возврат с чеком.
- Клиент потерял чек возврата — что делать? Копия по номеру ФН у оператора; клиенту достаточно номера чека.
- Возврат по СБП/переводу — отличается? Только сроком зачисления (до 5 дней), порядок тот же.
**Совет.**
Сверяйте X-отчёт с эквайринговой выпиской до ухода кассира — расхождения дешевле ловить в день операции.
**Если не помогло:** «не помогло» + текст ошибки кассы + способ оплаты.

## Как перенести клиентскую базу из Excel или бумажного журнала: регламент переноса и контроль качества
Ключевые слова: импорт клиентов, excel, перенос базы, массовое добавление, миграция, дубликаты клиентов, журнал
**Ответ.**
Штатного импорта файла в desktop нет — карточки вводятся по одной; с подготовленной таблицей это 30–60 секунд на клиента. Телефон — ключевой идентификатор (поиск, уведомления, защита от дублей). Базы 500+ человек — через поддержку (загрузка на сервере). Регламент: подготовка → ввод → сверка → закрытие старого источника.
**Сценарий 1. Подготовка данных (делается один раз).**
1. В исходной таблице оставьте колонки: ФИО, телефон, email, дата рождения, заметки.
2. Телефоны — только цифры формата 79XXXXXXXXX; «нет», «—» — оставьте пустыми.
3. Отсортируйте по телефону: дубли телефонов разберите до переноса (один телефон = один клиент).
4. ФИО — в одной колонке; раздельные фамилия/имя слейте через пробел.
5. Проверьте кодировку: файл должен открываться с русскими буквами; при знаках вопроса пересохраните как CSV UTF-8.
**Сценарий 2. Ввод карточек.**
1. Desktop: статус-бар «Сервер подключён | FitIntel Pro v1.6.2» — иначе ничего не сохранится.
2. «Клиенты» → «Добавить клиента» (плюс) или Ctrl+N в списке.
3. «Анкета»: ФИО обязательно; телефон — самое важное поле.
4. «Контакты»: email для чеков и писем.
5. «Замечания»: медицинские/поведенческие пометки из журнала — тренеры их читают.
6. «Документы» — можно позже, не тормозите поток из-за сканов.
7. «Сохранить». Вкладка со звёздочкой = несохранённые изменения — не уходите с неё.
8. Абонементы здесь не создаются: «Абонементы → Продать» — после сохранения клиента.
9. Каждые 20–30 карточек — мини-сверка счётчика с таблицей.
**Сценарий 3. Контроль и закрытие.**
1. Тест поиска: 5 случайных фамилий из старой базы — все находятся?
2. Тест уведомлений: один клиент → «Уведомления → Тест канала».
3. Тест карточки: откройте 3 карточки — данные на своих вкладках.
4. Бумажный журнал — в сторону, но не в мусор: 2 недели параллельной сверки вечером.
5. Рабочий Excel удалите из общих папок (152-ФЗ); архив — бухгалтерии под паролем.
**Проверка.**
- Счётчик списка = числу строк исходной таблицы минус осознанные дубли.
- Поиск по телефону и фамилии работает на перенесённых.
**Возможные ошибки.**
- 422 при сохранении — пустое обязательное поле или битый телефон.
- «Клиент не найден» — карточка не сохранена (звёздочка на вкладке).
- Вопросительные знаки в ФИО — кодировка файла (см. п.5 подготовки).
- «Сервер недоступен» — сеть: вкладка «Подключения» внизу sidebar, проверьте базу.
- Нашли дубль после переноса — не удаляйте: слияние истории делает поддержка, удаление потеряет платежи.
**FAQ.**
- Можно ли перенести балансы? Да — но через поддержку, массово; вручную балансы не вводите.
- Клиентов 1200 — как быть? Переносите частями по 100–150 в день + запрос в поддержку на серверную загрузку.
**Совет.**
Переносите в непиковые часы; две недели параллельного журнала экономят месяц разбора «потеряшек».
**Если не помогло:** «не помогло» + шаг + сколько карточек перенесено.

## Как настроить автоматические уведомления клиентам и не попасть в спам: каналы, автоматика, контроль доставки
Ключевые слова: уведомления, sms, email, спам, smtp, 535, подпись sms, дайджест, авто-напоминания, клиенту, рассылка
**Ответ.**
Хаб «Уведомления» — 6 подвкладок: каналы (SMSC, SMTP, бот MAX), «Клиенту» (5 событий автоматики), рассылки, дайджест, журнал, Web Push. Спам в 90% случаев — это неправильный SMTP, отсутствие подписи в SMS или рассылка без согласия. Регламент: каналы → автоматика → контроль.
**Сценарий 1. SMS через SMSC.**
1. «Уведомления → SMS»: логин/пароль кабинета SMSC.
2. Подпись отправителя: 6–11 латинских символов, зарегистрированная у SMSC.
3. «Тест» — SMS за 10–20 секунд. Нет — баланс (SMS с подписью ~46 ₽) или подпись не одобрена.
4. Лимит: 70 кириллических символов = 1 SMS; длиннее — две части и двойная цена.
**Сценарий 2. Email через SMTP.**
1. «Уведомления → Email»: SMTP сервера ящика; для mail.ru — smtp.mail.ru:465, SSL.
2. Логин — полный email; пароль — «пароль приложения» из настроек безопасности почты.
3. Ошибка 535 — неверный пароль приложения (или двухфакторка без него).
4. Спам у получателей: настройте DKIM/SPF в DNS домена; отправляйте с корпоративного ящика.
**Сценарий 3. Автоматика «Клиенту».**
1. Мастер-выключатель — включить.
2. События: «Абонемент заканчивается за 3 дня», «Абонемент закончился», «День рождения», «Нет визита 14 дней», «Аренда шкафчика истекает».
3. У каждого — канал и шаблон; в шаблонах подставляются {имя}, {дата}, {клуб}.
4. Рассылки — только с галочкой согласия в карточке клиента («Анкета → Согласия»).
5. Дайджест руководителю — «Уведомления → Дайджест», утреннее время.
**Сценарий 4. Контроль.**
1. «Клиенту → Очередь» — кто должен получить сегодня.
2. «Клиенту → Журнал» — статусы доставки; ошибки 535/баланс — сразу видно.
3. Web Push: «Настройки → Уведомления → Web Push», VAPID-ключи из веб-панели; iOS — подписка через Safari.
**Проверка.**
- Все «Тест канала» дошли; очередь формируется; журнал без ошибок.
**Возможные ошибки.**
- SMS не уходят: баланс / подпись / длина текста.
- 535 mail.ru — пароль приложения (см. сценарий 2).
- Письма в спаме — DKIM/SPF и корпоративный ящик.
- «MAX не настроен — сохранено локально» — юрлицу не привязан бот («MAX сообщения → Настройки»).
- Apple BadJwtToken — устаревшие VAPID, перевыпустите.
**FAQ.**
- Клиент просит не писать — снимите согласие, автоматика обойдёт.
- Сколько стоит месяц SMS? Обычно 300–800 ₽ для клуба на 500 клиентов при включённых 3 событиях.
**Совет.**
Первыми включайте «Нет визита 14 дней» и «День рождения» — максимум возврата на рубль.
**Если не помогло:** «не помогло» + канал + текст ошибки из «Журнала».
