# desktop: интеграция 1С (12 статей)

> Категория: desktop/cash-fiscal · CommerceML/API V3, выгрузки, автообмен, ошибки, mapping, регламенты.

## 1С Fitness: варианты обмена
Категория: desktop
Вариации запроса: 1с fitness обмен варианты, commerceml или api, какой обмен выбрать

**Два пути (экран «Интеграции → 1С Fitness»).**
1. **CommerceML 2.05** — универсальный XML-обмен (номенклатура, контрагенты, документы) — стандарт для типовых конфигураций 1С:Управление фитнес-клубом и совместимых.
2. **API V3** — прямой обмен по HTTP API (при поддержке вашей конфигурацией).
Выбор — по документации вашей 1С. Не знаете — начните с CommerceML (кнопка «Выгрузить номенклатуру» — тест).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Первичная настройка: пошагово
Категория: desktop
Вариации запроса: 1с настройка пошагово, подключение 1с fitness шаги

**Пошагово (admin + 1С-специалист).**
1. В 1С: включить обмен по CommerceML/API, получить адрес/логин/пароль.
2. «Интеграции → 🔄 1С Fitness»: адрес 1С (`http://<IP-сервера-1С>:<порт>/<путь>`), логин, пароль, режим (CommerceML 2.05 / API V3).
3. «Проверить связь» → зелёный статус.
4. «Сохранить».
5. Тестовая выгрузка: «📤 Экспорт номенклатуры» → в 1С появился пакет.
6. Журнал обмена — без ошибок.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Выгрузка номенклатуры в 1С
Категория: desktop
Вариации запроса: выгрузить номенклатуру в 1с, товары в 1с отправить

**Пошагово.**
1. «Интеграции → 🔄 1С Fitness → 📤 Экспорт номенклатуры».
2. Ожидание: «Файл сгенерирован» + отправлен в 1С (пакет CommerceML).
3. В 1С: импорт пакета → справочник номенклатуры пополнен.
4. Повторяйте после изменения товаров/цен (или по расписанию автообмена).
⚠️ Сначала — один тестовый товар: проверьте кодировку (UTF-8) и соответствие полей.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Выгрузка контрагентов и документов
Категория: desktop
Вариации запроса: контрагенты в 1с, документы выгрузка 1с, платежи в 1с отправить

**Что выгружать.**
1. **Контрагенты** — клиенты клуба (кнопка «Экспорт контрагентов»).
2. **Документы** — платежи/реализации за период (для бухгалтерии).
3. **Остатки/приходы** — при интеграции склада (по настройке).
**Регламент.** Контрагенты — при изменениях/ежедневно; документы — ежедневно вечером (сверка дня) или ежемесячно (пакетно). Журнал обмена — контроль отправки.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Автообмен по расписанию
Категория: desktop
Вариации запроса: автообмен 1с расписание, автоматическая выгрузка в 1с

**Настройка.** На экране 1С Fitness — расписание автообмена (периодичность, набор объектов). Ожидание: обмен выполняется без участия (журнал — записи по времени).
**Регламент.**
- Контрагенты/номенклатура: раз в день ночью.
- Документы: ежедневно после закрытия смены.
- Полный пакет месяца: 1-е число.
Сбой автообмена — кнопка «Отправить ожидающие» вручную + разбор причины.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Типовые ошибки обмена 1С
Категория: desktop
Вариации запроса: ошибки обмена 1с, не уходит в 1с, commerceml ошибка

**Типовые.**
1. Недоступен адрес 1С (timeout) → сеть/IP/порт/файрвол между сервером клуба и сервером 1С.
2. 401/403 → логин/пароль, права пользователя обмена в 1С.
3. Ошибка схемы XML → версия CommerceML не совпадает (должна быть 2.05).
4. Пустой пакет → нечего выгружать по фильтру (период/объекты).
5. Дубли в 1С → повторная загрузка без контроля соответствия (сверяйте по кодам).
Все — в «Журнал обмена» с текстом; текст ошибки — в обращение.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Соответствие справочников (mapping)
Категория: desktop
Вариации запроса: соответствие справочников 1с, коды товаров клиентов, mapping

**Принцип.** Соответствие — по кодам: у товара/клиента в FitIntel есть код, который ищется в 1С. При расхождении кодов создаются дубли.
**Регламент.**
1. Перед обменом — сверка кодов (выгрузка справочников в Excel, сопоставление).
2. Новые позиции — заводить с единым кодом в обеих системах.
3. Дубли 1С — чистить специалистом 1С (перенос документов на правильный элемент).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Месячная выгрузка бухгалтеру: регламент
Категория: cash-fiscal
Вариации запроса: месячная выгрузка 1с, пакет бухгалтерии, регламент обмена

**Пошагово (ежемесячно, 1–5 число).**
1. В FitIntel: все платежи месяца подтверждены; «Ожидает» = 0.
2. «Интеграции → 1С → 📤 Документы» за месяц (или автообмен сформировал пакет).
3. В 1С: импорт, сверка итогов (выручка нал/безнал vs ОСВ).
4. Расхождения — разбор по журналу платежей (не править вручную в 1С — исправлять источник).
5. Подпись бухгалтера — пакет сдан.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Ручная выгрузка из «Бухгалтерия → 1С (mock)» — отличие
Категория: desktop
Вариации запроса: mock экспорт 1с, бухгалтерия 1с кнопки, отличие mock

**Отличие.** Кнопки «Экспорт номенклатуры/контрагентов (mock)» в «Бухгалтерия → 🔄 1С» — демонстрационные (генерируют файл без реальной отправки в 1С). Боевой обмен — только «Интеграции → 🔄 1С Fitness». Не путайте: mock — для проверки формата, не для учёта.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## 1С не в сети: временный регламент
Категория: cash-fiscal
Вариации запроса: 1с недоступна, сервер 1с упал, обмен отложить

**Временный регламент.**
1. Обмен приостановить (отметить в журнале IT).
2. Учёт продолжается в FitIntel (источник истины — платежи/проводки там).
3. После восстановления 1С: накопленные документы выгрузить пакетом (за пропущенный период).
4. Сверка итогов пропущенного периода перед импортом (чтобы не было дублей/пропусков).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Контроль дублей при повторном импорте
Категория: desktop
Вариации запроса: дубли при импорте 1с, повторная загрузка документов

**Почему возникают.** Повторная выгрузка того же периода без контроля → 1С создаёт второй комплект документов.
**Контроль.**
1. В 1С — поиск документа по номеру/дате/сумме перед импортом пакета.
2. Режим «только новые» (если конфигурация поддерживает) — или выгружайте строго за закрытый период один раз.
3. Обнаружили дубли — удалить/аннулировать в 1С (специалист), исправить регламент периодов.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Кто отвечает за обмен (роли)
Категория: desktop
Вариации запроса: кто настраивает 1с обмен, ответственный за интеграцию

**Распределение.**
- Настройка подключения — IT клуба + специалист 1С (первично, 1–2 часа).
- Ежедневный контроль журнала обмена — бухгалтер (5 минут).
- Расхождения/дубли — бухгалтер + специалист 1С.
- Ошибки на стороне FitIntel (500, формат) — поддержка разработчика с текстом из журнала.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
