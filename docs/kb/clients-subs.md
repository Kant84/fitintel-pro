## Создание нового клиента (карточка)
Категория: clients-subs
Вариации запроса: новый клиент, создать клиента, добавить посетителя, завести карточку, регистрация клиента
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. «Клиенты» → кнопка «➕ Новый клиент» (или Ctrl+N).
2. Заполните: ФИО (обязательно), телефон в формате +7XXXXXXXXXX (обязательно, уникальный), email — если шлёте чеки/уведомления, дата рождения — для поздравлений.
3. «Сохранить». Ожидание: карточка открыта, клиент появился в списке.

**Типичные ошибки.** 422 «Validation error» — телефон с пробелами/дефисами вместо цифр, или такой телефон уже есть у другого клиента (поиск покажет дубль).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

3. Не находится? Проверьте написание; если клиент мог быть удалён — см. статью «Корзина: восстановление».

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Продажа абонемента клиенту
Категория: clients-subs
Вариации запроса: продать абонемент, оформить подписку, новый абонемент клиенту, продление
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Карточка клиента → «Пакеты/Услуги» → «➕ Продать» (или кнопка «Продать услугу» в шапке карточки).
2. Выберите услугу из справочника (тип: срок/лимит входов), дата начала (обычно сегодня), при необходимости скидка.
3. «К оплате» → выберите способ (нал/безнал/кошелёк) → платёж уйдёт в «Ожидает».
4. «Бухгалтерия → Платежи» → «✓ Подтвердить». Ожидание: статус «Подтверждён», чек, абонемент активен (зелёный в карточке).

**Типичные ошибки.** Забыли подтвердить платёж — абонемент висит неактивным; смена закрыта — см. errors.md.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Заморозка и разморозка абонемента
Категория: clients-subs
Вариации запроса: заморозить, разморозить, заморозка абонемента, приостановить, продлить за заморозку
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Карточка клиента → «Пакеты/Услуги» → выберите действующий абонемент.
2. «❄ Заморозить» → укажите причину и срок (или до даты). Ожидание: статус «Заморожен», турникет не пустит до разморозки.
3. Автоматически: срок абонемента продлевается на дни заморозки.
4. Разморозка: та же кнопка → «Разморозить» → статус «Активен».

**Типичные ошибки.** Замораживать можно действующий абонемент; истёкший — только продление. Число заморозок может ограничиваться тарифом.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Лимит входов исчерпан (сезонный абонемент)
Категория: clients-subs
Вариации запроса: закончились посещения, лимит входов, сколько осталось визитов, 8 из 8
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Карточка клиента → «Пакеты/Услуги» → счётчик вида «5/8» (использовано/лимит).
2. Варианты: продать новый абонемент; докупить визиты (если тариф поддерживает); перейти на безлимит.
3. Турникет на исчерпанный лимит отвечает «Отказ» — причина видна в журнале отказов.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Удаление клиента и корзина (восстановление ≤30 дней)
Категория: clients-subs
Вариации запроса: удалить клиента, корзина, восстановить удалённого, восстановление 30 дней
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Удаление: карточка клиента → «Удалить» (права admin). Клиент уходит в «Корзину» — данные НЕ стираются.
2. Восстановление: «Клиенты → 🗑 Корзина» → найти → «♻ Восстановить». Ожидание: клиент вернулся со всеми абонементами и балансом.
3. Срок жизни корзины — 30 дней; потом запись анонимизируется (152-ФЗ).
4. Удалённые ошибочно давно? Обратитесь в поддержку — возможна выгрузка из бэкапа.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Анонимизация клиента по 152-ФЗ (запрос на удаление данных)
Категория: clients-subs
Вариации запроса: 152-фз, удалить персональные данные, забыть клиента, анонимизация
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Получите письменный запрос клиента (это требование закона).
2. Карточка клиента → «Анонимизировать» (admin): ФИО/телефон/email заменяются на плейсхолдеры, история платежей сохраняется без персональных данных.
3. Ожидание: подтверждение анонимизации, запись в аудите. Клиент «исчезает» из поиска по ФИО/телефону.
4. Сообщите клиенту о выполнении; браслеты/карты отвяжите.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Дубликаты клиентов (один человек — две карточки)
Категория: clients-subs
Вариации запроса: дубликат, два клиента один человек, объединить, слить карточки
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Найдите обе карточки (по телефону/ФИО).
2. Определите «основную» (с абонементами/балансом).
3. Объединение — через поддержку или администратора с правом: переносятся пакеты, баланс, привязки; вторая карточка анонимизируется.
4. До объединения не продавайте услуги на «неправильную» карточку.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Согласия клиента (152-ФЗ, биометрия)
Категория: clients-subs
Вариации запроса: согласия, подписать согласие, биометрия согласие, обработка персональных данных
📷 Скриншоты: scr-clients-01.png

**Пошагово.**
1. Карточка клиента → «Согласия» — список: ПДн (152-ФЗ), биометрия, рекламные рассылки.
2. «➕ Подписать» → распечатайте шаблон, клиент подписывает → отметьте дату/номер.
3. Биометрия без согласия = Face ID не работает и шаблоны не хранятся (ошибка 403 `biometric_consent_required`).
4. Отзыв согласия — в том же разделе; шаблоны биометрии удаляются автоматически.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
