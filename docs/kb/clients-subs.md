# clients-subs — клиенты, абонементы, тарифы, корзина

> Категория: clients-subs · Проверено для: 1.6.2 · Для кого: ресепшен, кассир, менеджер, администратор.

## Как добавить клиента
Ключевые слова: добавить клиента, создать клиента, новый клиент, анкета
**Ответ.** «Клиенты → ＋ Добавить»: Фамилия*, Имя*, Телефон* (с +7), Email* (привязывает личный кабинет), Пол, Дата рождения (ДД.ММ.ГГГГ или ГГГГ-ММ-ДД) → OK (ИНСТРУКЦИЯ §10.3).
📷 [SCR-clients-01: форма «Новый клиент»]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Ошибки при создании клиента
Ключевые слова: такой email уже есть, дубль телефона, неверный формат даты, обязательные поля
**Ответ.** «Заполните обязательные поля» — проверьте поля со звёздочкой. «Такой email/телефон уже есть» — клиент уже в системе, ищите по телефону. «Неверный формат даты» — используйте ДД.ММ.ГГГГ. Дубль — сообщите администратору, не создавайте вторую карточку (ИНСТРУКЦИЯ §10.4).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как изменить / деактивировать клиента
Ключевые слова: изменить клиента, деактивировать, удалить клиента, двойной клик
**Ответ.** Двойной клик по строке или «✎ Изменить» → правка → OK. «⊘ Деактивировать» — клиент исчезает из списков, история сохраняется. Кнопка «Удалить» делает то же (мягкое удаление). Вернуть: «Показать удалённых» → «Восстановить» (≤30 дней, ИНСТРУКЦИЯ §10.5–10.6, §6.3).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Корзина: удалённые клиенты и восстановление
Ключевые слова: корзина, восстановить клиента, вернуть удалённого
**Ответ.** «Клиенты → Показать удалённых» — список с кнопкой «Восстановить». Восстановление вернёт клиента с исходным ID и статусом (проверено E2E 05.11: create → delete → restore → ACTIVE). Срок хранения снимков — 30 дней (ИНСТРУКЦИЯ §6.3, ROADMAP «Корзина»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как продать абонемент
Ключевые слова: продать абонемент, оформить абонемент, новая продажа
**Ответ.** «Абонементы → ＋ Продать абонемент» → клиент → тариф (видна цена) → дата начала (по умолчанию сегодня) → OK. Окончание посчитается по длительности тарифа. Дальше примите оплату в «Платежи» (ИНСТРУКЦИЯ §12.3, §27).
📷 [SCR-clients-02: форма «Продажа абонемента»]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Заморозка и разморозка абонемента
Ключевые слова: заморозить, разморозить, отпуск, болезнь, freeze
**Ответ.** Выделите ACTIVE → «❄ Заморозить» → дата «до» (пусто = без срока) → причина → OK. Разморозка: «▶ Разморозить» (без формы). Важно: при разморозке срок сдвинется на замороженные дни — дни не сгорают (ИНСТРУКЦИЯ §12.4–12.5).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Абонемент истёк — что делать
Ключевые слова: истёк абонемент, продлить, ex expired
**Ответ.** Продайте новый абонемент (при необходимости — новый тариф) или используйте продление, если оно настроено. Истёкший абонемент вход не даёт — турникет откажет. Статусы: ACTIVE зелёный, EXPIRED красный, FROZEN синий, CANCELLED серый (ИНСТРУКЦИЯ §12.1).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Лимитированный и безлимитный тариф — разница
Ключевые слова: лимит визитов, безлимит, тип тарифа
**Ответ.** При создании тарифа: «Лимит визитов» — N посещений за период (столбец «Осталось визитов»); пусто = безлимит. «Безлимитный» — любое число визитов за период. Исчерпан лимит → турникет откажет («Лимит визитов исчерпан») (ИНСТРУКЦИЯ §8, §15.10).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Как создать тариф
Ключевые слова: создать тариф, новый тариф, цена, дней действия
**Ответ.** «Бухгалтерия → Тарифы → Создать тариф»: Код (A-Z, 0-9, _ → станет ЗАГЛАВНЫМ)*, Название*, Цена*, Дней действия* (например 30), Лимит визитов (пусто = безлимит), Тип → OK. По тарифу с продажами удалять не советуем — редактируйте ✎ (ИНСТРУКЦИЯ §8).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## История клиента (все события одним списком)
Ключевые слова: история клиента, timeline, что делал клиент
**Ответ.** Карточка клиента → вкладка «История»: визиты, платежи, абонементы, документы, аудит доступа. API `GET /clients/{id}/timeline` (ИНСТРУКЦИЯ §10, USER_GUIDE).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Удалить данные клиента по требованию (152-ФЗ, «право на забвение»)
Ключевые слова: анонимизировать, право на забвение, 152-фз, удалить персональные данные
**Ответ.** «Бухгалтерия → Экспорт → 🗑 Право на забвение»: ID клиента + причина → «Анонимизировать». ФИО/телефон/email/дата рождения станут `***` — НЕОБРАТИМО, операция пишется в аудит. Перед выполнением — бэкап (ИНСТРУКЦИЯ §14, §15.11).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».
