## Требования к серверу клуба
Категория: server
Вариации запроса: требования сервер, железо, минимальные требования, сколько ресурсов

**Ответ.** Рекомендуется: 2 CPU, 4 ГБ RAM, 40 ГБ SSD ( Debian 12 / Ubuntu 22.04+). Docker + Docker Compose v2. Порт 80 (HTTP) и 443 (HTTPS, если домен). Статика ~5 ГБ + БД (растёт с клиентами). Полный чек-лист: INSTALL_SERVER.md §2. Для сети клуба: сервер и ПК/турникеты в одной локальной сети, белый IP не обязателен (достаточно для webhook'ов MAX/ЮKassa — через домен или туннель).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Установка с нуля (кратко)
Категория: server
Вариации запроса: установка с нуля, чистая установка, развернуть сервер, install prod

**Пошагово (краткий план, команды — INSTALL_SERVER.md §3–5).**
1. Подготовить Debian/Ubuntu + Docker.
2. Получить код: `git clone https://github.com/Kant84/fitintel-pro.git` (или USB/офлайн-пакет).
3. Заполнить `deploy/.env` (БД, домен, ITC-пароль и т.д.) по шаблону.
4. `bash scripts/install_prod.sh` — сборка и запуск контейнеров.
5. `bash scripts/secure_install.sh` — защита каталога (маркер SECURE_OK=1).
6. Проверка: `curl http://127.0.0.1/api/v1/health/` → `"status":"ok"`.
7. Создать первого администратора, активировать лицензию.
Ожидание: согласно чек-листу INSTALL_SERVER.md §17 (12 пунктов).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Проверка работоспособности после установки
Категория: server
Вариации запроса: проверка после установки, health, как проверить сервер, контрольный список

**Пошагово.**
1. `docker compose ps` — все контейнеры Up (api, db, redis, celery-worker, celery-beat, nginx).
2. `curl http://127.0.0.1/api/v1/health/` → JSON `{"status":"ok","app":"FitIntel Pro","module":"crm","database":"ok"}`.
3. С ПК клуба: открыть `http://<IP-сервера>/api/v1/health/` в браузере → тот же JSON.
4. Desktop: «Настройки → Подключения → Проверить связь» → зелёный.
   Ожидание: все 4 пункта зелёные.
⚠️ 502 сразу после старта — прогрев 20–30 секунд, подождите (не перезапускайте по кругу).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Обновление сервера
Категория: server
Вариации запроса: обновление, update, новая версия сервера, git pull обновить

**Пошагово.**
1. `cd /opt/fitintel-pro && git fetch origin && git reset --hard origin/main`.
2. `docker compose --env-file deploy/.env -f deploy/docker-compose.prod.yml up -d --build` (или install_prod.sh).
3. Ожидание: контейнеры пересобраны; API прогревается 20–30 сек (502 — норма на этом окне).
4. Проверка: health + версия в «О программе» desktop.
5. Перед обновлением — бэкап БД (см. «Бэкапы»).
⚠️ Если менялись env-параметры — сверьте `deploy/.env` с шаблоном в репо.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Бэкапы: автоматика и ручное копирование
Категория: server
Вариации запроса: бэкап, backup, копия базы, как восстановиться, скачать бэкап

**Ответ.** Встроено: автобэкап PostgreSQL **каждый день в 03:00** (backup_postgres.py + ротация через install_cron.sh). Ручной бэкап: `python3 scripts/backup_postgres.py` — снимок в каталог бэкапов. Копия на внешний носитель/облако — скриптом offsite (настраивается путём в install_cron.sh); рекомендуется вне клуба (пожар/кража сервера). Проверяйте бэкапы раз в месяц: развернуть на тестовом ПК.

**Пошагово восстановления:** остановить контейнеры → накатить дамп в чистую БД (`psql -U fitintel fitintel < backup.sql`) → `up -d` → проверка health. Детально: INSTALL_SERVER.md §11.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Ротация пароля ITC (три точки хранения)
Категория: server
Вариации запроса: ротация itc, смена пароля itc, itc basic password где менять

**Ответ.** Пароль Basic-auth на `/skud/*` должен совпадать в трёх местах:
1. `deploy/.env` сервера: `ITC_BASIC_USER`/`ITC_BASIC_PASSWORD` → после правки `docker compose up -d --force-recreate api`.
2. Реестр ПК с ITCService: `BasicAuthUser`/`BasicAuthPass`.
3. `/etc/fitintel/bridge.env` на сервере: `itc_user`/`itc_password` → `systemctl restart ent_bridge`.
Проверка: старый пароль → 401, новый → 422 на `POST /api/v1/skud/checkaccess`. Регламент — при утечке или раз в квартал; пароль в менеджер паролей, не в чаты.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Место на диске заканчивается
Категория: server
Вариации запроса: место на диске, диск заполнен, no space left, чистка docker

**Пошагово.**
1. `df -h` — какой раздел под `/var/lib/docker`.
2. `docker system df` — сколько в образах/контейнерах/томах.
3. Безопасная чистка: `docker system prune` (удалит неиспользуемые образы; запущенные не тронет).
4. Логи: `journalctl --vacuum-size=200M`; логи compose контейнеров ротируются по настройкам.
5. Бэкапы — самый частый пожиратель: оставляйте ротацию (install_cron.sh), старые копии — на внешний носитель.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Права доступа к каталогу (secure_install.sh)
Категория: server
Вариации запроса: права, secure install, chmod, кто имеет доступ к файлам клуба

**Ответ.** `bash scripts/secure_install.sh` (root): владелец каталога — служебный пользователь (на nfs — `andrei`, группа `admin.platform`), `.env`/секреты — 600, скрипты — по политике 750/640/600, проверка группы docker. Маркер: `SECURE_OK=1`. Запускать после каждого `git reset --hard` (он сбрасывает mode-bits). Скрипт также показывает членов группы docker — лишних удаляйте.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Логи сервера: где и как читать
Категория: server
Вариации запроса: логи сервера, app.log, error.log, где ошибки api

**Ответ.** Каталог `/opt/fitintel-pro/logs/`: `app.log` (инфо), `error.log` (ошибки), `access.log` (запросы nginx). Docker: `docker compose logs --tail=100 api` (api), `docker compose logs db` (PostgreSQL). Журнал systemd: `journalctl -u itcservice`, `journalctl -u ent_bridge`. Лог за моментом сбоя: фиксируйте точное время с ПК пользователя.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Кто чинит»: зоны ответственности
Категория: server
Вариации запроса: кто отвечает, зоны ответственности, что чинит клуб а что разработчик

**Ответ.**
- **Клуб/IT клуба**: сервер, сеть, электричество, касса/ФН/ОФД, контроллеры/считыватели/камеры, Windows-ПК с desktop, интернет.
- **Разработчик (поддержка)**: баги ПО, ошибки API, модули FitIntel, консультации по настройке.
- **Платформа**: работоспособность ботов MAX, платформенная лицензия.
Точка раздела: если `curl http://127.0.0.1/api/v1/health/` с сервера отвечает ok — инфраструктура жива, ищем в ПО/настройках; не отвечает — инфраструктура клуба.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Рестарт контейнеров (когда и как)
Категория: server
Вариации запроса: перезапуск, restart, контейнеры перезапустить, сервер перезагрузить

**Пошагово.**
1. Штатный: `docker compose --env-file deploy/.env -f deploy/docker-compose.prod.yml restart` — без потери данных, пауза ~10 сек.
2. После правки `.env`: `up -d --force-recreate api celery-worker celery-beat` (перечитать env).
3. НЕ используйте `docker compose down` в часы работы без необходимости — прогрев после старта 20–30 сек.
4. После рестарта: health + 502-прогрев (подождать, не долбить).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Перенос сервера на другую машину
Категория: server
Вариации запроса: перенос сервера, миграция, другой сервер, переезд

**Пошагово (кратко, детали — INSTALL_SERVER.md).**
1. На новой машине: Docker + клон репозитория + тот же `deploy/.env`.
2. Перенести БД: последний бэкап (`pg_dump`/файл из каталога бэкапов) → восстановить.
3. Перенести uploads/static (фото/документы) и `license` файлы.
4. Запустить, проверить health, переключить desktop на новый IP.
5. Старый сервер — не выключать до полной сверки (параллельная работа опасна: два источника записи).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Мониторинг: метрики и алерты
Категория: server
Вариации запроса: мониторинг, метрики, алерты, prometheus

**Ответ.** API отдаёт `/metrics` (Prometheus): счётчики запросов и гистограммы длительности. Для IT: поднимите node_exporter + Prometheus/Grafana на том же сервере или ПК администратора; алерты: контейнер down, диск >80%, 5xx-серия. Для клуба без мониторинга — минимум: ежедневный взгляд на health + место на диске.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
