# faceid — Face ID: регистрация, распознавание, согласия (10 статей)

> Категория: faceid · Проверено для: 1.6.2 по app/api/v1/face_id.py и экрану «Face ID» (4 диалога настроек).
> Биометрия — чувствительные данные: без согласия 152-ФЗ шаблоны не создаются и не хранятся.

## Регистрация лица клиента
Категория: faceid
Вариации запроса: зарегистрировать лицо, добавить лицо, face id регистрация, снять лицо
📷 Скриншоты: scr-face-01.png

**Пошагово.**
1. Убедитесь: у клиента подписано согласие на биометрию (карточка → «Согласия»). Без него — ошибка 403 `biometric_consent_required`.
2. Вкладка «Face ID» → «➕ Добавить» (или из карточки клиента).
3. Наведите камеру на лицо клиента (анфас, ровный свет, без очков/капюшона).
4. Ожидание: рамка захватила лицо, несколько кадров → «Шаблон сохранён».
5. Проверка: тестовое распознавание на этом же экране.

**Типичные ошибки.** 403 consent — сначала согласие; плохой свет — перенесите к окну; камера занята другим приложением — закройте его.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Согласие на биометрию (152-ФЗ): подписание и отзыв
Категория: faceid
Вариации запроса: согласие на биометрию, 152-фз лицо, отозвать согласие, персональные данные лицо
📷 Скриншоты: scr-face-01.png

**Пошагово.**
1. Карточка клиента → «Согласия» → «Биометрия» → «Подписать» → распечатайте шаблон, клиент подписывает → отметьте дату в системе.
2. Ожидание: согласие активно (зелёный статус) — теперь возможна регистрация лица.
3. Отзыв: «Отозвать» в том же разделе. Ожидание: **шаблоны лица удаляются автоматически**, турникет по лицу перестаёт узнавать клиента.
4. Все действия — в аудите доступа.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Лицо не распознаётся» на турникете
Категория: faceid
Вариации запроса: не узнаёт лицо, плохо распознаёт, face id не срабатывает, снова просит карту
📷 Скриншоты: scr-face-01.png

**Пошагово.**
1. Контроль света: камера против света/в темноте — смените ракурс; просите клиента смотреть в камеру.
2. Внешность изменилась (очки, борода, шапка) — перерегистрируйте лицо.
3. Порог схожести: «Face ID → Настройки» — стандарт 0.6; в сложных условиях поднимите до 0.65–0.7 (баланс с ложными срабатываниями).
4. Шаблон старый (регистрация была давно) — перерегистрация обновляет вектор.
   Ожидание после правок: клиента пускает по лицу.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Настройки Face ID (4 диалога)
Категория: faceid
Вариации запроса: настройки face id, порог распознавания, камера face id, параметры биометрии
📷 Скриншоты: scr-face-06.png

**Ответ.** Экран «Face ID» содержит диалоги: 1) **Камеры** — список/приоритет источников; 2) **Порог схожести** (0.6 по умолчанию); 3) **События/журнал** распознаваний; 4) **Шаблоны** — список зарегистрированных лиц с привязкой к клиентам (удаление/пересъёмка).
**Пошагово.** Откройте нужный диалог → измените → «Сохранить» → тестовый проход.
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «ОТКАЗ: auth» на проходе по лицу
Категория: faceid
Вариации запроса: отказ auth, биометрия отказ, face id отклоняет всех
📷 Скриншоты: scr-face-01.png

**Пошагово.**
1. Один клиент: нет согласия (проверьте «Согласия» в карточке) или истёк абонемент — причина во вложенном тексте отказа.
2. ВСЕ клиенты: связь модуля распознавания с API (`docker compose logs api | grep -i face`) или упал сервис распознавания.
3. Лицо нашлось, но «Отказ» — смотрите журнал распознаваний: там счётчик схожести; ниже порога — подстройте порог или перерегистрируйте.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## «Камера не найдена»
Категория: faceid
Вариации запроса: камера не найдена, нет камеры, не видит камеру, устройство видео
📷 Скриншоты: scr-face-01.png

**Пошагово (IT).**
1. Камера подключена к ПК/серверу, определяется в ОС (Диспетчер устройств / v4l2-ctl --list-devices).
2. Не занята другим приложением (браузер, Zoom) — закройте.
3. В «Face ID → Настройки → Камеры» выберите правильное устройство из списка.
4. USB-камеры через хабы могут отваливаться — втыкайте напрямую (как и ACR1252).
   Ожидание: превью пошло, регистрация доступна.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Ложные срабатывания (пускает чужих)
Категория: faceid
Вариации запроса: пускает чужих, ложное распознавание, узнал не того, ошибочный проход
📷 Скриншоты: scr-face-01.png

**Пошагово.**
1. Поднимите порог схожести: «Face ID → Настройки» → 0.7 и выше; тестируйте на разных людях.
2. Проверьте свет и угол камеры: боковой ракурс резко повышает ложные совпадения.
3. Перерегистрируйте «проблемных» клиентов качественными кадрами.
4. Оставьте двухфакторный проход: лицо + браслет — тогда ложное лицо не откроет турникет.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Распознавание сотрудников по лицу
Категория: faceid
Вариации запроса: лицо сотрудника, персонал по лицу, face id для staff
📷 Скриншоты: scr-face-01.png

**Ответ.** Регистрация — как для клиентов, но привязка к учётной записи сотрудника; в журнале проход помечен «Сотрудник». Согласие сотрудника на биометрию оформляется в кадровом порядке (карточка сотрудника → «Согласия»). Увольнение — шаблон удаляется при деактивации учётки.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Журнал распознаваний: где и что смотреть
Категория: faceid
Вариации запроса: журнал распознаваний, лог face id, кто проходил по лицу, счётчик схожести
📷 Скриншоты: scr-face-01.png

**Пошагово.**
1. «Face ID → События» (или «История → Фильтр: биометрия»).
2. Строка: время, камера, найденный клиент/«неизвестно», счётчик схожести, результат (проход/отказ).
3. Для разбора жалобы найдите конкретное событие по времени — там детали отказа.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
