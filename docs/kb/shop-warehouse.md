# desktop: магазин и склад (12 статей)

> Категория: desktop · Поставки, продажи, штрих-коды, списания, инвентаризация, отчёты, бар.

## Магазин: структура вкладки (1.6.2)
Категория: desktop
Вариации запроса: вкладка магазин структура, что в магазине, разделы магазина

**Структура «Магазин» (sidebar, 1.6.2).** Каталог (товары: название/категория/цена/штрих-код), Остатки (склад/инвентаризация), Продажи (касса магазина + история), Отчёты (выручка/маржа по товарам). Всё синхронизировано с «Коммерцией» — это один контур учёта.
**Доступ.** Экран «Магазин» — в «Экранах ролей» (продавец/кассир/администратор).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Поставка товаров: приход на склад
Категория: desktop
Вариации запроса: поставка товара, приход на склад, оприходование

**Пошагово.**
1. «Магазин/Коммерция → Остатки → ＋ Приход» (или «Поставка»).
2. Позиции: товар (или новый «＋»), количество, закупочная цена.
3. «Сохранить» → остатки выросли; себестоимость обновилась (средняя).
4. Документ прихода — в «Бухгалтерия → Документы» (проводки Дт товарный счёт).
Поставщик и счёт — по комментарию/документу (детали — в 1С при интеграции).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Продажа товара на кассе: пошагово
Категория: desktop
Вариации запроса: продать товар на кассе, касса магазина, продажа со склада

**Пошагово.**
1. «Магазин → Продажи → ＋ Новая продажа» → добавьте товары (поиск по названию/штрих-коду), количество.
2. «К оплате» → способ оплаты (нал/безнал/кошелёк).
3. Платёж уходит в «Платежи» (категория «Товар») → «✓ Подтвердить» → чек + списание остатка.
4. Ожидание: статус «Завершён», остаток товара уменьшился.
⚠️ Продажа без подтверждённого платежа = товар ушёл, денег нет (сверка вечером).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Штрих-коды товаров: назначение и сканирование
Категория: desktop
Вариации запроса: штрих код товара, сканер на кассе, barcode магазин

**Назначение.** Ускорение продаж: сканер подставляет товар в чек. Назначение: в карточке товара поле «Штрих-код» (EAN-13 или внутренний код). Печать этикеток — внешним принтером (в ПО генерации нет — печатайте из 1С/сторонних утилит).
**Проблемы.** Сканер не вводит код → проверьте, что курсор в поле поиска; код не находится → проверьте привязку к товару.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Списание и брак: документы
Категория: desktop
Вариации запроса: списание товара, брак списать, утилизация

**Пошагово.**
1. «Остатки → ＋ Списание» → товар, количество, причина (брак/истёк срок/порча).
2. «Сохранить» → документ списания (Бухгалтерия → Документы), остатки уменьшены.
3. Причина обязательна — без неё списание не пройдёт/будет непонятно бухгалтеру.
4. Физическая утилизация — по регламенту (акт с подписями при крупных суммах).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Инвентаризация: пошаговый протокол
Категория: desktop
Вариации запроса: инвентаризация протокол, пересчёт товаров шаги, как провести

**Протокол.**
1. Назначить дату/комиссию (двое сотрудников).
2. «Остатки → Инвентаризация» → начать: система фиксирует эталонные остатки.
3. Физический пересчёт (без продаж в это время или с учётом продаж — по регламенту).
4. Ввод фактических чисел → расхождения: излишек (оприходование) / недостача (списание).
5. Документы — в «Бухгалтерия → Документы»; акт — PDF + подписи.
6. Разбор недостач — с материально ответственным.
Периодичность: ежемесячно или поквартально.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Отчёты магазина: выручка и маржа
Категория: desktop
Вариации запроса: отчёт магазин, маржа товаров, выручка магазина отчёт

**Где.** «Магазин → Отчёты» (или «Бухгалтерия → Отчёты» по категории «Товар»): выручка по товарам/категориям, количество продаж, маржа (цена − себестоимость).
**Применение.**
- ABC-анализ: топ-товары — на витрину/в вендинг.
- Неликвид: не продаётся N дней — распродажа/возврат поставщику.
- Маржинальность: категории с низкой маржой — пересмотр закупок.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Вендинг из магазина: связь остатков
Категория: vending
Вариации запроса: вендинг и склад связь, товары автомата со склада, списание вендинга

**Связь.** Автоматы продают товары из общего каталога: продажа через автомат (код/браслет) списывает остаток товара автомата (как «продажа»).
**Учёт загрузки автомата.** При загрузке товара в автомат — перемещение по регламенту (документ перемещения или списание со склада + приход «автомат» — зависит от настройки клуба; уточните с бухгалтером). Остаток автомата — по журналу вендинга (что продано).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Несколько точек продаж/складов
Категория: desktop
Вариации запроса: несколько складов, второй магазин, точка продаж дополнительная

**Модель.** В текущей версии — один складовый контур на клуб: остатки общие. Точки продаж (ресепшен + бар) — используют общий каталог; перемещения между точками не выделяются.
**Практика.** Разделение по категориям («Бар»/«Мерч») + регулярная сверка. Полноценная мультискладская схема — через интеграцию 1С (склады там) или в дорожной карте — уточняйте у разработчика.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Возврат товара клиентом
Категория: desktop
Вариации запроса: вернуть товар, возврат покупки магазина, товарный возврат

**Пошагово.**
1. Найдите продажу («Продажи»/«Платежи» по клиенту).
2. «↩ Возврат» → сумма (полная), причина → платёж-возврат.
3. Товар вернулся на остаток (проверьте в «Остатки»); чек возврата — на ККТ.
4. Деньги — тем же способом, что оплата.
⚠️ Возвращённый товар с признаками использования — списание, а не возврат в остаток (по регламенту).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Комбо-продажи и наборы
Категория: desktop
Вариации запроса: комбо набор, продажа набора, комплект товаров

**Ответ.** Отдельного «конструктора наборов» в текущей версии нет: набор оформляется как отдельный товар (категория «Наборы», цена набора) со списанием компонентов вручную (списание по компонентам или учёт набора как самостоятельной позиции — решите с бухгалтером; влияет на себестоимость).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Еда и напитки (бар): учёт и сроки
Категория: desktop
Вариации запроса: бар учёт, сроки годности, еда в магазине

**Регламент.**
1. Категории «Бар»/«Кафе» — отдельные; сроки годности — в названии/описании + контроль вручную (автосписание по срокам в текущей версии не настраивается).
2. Списание просрочки — ежедневно (чек-лист закрытия) с причиной «истёк срок».
3. Маржинальность бара — отдельный отчёт (категория).
4. Санитарные требования — по законодательству (журнал температур и пр. — вне ПО).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
