## Подключение турникета (схема целиком)
Категория: skud-hardware
Вариации запроса: подключение турникета, схема скуд, как подключить контроллер, установка турникета
📷 Скриншоты: scr-rfid-01.png

**Ответ (боевой пример nfs).** Цепочка: турникет/считыватели → контроллер ITC (LAN клуба) → ITCService на ПК/сервере → webhook на API клуба (`/skud/checkaccess` по Basic-auth) → решение «пускать/нет» → открытие. Альтернатива: программный мост ent_bridge (`/etc/fitintel/bridge.env`, режим задаётся `mode`). Питание контроллера и турникета — отдельные линии; считыватели — Wiegand на контроллер.

**Пошагово.** 1) Смонтировать турникет и контроллер; 2) проложить LAN к контроллеру; 3) настроить ITCService (статья ниже); 4) проверить curl на checkaccess (422 = ок); 5) тестовый проход картой.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Настройка ITCService (реестр Windows)
Категория: skud-hardware
Вариации запроса: itcservice настройка, реестр, basicauthpass, настроить itc service
📷 Скриншоты: scr-rfid-01.png

**Пошагово (ПК/сервер с ITCService, от администратора).**
1. Откройте редактор реестра: Win+R → `regedit`.
2. Перейдите в ветку `HKEY_LOCAL_MACHINE\SOFTWARE\ITCService` (имя может отличаться — ищите по ключам ниже).
3. Ключи: `ServerURL` = `http://<IP-сервера-клуба>`; `BasicAuthUser` = `itc`; `BasicAuthPass` = пароль из `deploy/.env` (`ITC_BASIC_PASSWORD`); параметры клуба (id клуба/проходные) — по документации ITC.
4. Перезапустите службу ITCService (`services.msc` → ITCService → Перезапустить).
5. Проверка: в логе службы нет 401; тестовый проход карты создаёт событие в FitIntel.

**Типичные ошибки.** После ротации пароля забыли обновить `BasicAuthPass` — все проходы отвечают 401 (см. server.md «Ротация ITC»).
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Проверка связи контроллера (curl checkaccess)
Категория: skud-hardware
Вариации запроса: проверить скуд, curl checkaccess, тест контроллера, 422 норма
📷 Скриншоты: scr-rfid-01.png

**Пошагово (с сервера).**
1. `curl -s -u itc:<пароль> -X POST http://127.0.0.1/api/v1/skud/checkaccess -H 'Content-Type: application/json' -d '{"uid":"<UID-карты>"}'`.
2. Ожидание: HTTP **422** — это НОРМА: авторизация прошла, доступ не выдан (карта неизвестна/абонемент нет). В теле JSON причина отказа.
3. HTTP **401** — логин/пароль не совпадают с `deploy/.env`.
4. HTTP **000/timeout/502** — API не поднялся/не прогрелся: `docker compose ps`, подождать 30 сек, логи api.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ent_bridge: программный мост (режимы)
Категория: skud-hardware
Вариации запроса: ent_bridge, мост, bridge mode, программный мост турникета
📷 Скриншоты: scr-rfid-01.png

**Ответ.** Сервис `ent_bridge.service` (конфиг `/etc/fitintel/bridge.env`, владелец andrei, права 600): `mode` — режим опроса контроллера (`none` = опрос выключен, путь идёт через ITCService; иные режимы — по задаче). Поля: `login`, `fit` (адрес API клуба, вида `http://192.168.101.182/api/v1`), `itc_user`, `itc_password`. Пароль должен совпадать с `ITC_BASIC_PASSWORD` сервера. После правки: `systemctl restart ent_bridge`; лог: `journalctl -u ent_bridge`.

**Пошагово проверки.** `systemctl is-active ent_bridge` → `active`; в логе нет 401.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Программирование Kerong S80F (мастер-карта, номер шкафчика)

Вариации запроса: kerong s80f, мастер карта, запрограммировать замок, номер шкафчика, добавить замок
📷 Скриншоты: scr-rfid-01.png

**Пошагово (по KERONG_KR-S80_SETUP.md).**
1. Мастер-карта штатно прилагается к набору — храните отдельно, доступ только у администратора.

4. Сброс замка: удержание кнопки/мастер-последовательность по инструкции замка (сотрёт все карты).

**Типичные ошибки.** Программировать карты «на все замки сразу» — нельзя, каждый S80F самостоятелен; путать номера наклеек и номера в ПО.

## Клонирование и сброс карт MIFARE
Категория: skud-hardware
Вариации запроса: клонирование карты, скопировать браслет, сброс mifare, uid карты
📷 Скриншоты: scr-rfid-01.png

**Ответ.** UID (серийный номер) карты MIFARE уникален и не перезаписывается; FitIntel работает именно с UID. «Клонирование» = выпуск новой карты с привязкой к тому же клиенту (старая — в блок, статья visits-access.md «Перевыпуск»). Дубликаторы UID-изменяемых карт (UID-writable) — уязвимость: блокируйте такие карты при обнаружении (журнал покажет один UID на разных физических картах одновременно в разных местах).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Турникет пускает всех подряд
Категория: skud-hardware
Вариации запроса: пускает всех, турникет не проверяет карты, свободный проход, fail open
📷 Скриншоты: scr-rfid-01.png

**Пошагово (срочно).**
1. Режим «открыто» на контроллере: проверьте реле турникета — замкнуто ли постоянно; аварийные входы контроллера (fire alarm) не активны ли.
2. ITCService упал/не отвечает — контроллер в offline-режиме по локальному списку. `systemctl status itcservice`, перезапуск.

4. Проверка: неизвестная карта должна получать отказ (curl-чек 422 с причиной).
5. Пока не разобрались — физически ограничьте проход (второй турникет/администратор у прохода).

## Карта работает на турникете, но не определяется на ресепшене
Категория: skud-hardware
Вариации запроса: карта не читается на ресепшен, браслет на турникете ок а у администратора нет
📷 Скриншоты: scr-rfid-01.png

**Ответ.** Турникет и ACR1252 читают разные носители: турникет — EM-Marine (125 кГц), ACR1252 — MIFARE (13.56 МГц). Если выдали EM-браслет, ресепшен его не увидит. Решение: единый стандарт носителей в клубе (рекомендуется MIFARE), либо два считывателя на ресепшене (ACR1252 + EM-USB).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

📷 Скриншоты: scr-rfid-01.png

**Пошагово (IT).**

3. Подсветка есть, карту не читает — попробовать другую карту; потом замена считывателя.
4. После замены — тест 3 картами + запись в журнале визитов.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Антенна/направленность считывателя: радиус действия
Категория: skud-hardware
Вариации запроса: радиус считывателя, дальность карты, антенна турникета, слабо читает
📷 Скриншоты: scr-rfid-01.png

**Ответ.** Дальность зависит от типа: EM — до ~10–15 см, MIFARE — до ~5–10 см (USB-считыватели меньше). Увеличить «настройкой» нельзя — только качеством носителя и расположением антенны. Симптом «читает через раз» — помехи (металл рядом, LED-подсветка), кабель без экрана; решение — перенос антенны/экранированный кабель.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Пожарный выход и аварийный режим турникета
Категория: skud-hardware
Вариации запроса: пожарный выход, аварийное открытие, fire alarm турникет, антипаника
📷 Скриншоты: scr-rfid-01.png

**Ответ.** Турникеты обязаны открываться при пожарной сигнализации (контакт «fire alarm» на контроллере). Регламент: ежемесячный тест сигналом; FitIntel не участвует в аварийном открытии (это аппаратная цепь). После срабатывания — проверить журнал: события аварийного открытия фиксируются контроллером; если FitIntel должен уведомлять о них — настройте событие в ITCService.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
