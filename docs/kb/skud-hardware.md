# skud-hardware — СКУД: ITC, турникеты, Kerong, RFID

> Категория: skud-hardware · Проверено для: 1.6.2 · Для кого: IT клуба, администратор, интегратор.

## Как подключить турникет к FitIntel (контроллеры ITC/ЭРА)
Ключевые слова: подключить турникет, itc, эра, checkaccess, контроллер
**Ответ.** В ПО контроллера включите «Подтверждение доступа»: URL проверки `http://<сервер-клуба>/api/v1/skud/checkaccess`, URL событий `.../skud/event`, аутентификация HTTP Basic (логин/пароль из `deploy/.env`), таймаут 3–5 сек. При проходе контроллер спрашивает сервер и открывает по `grant_access: 1` (SKUD_SETUP.md).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Настройка ITCService (Windows-служба контроллера)
Ключевые слова: itcservice, реестр, windows служба, checkaccessurl
**Ответ.** Реестр `HKLM\SOFTWARE\ITCService`: CheckAccessURL/EventURL/HealthCheckURL (`http://<сервер>:8001/api/v1/skud/...`), BasicAuthUser/BasicAuthPass (совпадают с `.env` клуба!), TimeoutMs 5000, RetryCount 3. Импорт — файл .reg, затем `Restart-Service ITCService`. Подробно и с форматами запросов/ответов — ITCService_SETUP.md.
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Проверка связи с сервером вручную (curl)
Ключевые слова: curl checkaccess, проверка скуд, grant_access
**Ответ.** `curl -u itc:<пароль> -X POST http://<сервер>/api/v1/skud/checkaccess -H 'Content-Type: application/json' -d '{"device_id":"<IP-контроллера>","client_card":"<UID>","request_id":"t1","direction":"entry"}'` → `{"grant_access":1,...}` — пускает, 0 — отказ с причиной. Старый пароль → 401, новый при пустом теле → 422 (SKUD_SETUP.md «Проверка»).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## ent_bridge (мост турникета)
Ключевые слова: ent_bridge, bridge, мост, itc_password, bridge.env
**Ответ.** Мост живёт НА СЕРВЕРЕ клуба (systemd `ent_bridge.service`), конфиг `/etc/fitintel/bridge.env`: `itc_user=itc`, `itc_password=<как в .env>`, `fit=http://<LAN-IP>/api/v1`, режим `mode` (none/fb/http/file). Ротация пароля — обновить `itc_password` и `systemctl restart ent_bridge`. Проверка совпадения с `.env` — diff (ITCService_SETUP.md §«Безопасность»; уточнение: боевая проверка 05–06.11).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Замки Kerong S80F/ITC-30: программирование
Ключевые слова: kerong, s80f, программирование замка, мастер карта, номер шкафчика
**Ответ.** Последовательность (подносите карты к ACR1252, следите за журналом): 1) «🛡 Карта доступа» → приложить к замку; 2) «👑 Мастер-карта» → к замку; 3) введите номер шкафчика → «🔢 Назначить номер» → к замку (2 раза: закроется, откроется); 4) «🗑 Очистить носитель» — карта готова к выдаче. Сектор: 0 (по умолчанию)–2 (INSTRUCTION_RFID §3).
📷 [SCR-skud-01: вкладка «Программирование замков»]
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Клонирование и сброс замка
Ключевые слова: клонировать карту, сброс замка, очистить замок, режим личный
**Ответ.** «📋 Клонировать» — копия данных с одной карты на другую. «🚫 Очистить замок» — удаляет все карты из замка. «🔐 Режим личный» — замок открывается только выбранной картой (max 4). «💥 Перезагрузить замок» — полный сброс (INSTRUCTION_RFID §3).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Онлайн-замки (TTLock / KERONG Cloud / Sciener)
Ключевые слова: ttlock, онлайн замок, sciener, цифровой ключ
**Ответ.** «Браслеты/Карты → ☁ Онлайн-замки»: Клиент ID (UUID) + Провайдер + Lock ID (+ пароль для TTLock) → «💾 Создать цифровой ключ». Работают через облако провайдера; доска раздевалок с арендой и стражем выхода — в desktop-панели «Онлайн-замки» (INSTRUCTION_RFID §4, ИНСТРУКЦИЯ §23.4).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## RFID-считыватели: какие поддерживаются
Ключевые слова: acr1252, acr122, omnikey, считыватель
**Ответ.** ACS ACR1252U, ACR122U, OMNIKEY 5022 (PC/SC). Требование: USB напрямую в порт ПК (без хабов/удлинителей). Носители: Mifare Classic 1K/4K, браслеты KERONG KR-S50/S80/S100 (INSTRUCTION_RFID §6).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».

## Турникет пускает всех / никого не пускает — для IT
Ключевые слова: турникет весь день открыт, сервер недоступен контроллер
**Ответ.** При недоступности сервера контроллер ведёт себя по своей локальной логике (как настроено в контроллере). Проверьте цепочку: контроллер → ITCService (логи службы) → сеть до сервера → `curl .../skud/health_check` → логи api. Health: `curl -u itc:<пароль> http://<сервер>/api/v1/skud/health_check` → `{"status":"ok"}` (SKUD_SETUP.md, ITCService_SETUP.md §6).
**Если не помогло:** «Помощь → Поддержка разработчика (MAX)».
