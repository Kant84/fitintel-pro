## secure_install.sh — политика безопасности
Категория: server
Вариации запроса: secure install что ставит, политика прав, 750 640 600

**Что делает.** Владелец каталога — служебный пользователь (на nfs `andrei`, группа `admin.platform`); `.env`/секреты — 600; скрипты — 750/640/600 по политике; выводит членов группы docker (проверка лишних). ## Бэкап PostgreSQL: автоматика и ручной
Категория: server
Вариации запроса: бэкап базы, pg_dump, backup_postgres, как снять копию

**Автоматика.** Ежедневно 03:00: `backup_postgres.py` (pg_dump в каталог бэкапов) + ротация через `install_cron.sh`.

## Восстановление из бэкапа
Категория: server
Вариации запроса: restore, восстановить базу, накатить бэкап

**Пошагово (из INSTALL_SERVER.md §11).**
1. Остановить контейнеры: `docker compose down` (или stop api/celery).
2. Накатить дамп в чистую БД: `gunzip -c backup.sql.gz | docker compose exec -T db psql -U fitintel fitintel` (либо psql с хоста).
3. `docker compose up -d` → прогрев 20–30 сек.
4. Проверка: health, вход desktop, сверка последних данных (платежи/визиты за день бэкапа).
⚠️ Восстановление перезаписывает текущие данные — снимите копию текущей БД перед накатом.

## Аварийный план: сервер не поднимается
Категория: server
Вариации запроса: сервер упал, аварийный план, не стартует контейнер

**Пошагово.**
1. `docker compose ps` — кто не Up.
2. `docker compose logs --tail=100 <сервис>` — причина (миграция, env, порт занят).
3. Порт 80 занят: `ss -tlnp | grep :80` — освободить/перенастроить.
4. БД не стартует: место на диске, права volume.
5. Порча данных: восстановление из бэкапа (статья «Восстановление»).
6. Критично и не решается — поддержка с логами; параллельно: работа на резервном ПК с дистрибутивом/бэкапом.
