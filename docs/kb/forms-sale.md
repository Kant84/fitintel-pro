# desktop: формы и окна ввода (20 статей)

> Категория: desktop · Каждое окно — по полям: что вводить, диапазоны, тексты ошибок.

## Продажа абонемента: окно по полям
Категория: desktop
Вариации запроса: продать абонемент окно, поля формы продажи, как заполнить продажу

**Окно «Продажа абонемента» — пошагово.**
1. «Абонементы → ＋ Продать абонемент».
2. «Клиент*» — список «Фамилия Имя (телефон)»; печатайте для фильтра (первые 200 записей).
3. «Тариф*» — список активных тарифов «Название — цена RUB».
4. «Дата начала*» — ГГГГ-ММ-ДД, по умолчанию сегодня.
5. «OK». Ожидание: абонемент создан, в таблице появилась строка; дата окончания = начало + дней действия тарифа.
6. Пустой список клиентов/тарифов → «Нужны клиенты и тарифы» — сначала создайте клиента и тариф.

**Типичные ошибки.** Клиент не в списке — создайте в «Клиентах → ＋»; деньги за абонемент оформляются платежом отдельно (экран «Платежи»).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Продажа услуги клиенту (единичной)
Категория: desktop
Вариации запроса: продать услугу, разовое занятие, продажа тренировки

**Пошагово.**
1. Откройте карточку клиента (двойной клик в «Клиентах»).
2. «Пакеты/Услуги → ＋ Продать» — выберите услугу из справочника, дату, при необходимости скидку.
3. «К оплате» → «Подтвердить».
4. Оформите платёж в «Платежи» (способ, категория «Услуга») → «✓ Подтвердить».
Ожидание: услуга активна у клиента, чек пробит, проводка создана.

**Типичные ошибки.** Без подтверждённого платежа услуга висит неоплаченной; закрытая смена — чек не пробьётся (сначала «🔓 Открыть смену»).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Окно «Провести платёж» — все поля
Категория: desktop
Вариации запроса: поля платежа, форма провести платёж что вводить, сумма способ категория

**Поля окна.**
- Сумма — число >0 (запятая или точка; ≤0 → «Сумма должна быть положительным числом»).
- Способ оплаты — Наличные/Карта/СБП (по QR)/Перевод/Онлайн-оплата/Абонемент (зачёт)/QR-код/Внутренний баланс/Другое.
- Направление — Приход (клиент платит) / Расход (выдача денег).
- Категория — (пусто)/Абонемент/Услуга/Товар/Прочее.
- Комментарий — свободный текст (попадёт в чек и описание проводки).
«OK» → платёж «Ожидает» → «✓ Подтвердить» (чек).

**Типичные ошибки.** Выбрали «Приход» вместо «Расход» — исправляется возвратом + новым платежом; пустой комментарий у расхода — бухгалтерия не поймёт основание.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Пополнение кошелька: окно и шаги
Категория: desktop
Вариации запроса: пополнить кошелёк окно, зачислить на баланс форма

**Пошагово.**
1. Карточка клиента → «СЧЁТ → Баланс → Пополнить».
2. Сумма >0, способ (нал/безнал).
3. «OK» → для нал/безнал платёж «Ожидает».
4. «Платежи → ✓ Подтвердить» (обязателен — без него баланс не вырастет, чек не пробьётся).
Ожидание: баланс вырос, запись в истории баланса.

**Типичные ошибки.** Пополнение без подтверждения платежа — клиент видит старый баланс; способ «Внутренний баланс» при пополнении не используется (это способ ОПЛАТЫ).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Окно «Возврат платежа» — поля и правила
Категория: desktop
Вариации запроса: окно возврата, поля возврата, частичный возврат как

**Поля.**
- Сумма возврата — пусто = полный возврат; можно частичную сумму ≤ суммы платежа.
- Причина возврата* — обязательна, без неё «Причина возврата обязательна».
«OK» → «Возврат оформлен»: баланс уменьшен (нал из наличных, безнал из безналичных), чек возврата на ККТ, сторно-проводка.

**Правила.** Возвращать можно только «Завершённый» платёж; дважды возвратить нельзя; при оплате кошельком возврат возвращает сумму на кошелёк.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## ПКО/РКО: поля ордеров
Категория: desktop
Вариации запроса: пкко ркко поля, сумма описание номер ордера

**Поля «💰 Касса».**
- ПКО: Сумма (по умолчанию 1000), Описание («Абонемент»), Номер (необязательно) → «📥 ПКО (приход)» → «✅ ПКО создан», проводка Дт 50.
- РКО: Сумма (500), Описание («Расход»), Номер → «📤 РКО (расход)» → «✅ РКО создан», проводка Кт 50.
Недостаток наличных → сервер откажет текстом. Ошибки валидации — красным под формой.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Окно «Новый тариф» — все поля и диапазоны
Категория: desktop
Вариации запроса: поля тарифа, код название цена дней лимит, форма тарифа

**Поля «Создать тариф».**
- Код* — A-Z, 0-9, _ (станет ЗАГЛАВНЫМ).
- Название* — пусто → «Название обязательно».
- Цена* — число ₽.
- Дней действия* — по умолчанию 30.
- Лимит визитов — пусто = без лимита; для «Лимитированный» пустое → 30.
- Тип — Лимитированный / Безлимитный.
«OK» → тариф в таблице «Тарифы». Правка — «✎» в строке, удаление — «✕» с подтверждением.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

Категория: desktop
Вариации запроса: поля впуска, способ зона впустить, форма входа

**Поля «🟢 Впустить».**

## Форма Email-уведомлений — все поля

**Поля.** Галочка «Включить Email-уведомления»; SMTP хост (плейсхолдер smtp.yandex.ru); SMTP порт (465=SSL, 587=TLS); SMTP логин; SMTP пароль (точками); От кого (email); Время ежедневного дайджеста (ЧЧ:ММ, 09:00). «💾 Сохранить Email» → «Сохранено ✓». mail.ru — пароль ПРИЛОЖЕНИЯ (535 иначе).

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».
