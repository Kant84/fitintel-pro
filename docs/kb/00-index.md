# База знаний поддержки FitIntel Pro (docs/kb/)

> Назначение: источник ответов для умного бота MAX (ТЗ «Бот техподдержки») и для живых
> администраторов. Формат статей — под инжест бота: заголовок H2 = вопрос дословно,
> «Категория» → `kb_articles.category`, «Вариации запроса» → `kb_articles.keywords[]`
> (каждая вариация — отдельная поисковая фраза, по ним бот находит статью),
> тело статьи → `answer_text`, скриншот → `screenshot_path`.
> Версия продукта: **1.6.2** (07.11.2026). Фактура проверена по коду репозитория: payments.py, cash_desk.py, vending.py, analytics.py/analytics_ai.py, main.py (состав роутеров), face_id.py. При бампе версии — пересматривать файлы.

## Правила наполнения (v3, 07.11)
1. Вопрос формулируем языком сотрудника клуба («чек не пробивается»), не языком разработчика.
2. **У каждой статьи — блок «Вариации запроса»: 4–6 формулировок** того же вопроса
   (синонимы, разговорные, с опечатками). Бот ищет по ним FTS — чем больше вариаций,
   тем чаще попадание. Вариации = поисковые ключи, дублировать их в тексте не нужно.
3. **Ответ — самодостаточный и пошаговый**: конкретные действия (какая вкладка, какая
   кнопка, что ввести), после каждого шага — «Ожидание» (что увидит пользователь).
   Запрещено отправлять «подробности в документации» как ОТВЕТ — ссылку на раздел
   ИНСТРУКЦИИ можно добавлять только строкой «Где почитать подробнее» ПОСЛЕ полного ответа.
4. В ответе — блок «Типичные ошибки на этом шаге» (если применимо): симптом → что не так.
5. Каждая статья заканчивается строкой **«Если не помогло»** — эскалация:
   desktop «Помощь → Поддержка разработчика (MAX)» (обращение уходит с логами и версиями)
   или support@fixintel.ru.
6. Скриншоты: места помечены `📷 [SCR-<тема>-NN: что снято]`; файлы — docs/images/desktop/,
   в БД попадают через kb_import по SCREENSHOT_MAP.
7. Объём: в KB ≥ **240 статей**. Лимита строк нет — главное полнота шагов.
