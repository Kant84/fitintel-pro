## Как настроить отправку писем (SMTP)
Категория: notifications
Вариации запроса: настроить почту, smtp, письма не уходят, email настройка, сервер исходящей почты

**Пошагово (admin).**
1. «Уведомления → Email»: сервер `smtp.mail.ru` (или smtp.yandex.ru), порт 465, SSL — включён.
2. Логин — полный email отправителя (например `club@club.ru`).
3. Пароль — **пароль приложения** mail.ru (Почта → Безопасность → Пароли приложений → создать для FitIntel), НЕ обычный пароль почты.
4. Копия (BCC) — опционально, для контроля копий писем клуба.
5. «Сохранить». Ожидание: зелёный баннер «SMTP настроен».
6. Отправьте тестовое письмо кнопкой «Тест». Ожидание: письмо пришло в течение минуты.

**Типичные ошибки.** Обычный пароль вместо пароля приложения → «535 Application password is REQUIRED»; порт 587 вместо 465 → таймаут.
📷 [SCR-notif-01: подвкладка Email с заполненными полями]
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Ошибка 535 «Application password is REQUIRED»
Категория: notifications
Вариации запроса: 535, mail.ru пароль, письма не отправляются 535, smtp ошибка 535

**Причина.** mail.ru/Яндекс принимают только пароль приложения.

**Пошагово.**
1. Войдите в почту отправителя в браузере.
2. Настройки → Безопасность → «Пароли приложений» (или «Пароли и авторизация → App passwords»).
3. Создайте пароль с названием «FitIntel» → скопируйте 16 символов.
4. Впишите его в «Уведомления → Email» → пароль → «Сохранить» → «Тест».
   Ожидание: тестовое письмо ушло.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Настройка SMS (SMSC.ru) и подпись отправителя
Категория: notifications
Вариации запроса: смс, smsc, отправка смс, подпись отправителя

**Пошагово (admin).**
1. Зарегистрируйтесь на smsc.ru, пополните баланс.
2. «Уведомления → SMS»: логин/пароль с smsc.ru → «Сохранить».

4. Тестовая SMS → «Тест». Ожидание: смс пришла.
5. Помните: ~46 ₽/смс — используйте SMS для срочного, остальное — MAX/Telegram/email (бесплатно).

## Подключение бота MAX для клиентов клуба
Категория: notifications
Вариации запроса: бот max, подключить бота, max bot токен, чат бот для клиентов

**Пошагово (admin).**
1. Создайте бота через @masterbot в MAX → получите токен.
2. Для юрлица включите чат-бота (кнопка «Чат-бот» в карточке бота) — без этого webhook не принимается.
3. «Уведомления → Клиенту → Каналы»: вставьте токен → «Установить webhook».
   Ожидание: статус «MAX: подключён».
4. Клиент должен запустить бота в MAX (кнопка «Начать») — бот не может написать первым.
5. Проверьте: клиент пишет боту /start → ответ пришёл.

**Типичные ошибки.** Не включён «Чат-бот» у юрлица; домен недоступен из интернета по HTTPS.

## «Клиенту»: события и что в них уходит (5 событий)
Категория: notifications
Вариации запроса: клиенту, события уведомлений клиенту, что приходит клиенту, автоматические сообщения клиентам

**Ответ.** Вкладка «Уведомления → Клиенту» — 5 событий, каждое включается галочкой и редактируется текстом:
1. **Оплата/пополнение** — чек и баланс после платежа (при включённом чеке на email).
2. **Запись/перенос** — подтверждение записи на услугу с датой/временем.
3. **Абонемент истекает** — за N дней до конца (N — в тексте/настройках).
4. **Абонемент истёк** — утром дня истечения.
5. **Аренда шкафчика истекает** — уведомление о заканчивающейся аренде.

**Пошагово.** Галочка события → «✏» правка текста (поддерживаются переменные {name}, {date}…) → «Сохранить». Ожидание: зелёная плашка «Сохранено» — иначе ошибка «api-клиент без put/post» (desktop <1.6.2, обновитесь).

## Как проверить, что уведомление реально ушло (Журнал)
Категория: notifications
Вариации запроса: журнал уведомлений, статус отправки, как проверить что письмо ушло

**Пошагово.**
1. «Уведомления → Журнал» — список всех исходящих: кому, канал, статус, текст ошибки.
2. Найдите нужное письмо (поиск по клиенту/дате).
3. Статусы: `sent` — ушло; `pending` — в очереди (до минуты норма); `failed` — раскройте строку, там точная ошибка SMTP/MAX.
   Ожидание: по `failed` видно, что чинить (пароль, токен, домен).

📷 [SCR-notif-05: журнал со статусами]
**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Письма попадают в спам
Категория: notifications
Вариации запроса: спам, письма в спаме, промоакции, доставляемость

**Пошагово.**
1. Попросите клиента перетащить письмо из «Спам»/«Промоакции» во «Входящие» и добавить адрес в контакты.
2. Не рассылайте массовые рекламные тексты с почты клуба — для рассылок используйте отдельный поддомен и сервис рассылок (Unisender и т.п.), иначе репутация основного домена просядет.
3. Настройте SPF/DKIM для домена клуба в DNS (записи из кабинета почты) — без них часть писем отсекается на входе.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## SMS стоят дорого — как удешевить коммуникацию
Категория: notifications
Вариации запроса: смс дорого, как сэкономить на смс, альтернатива смс, бесплатные уведомления

**Ответ.** SMS в FitIntel — только для срочного (смена расписания, инциденты). Всё остальное переведите на бесплатные каналы: MAX (клиентский бот) → Telegram → email. Порядок приоритета канала настраивается в «Клиенту → Каналы»: MAX/Telegram/email включены, SMS — только у сотрудников без привязки мессенджеров. Ожидание: расходы на smsc падают до минимума.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Уведомления приходят дважды клиенту
Категория: notifications
Вариации запроса: дубли уведомлений, два сообщения подряд, повторная отправка

**Пошагово.**
1. Проверьте, что клиенту привязаны ОБА канала (MAX и Telegram) — сообщение идёт по каждому привязанному каналу.
2. Дубль внутри ОДНОГО канала → смотрите «Журнал»: если там одна запись sent, а клиент получил два — проблема на стороне мессенджера/переотправки; если две записи — действие было выполнено дважды (двойной клик), обучите сотрудника.
3. Оставьте один приоритетный канал, второй отвяжите у клиента, если дубли мешают.

**Если не помогло:** Ескалация: «Помощь → Поддержка разработчика (MAX)».

## Отложенная отправка по расписанию
Категория: notifications
Вариации запроса: запланировать рассылку, отправить позже, по времени рассылка

**Пошагово.**
1. При создании рассылки («Клиенту → Рассылки») выберите «Запланировать» вместо «Отправить сейчас».

3. Отмена/правка — до момента отправки: откройте рассылку → «Отменить».
4. После отправки статус меняется на «Отправлено», результаты — в журнале.
