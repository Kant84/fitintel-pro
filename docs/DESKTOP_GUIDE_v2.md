# ЧАСТЬ 0. УСТАНОВКА И ПЕРВЫЙ ЗАПУСК

## 0.1 Установка программы
📷 scr-install-01 (файл Setup), scr-install-02 (приветствие)
1. Получите `FitIntelDesktop-Setup_v1.6.2.exe` (~154 МБ). Проверьте хеш:
   `Get-FileHash .\FitIntelDesktop-Setup_v1.6.2.exe -Algorithm SHA256` — совпасть с RELEASES.md.
2. Запуск → «Далее» → папка → ярлык → «Установить» → «Завершить». Прав администратора не требуется.
3. Удаление: «Параметры Windows → Приложения». Обновление: новый Setup поверх (настройки сохраняются).
4. Portable-вариант: один .exe в любой папке, настройки рядом (client_settings.json, connections.json).

## 0.2 Первый запуск — адрес сервера (один раз на ПК)
📷 scr-login-02
Окно «Подключение к серверу»: введите `http://<IP-сервера>` (окончание /api/v1 допишется само) → «OK».
Создастся профиль «Сервер клуба». «Отмена» — вход с адресом по умолчанию (будет «Сервер недоступен»).

## 0.3 Активация лицензии (только новый сервер, один раз)
📷 scr-login-03
Окно открывается, если `/license/status` = не активирована. Поле ключа (вставлять целиком, начинается с `FIPRO-`) → «Активировать и войти».
Ошибки: «Ключ должен начинаться с FIPRO-» (скопируйте заново, Ctrl+A→Ctrl+C); «В ключе нет пароля» (перевыпустите в Studio); «Сервер отклонил: 403» (ключ привязан к другому machine-id → новый ключ у платформы); «Нет связи с сервером» (проверьте адрес, раздел 0.2).

## 0.4 Выбор информационной базы
📷 scr-login-05
Если профилей >1 — окно со списком: «1. Подключить» (или двойной клик), «2. Добавить…», «3. Изменить…», «4. Удалить», «? Справка», «Выход». Один профиль — окно пропускается.

## 0.5 Вход в систему
📷 scr-login-04
Поля «Логин» (email) и «Пароль», галочка «Запомнить меня» (только свой ПК), «Войти»/Enter.
Ошибки: «Введите логин и пароль»; «Неверный логин или пароль. Осталось попыток: N» (раскладка/Caps Lock); «Аккаунт заблокирован… 5 минут» (5 неверных, HTTP 423); «Сервер недоступен» (смотри раздел «Сервер не подключён» в Части 5).

## 0.6 Принудительная смена пароля
📷 scr-login-06
Жёлтая плашка «Это ваш первый вход…». Поля: старый (временный), новый (≥8 символов), подтверждение → «Сохранить и войти».
Ошибки: «Пароль минимум 8 символов»; «Пароли не совпадают»; «Неверный текущий пароль». Без успешной смены вход не завершится («вечный круг» — не баг).

## 0.7 Главное окно
📷 scr-main-01 (Обзор), scr-main-08 (Музыка, полный sidebar)
- **Шапка:** «FitIntel Pro»; справа — аватар, «superadmin | admin» (роли), «Выход» (подтверждение).
- **Sidebar (18 вкладок, состав — от сервера по роли):** Главная, Музыка/DJ, Клиенты, Входы/Выходы, Абонементы, Услуги, Расписание, Бухгалтерия, MAX сообщения, Уведомления, AI центр, Пользователи, История, Магазин, Face ID, Настройки, Банки, Браслеты/Карты. Ниже — «Подключения» (видит superadmin).
- **Статус-бар:** «Сервер подключён | FitIntel Pro v1.6.2», кнопка «Инструкция» (F1-справка по экрану).

# ЧАСТЬ 1. ОБЩИЕ ЭЛЕМЕНТЫ

## 1.1 Печать и PDF
Внизу экранов с таблицами: «🖨 Печать» (предпросмотр → принтер), «📄 В PDF» (выбор папки). Пустая таблица — «На этом экране нет данных для печати».

## 1.2 RFID Монитор (плашка)
📷 scr-rfid-01, scr-rfid-02
Плавающее окно (перетаскивается, позиция запоминается). Поля: **UID** карты; **Сектор**; **Тип карты** («Пустая карта», «Карта клиента», «Карта администратора», «Сервисная карта», «Не обслуживается», «Индивидуальный режим», «Режим удаления», «Сброс замка», «Номер шкафчика N», «Неизвестный формат»); **Шкафчик** (🔒 №N / 🔓 не назначен); **Клиент** (зелёный — найден, красный «Неизвестный»); **Аренда шкафчика**; **Вердикт** (ПУСКАТЬ/«ОТКАЗ: auth» — auth = нет активного абонемента/карта не привязана); **block_1** (сырые данные). Карту убрали → плашка исчезает.

## 1.3 Карточки и формы
Двойной клик по строке таблицы — открыть карточку/детали. Обязательные поля помечены *; пустое обязательное — предупреждение. Все списки обновляются кнопками «Обновить». Ctrl+Z — отмена последнего действия (см. меню Правка).

## 1.4 Горячие клавиши
F1 справка · F5 обновить · F11 часы · Ctrl+Q выход · Ctrl+/Ctrl− шрифт · Ctrl+Z отмена · Enter подтвердить · Esc закрыть.

# ЧАСТЬ 2. ВКЛАДКИ SIDEBAR

## 2.1 Главная
📷 scr-main-01 (Обзор), scr-main-07 (Прогноз), scr-main-09 (Тепловая), scr-main-10 (AI Отток)
Четыре подвкладки.

### «Обзор»
- **6 KPI-карточек:** Посещений сегодня · Выручка сегодня, ₽ · Приток клиентов (мес) · Отток (мес) · Прогноз выручки +14 дн, ₽ · Клиентов в риске.
- **Строка сегментов:** «Сегменты риска: Низкий: N | Средний: N | Высокий: N (всего: N)».
- **3 графика:** Приток клиентов по дням; Посещения — факт и прогноз (+14 дн, тренд STABLE/DOWN); Выручка — факт и прогноз.
- **Кнопки:** «👤 Приток клиентов» (отчёт по новым), «🔄 Обновить», «🧮 Пересчитать историю (56 дн)» — сбор статистики за 56 дней (до минуты, после установки/импорта — обязательно).

### «Прогноз»
Поля «Метрика» (Посещаемость/Выручка/Новые клиенты/Риск оттока) и «Дней» (1–90, стандарт 7) → «📈 Построить прогноз». Голубая линия — факт, розовый пунктир — прогноз.
Ошибка: «Нет данных — построй прогноз» / «Прогноз: нужно ≥14 дней истории» → «Пересчитать историю».

### «Тепловая карта»
«⚡ Загрузить тепловую карту» — сетка день недели × час (0–23), цвет = число визитов. Пусто — данных нет.

### «AI Отток»
«⏵ Обучить / дообучить» · «🔄 Обновить список риска» · «📈 Сверить прогнозы с фактом». Строка статуса: «Модель: обучена | примеров: N | точность: X». Таблица риска: Клиент | Вероятность оттока | Дней без визитов | Визитов за 30 д. График «Рост точности модели».
Ошибка: «Мало данных для обучения» → «Пересчитать историю (56 дн)» + ≥14 дней.

## 2.2 Музыка/DJ
📷 scr-music-01, scr-music-02
- **Верхняя панель:** сервер API; выбор **Зоны** (local_agent — наш плеер / external — провайдер); «⏵ Плеер: ВКЛ/ВЫКЛ» (запуск/остановка DJ-агента: 3 процесса mpv — Deck A, Deck B, PAD); «🎤 Микрофон: ВКЛ» (дакинг); «Новая зона…», «Плеер…», «Провайдер…», «Лицензия…».
- **Строка статуса зоны:** «Зона: <имя> | состояние: playing/stopped | громкость: N».
- **DJ-пульт:** «Трек на A/B» (из плейлиста), «Файл на A/B…», «Папка на A/B…», «Эфир A/B» (сведение), «ЭФИР: Deck X | мастер N | кроссфейд N.Ns», «Мастер-громкость» + «Применить пульт», «Кроссфейд, сек» (0–30), красная «MUTE ALL».
- **Плейлисты** (справа): выбор плейлиста, список треков, «→ A/→ B» (без эфира), «▶ A/▶ B» (с эфиром), двойной клик — на активный дек.
- **Эквалайзер:** Бас/Середина/Верха (−12…+12 дБ) отдельно на дек → «Применить EQ» (на лету). Подпись «A: 12/12/5 | B: 12/12/12».
- **Сэмплер (пады 1–8):** «＋ Добавить сэмпл» (имя, путь sfx/…, громкость), «Обновить сэмплы», клик — one-shot. Повтор <2 сек игнорируется. Серые — не назначены.
- **Лицензия (строка внизу):** «Лицензия фоновой музыки: provider, действует до ГГГГ-ММ-ДД (договор …)». 🔴 истекла → фон заблокирован (play/Energize → 402).
Ошибки: «403/bad token» в логе агента → авто-перерегистрация по machine_id; `lib=—` → client_settings.json не рядом с exe; тишина → mpv/громкость/мастер 0 (TROUBLESHOOTING §Музыка).

## 2.3 Клиенты
📷 scr-clients-01 (список), scr-clients-02…scr-clients-17 (карточка клиента)
**Таблица:** № | ФИО | Телефон | Email | Категория | Статус | Создан | Баланс | Бонусы.
**Кнопки:** «＋ Добавить» · «⊘ Деактивировать» · «🗑 Удалить» · «📥 Корзина» · «🔄 Обновить» · «🖨 Печать» · экспорт (XLSX/PDF/CSV/JSON/1C XML — меню у кнопки сохранения).
**«Добавить»/«Изменить» (двойной клик):** Фамилия*, Имя*, Отчество, Телефон* (+7…), Email*, Пол, Дата рождения (ДД.ММ.ГГГГ). Ошибки: «Заполните обязательные поля»; «Такой email/телефон уже есть» (дубль — ищите, не создавайте); «Неверный формат даты».
**«Удалить»/«Деактивировать»:** мягкое удаление (deactivated/deleted_at, история сохраняется).
**«Корзина» (trash_dialog):** список удалённых ≤30 дней → «Восстановить» (исходный ID и статус). Ошибка «snapshot not found» после циклов удаления/восстановления — исправлено, при повторе — «Обновить» список.

### КАРТОЧКА КЛИЕНТА (двойной клик по строке)
📷 scr-clients-02…17
**Шапка-карточки:** Клиент · Клуб · Тариф · Карта · Договор (№ анкеты) · Лиц. счёт · Состояние (Активен).
**Кнопки действий:** «Продать услугу» · «Выдать карту» (→ Браслеты/Карты) · «Заморозить» (активный абонемент) · «К сообщениям MAX» · «Face ID» (→ раздел Face ID с выбранным клиентом).

**Левое меню разделов:**
- **Анкета:** Дата рождения, Пол, Категория (ADULT/CHILD/VIP/STAFF), Тег, Сегмент, Источник, Паспорт, Гражданство, Семейное положение, Дети, Домашний адрес, Почтовый адрес, Компания, Должность, Вид договора. «Сменить фото» (фото — в защищённом медиа-хранилище сервера).
- **Телефоны/Контакты:** таблица Тип/Вид/Значение/Основной; добавление: тип («Телефон»), вид («Мобильный»…), значение (+7…) → «Добавить»; «Удалить выбранный». Сюда же привязки MAX/Telegram.
- **Документы:** «Загрузить файл (договор, справка…)», «Открыть», «Удалить» — файлы в защищённом медиа-хранилище (AES-256-GCM, UUID-имена, доступ по правам).
- **Фото:** загрузка/просмотр/удаление фотографий клиента.
- **Пакеты/Услуги:** таблица Название/Тип/Остаток/Срок/Статус/«Заморожен до».
- **Замечания:** поле «Текст заметки/задачи…» + тип («Заметка»/…) → «Добавить»; журнал заметок.
- **Согласия (152-ФЗ):** галочки «Обработка фото» и «Биометрия — Face ID» (+ «Не выдано»). Предупреждение: «Отзыв биометрии удаляет ВСЕ шаблоны Face ID клиента. Без активного согласия регистрация Face ID на сервере отклоняется (403 biometric_consent_required)». «Сохранить согласия».
- **Аудит доступа:** Когда/Кто/Действие/Файл/Результат — append-only (кто смотрел фото/документы, менял согласия).
- **Чеки:** таблица Дата/Сумма/Способ/Статус/Комментарий.
- **Баланс:** крупная цифра; подсказка «Лицевой счёт (кошелёк клиента). Не путать с кассой: здесь — внутренние деньги приложения; в кассу деньги попадают через платежи». «Сумма» + «Пополнить» + «Комментарий (откуда/зачем)»; История операций: Дата/Изменение/Баланс после/Комментарий.
- **Бонусы:** баланс бонусных баллов; «Правила начисления задаются в Параметры клуба → Бонусы».
- **Скидки:** «Персональная скидка, %» + «Сохранить» («Применяется менеджером при продаже — фиксируйте в комментарии платежа»).
- **Сообщения:** «Открыть MAX сообщения» (переписка с клиентом).
- **История:** визиты клиента: Дата/Вход/Выход/Зона/Способ (RFID, FACE_ID, QR, MANUAL).
- **Блоки:** «Вход заблокирован (чёрный список)» + «Причина блокировки» → «Сохранить». Блок = турникет не пускает независимо от абонемента.
- **Автомобили:** Марка/Номер/Примечание → «Добавить»/«Удалить выбранный».
- **Гость:** «Гостевой пропуск / примечание о госте» (напр. «гостевой визит до 25.10, сопровождает Сидорова А.»).

## 2.4 Входы/Выходы
📷 scr-visits-01
**5 счётчиков:** Сегодня · Неделя · Месяц · Новых в месяц · Ушедших в месяц.
**Поиск** по ФИО/телефону/статусу. **Кнопки:** «🟢 Впустить» · «🔴 Выпустить» · «✓ Завершить» · «🔄 Обновить» · «QR сотрудников» (служебный пропуск).
**Таблица:** № | Клиент (ФИО) | Телефон | Способ входа (MANUAL/RFID/QR/QR_STAFF/FACE_ID) | Время входа | Статус (ACTIVE/COMPLETED).
**«Впустить»:** Клиент* → Способ (Ручной/Карта/QR/Face ID) → Зона (main) → OK. Проверки сервера: активный визит (409 «Клиент уже находится в клубе»), абонемент, лимит визитов, время тарифа, чёрный список.
**«Выпустить»:** ACTIVE → открывает выход + закрывает визит. «Завершить» — закрыть без турникета. Ошибки: «Выделите строку»; «Этот визит уже закрыт»; при закрытом шкафчике — «Откройте шкафчик №N перед выходом!».

## 2.15 Face ID
📷 scr-face-01…07
**Слева:** поиск (ФИО/телефон/ID) → «Найти»; карточка клиента (ФИО/Телефон/Абонемент/Фото); «Снять с камеры» · «Загрузить файл» · «✓ Проверить меня»; область результата («Результат регистрации / verify…» / JSON).
**Справа:** «Шаблоны Face ID» (ID/Клиент ID/Создан/Качество). Кнопки: «Обновить список» · «🗑 Удалить шаблон» · «Настройки движка…» · «Движок Face ID» · «Симуляция: verify».
**«Настройки движка…»** — 4 последовательных диалога:
1. **Порог уверенности** — «Евклидово расстояние dlib (меньше = строже; 0.6 — стандарт)».
2. **Мин. качество фото** — «Порог резкости (Лапласиан; стандарт 40)».
3. **Лимит шаблонов** — «Максимум шаблонов на одного клиента».
4. **Хранение фото лиц** — «Сохранять сами фотографии на сервере? (по умолчанию — нет, только математические шаблоны; 152-ФЗ)».
**«Движок Face ID»** → JSON: `{engine: dlib, library: face_recognition, model: ResNet-34 (dlib), embedding_size: 128}`. **«Симуляция: verify»** → тестовый кадр: отказ — норма (`matched:false, reason:"Лицо не обнаружено"`).
Ошибки регистрации: «Лицо не обнаружено»; «Низкое качество фото»; «Обнаружено несколько лиц»; «Лимит шаблонов»; 403 biometric_consent_required (нет согласия — отзыв удаляет ВСЕ шаблоны).

### Клиентская карта
Поиск (ФИО/телефон/ID) → «Найти» → при нескольких совпадениях диалог «Выберите клиента» («Найдено клиентов: N», список с телефоном и ID, «Выбрать»/«Отмена»).
Карточка: ФИО/Телефон/ID. **Кнопки:** «Очистить носитель» · «Привязать к клиенту» · «Сброс к заводским» · «Аренда шкафчика» (диалог: «Аренда шкафчика активна», «Действует до (ГГГГ-ММ-ДД, пусто = бессрочно)» → «Сохранить»/«Отмена») · «✓ Проверить считыватель».
**Журнал операций** (внизу): каждый шаг с пометками [DEBUG]/[OK]: «Поднесите носитель для очистки…», «Носитель очищен. Клиент сохранён», «UID считан: …», «Привязано: UID=…», «Блок 1 очищен (данные клиента удалены)», «клиент отвязан на сервере, карта очищена, кэш сброшен».
**«Носители клиента»** (справа): таблица Тип | ID/UID.
Статус считывателя: «Считыватель не подключён» (красный) / «Готово» (зелёный). Ошибки: «Сначала выберите клиента»; «ОТКАЗ: auth» (в плашке — нет основания входа); 408 (карта не поднесена за 10 сек).
Алгоритм привязки: Очистить носитель → Привязать к клиенту (UID → сервер, чужая карта перепривяжется) → запись в «Носители клиента».

# ЧАСТЬ 5. СВОДКА ОШИБОК (симптом → причина → действие)
| Сообщение | Где | Причина → действие |
|---|---|---|
| Сервер не подключён / недоступен | статус-бар | ping IP; «Настройки → Проверить связь»; `curl http://IP/api/v1/health/`; 502 сразу после up — прогрев 20–30 с |

| Касса недоступна / ошибка: N (502) | Платежи | адрес ККТ, ping, журнал ККТ/mock |
| Снятие кассы 403 | Платежи | роль Бухгалтер/Админ |
| Платёж «Ожидает» | Платежи | «✓ Подтвердить» |
