\# Подключение контроллера ЭНТ / ЭРА к FitIntel Pro (подтверждение доступа)



FitIntel решает «пускать/не пускать» в реальном времени: контроллер спрашивает

наш сервер при каждом предъявлении карты, сервер отвечает за доли секунды.



\## Настройка в ПО контроллера (ЭНТ «Подтверждение доступа»)

1\. Включите функцию «Подтверждение доступа» (Access Verification).

2\. URL проверки:  http://\&lt;адрес-сервера-клуба\&gt;/api/v1/skud/checkaccess

3\. URL событий:   http://\&lt;адрес-сервера-клуба\&gt;/api/v1/skud/event

4\. Аутентификация: HTTP Basic — логин/пароль из файла `deploy/.env`

&#x20;  (ITC\_BASIC\_USER / ITC\_BASIC\_PASSWORD), сообщает владелец клуба.

5\. Таймаут ожидания ответа: 3–5 секунд. При недоступности сервера

&#x20;  контроллер ведёт себя по своей локальной логике (как настроено).



\## Что происходит при проходе

1\. Клиент прикладывает карту/браслет → контроллер шлёт POST /skud/checkaccess

&#x20;  {device\_id: \&lt;IP контроллера\&gt;, client\_card: \&lt;UID\&gt;, direction: entry|exit}

2\. FitIntel проверяет: карта зарегистрирована → есть активный абонемент

&#x20;  (и не просрочен) → при выходе нет закрытого бесплатного шкафчика.

3\. Ответ {grant\_access: 1, text\_full: "Доступ разрешен."} → реле открывает.

&#x20;  grant\_access: 0 + причина ("Нет активного абонемента",

&#x20;  "Откройте шкафчик №N перед выходом!", "Карта не зарегистрирована") → отказ.

4\. Проход зафиксирован: контроллер шлёт /skud/event → запись в «Входы/Выходы».



\## Проверка после настройки

\- curl -u \&lt;логин:пароль\&gt; -X POST http://\&lt;сервер\&gt;/api/v1/skud/checkaccess \\

&#x20;   -H 'Content-Type: application/json' \\

&#x20;   -d '{"device\_id":"\&lt;IP контроллера\&gt;","client\_card":"\&lt;UID\&gt;","request\_id":"t1","direction":"entry"}'

&#x20; → {"grant\_access":1,...}

\- Тестовый проход картой → запись появилась в desktop «Входы/Выходы».
